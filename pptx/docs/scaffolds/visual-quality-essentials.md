# 幻灯片视觉质量脚手架:间距节奏 / 色彩角色 / 构成平衡

> **状态:** v0 · 候选(待作者评审)。
> **用法:** 做 pptx 的视觉 QA / 风格收敛 / 目检判读前,先加载本文件对证。它管"观感级判断"——硬阈值在 [acceptance-checklist.md](../../acceptance-checklist.md)(C1–C9),中文文字微排版在 [typography.md](../../typography.md)。

> **词表对照:** 本文件按 essentials 分级;与 deck QA 产物的【实测 / 引用 / 假设待测】对照:核 ≈ 实测·引用;估 ≈ 假设待测;待补证据 ≈ 弱来源待核。

## 一、底层事实 / 观察

1. **间距要用"有限刻度",不是随手数值。** 成熟设计系统用一个小集合的固定间距值布局(如 8px 基准的等比刻度),一致性来自"选择受限"。【核:Atlassian Spacing】
2. **间距本身有语义:近 = 相关,远 = 无关。** 同组/同类元素用同距;组间距离 > 组内距离;同类元素间距不一致会破坏"同类感"。【核:Atlassian(similarity / proximity);CRAP-P】
3. **视觉节奏 = 规律间距的重复。** 可预测的节奏强化"同级同重";刻意打破节奏(变化间距 / 尺寸)才用来做注意点——两种都是有意的动作,"随机"不是。【核:Atlassian(visual rhythm)】
4. **层级靠对比建立,不靠"看起来不同"。** 大小 / 字重 / 颜色 / 留白都能建层级,但每级差异要明确;差异模糊 = 层级失效。【核:CRAP-C;Ant Design 中性色】
5. **色彩要"角色化 + 克制"。** 同一色值挂在什么角色上决定怎么用:正文中性色 / 次要中性色 / 品牌·强调色 各有职责;"有语义的颜色"不做装饰,装饰色不担语义。【核:Atlassian(color roles:"Don't use an accent when the color has semantic meaning");Ant Design("对色彩的态度是克制的")】
6. **光学平衡允许偏离刻度,但要能说出理由。** 元素视觉重量不同,机械等距可能失衡;在刻度内做小调整是常规动作,不是例外。【核:Atlassian(optical adjustment)】
7. **中性色文本层级是"层级表",不是"任意灰"。** 成熟做法固定 2–4 级(如 一级 / 二级 / 禁用),并同时定义深浅背景两套;层级次序全篇固定。【核:Ant Design 中性色(分层 + 双背景 + 结合 WCAG 2.0);Atlassian(emphasis levels:default / subtle / subtlest)】
8. **放映型与阅读型 deck 的判据不同。** 现场放映按演讲标准(大标题、正文 18–24pt、行距 ≥1.5);交付阅读型可更小更密——先定场景再套数值。【核:Harvard HSPH checklist;阅读型梯度【估】(待在项目内实测校准)】

## 二、通例(易犯的模式 → 更有效的做法)

| # | 易犯的模式 | 更有效的做法 |
|---|---|---|
| 1 | 每页各自手调间距,"看起来差不多" | 选一个**有限间距刻度**(如 8 的倍数序列),先定"组内距 / 组间距"两级基线,同角色同值、全篇复用。【触发:目检发现"全篇底部留白节奏不齐"】 |
| 2 | 用深浅不同的多种灰表示层次,但角色不稳(说明文字有时比正文深) | 建**文本层级表**:一级 / 二级 / 禁用各定一值,次序全篇不变;换背景时整表切换(浅底一套 / 深底一套)。【触发:三种灰阶的角色化使用未收敛】 |
| 3 | 品牌 / 强调色当"好看的文字色"到处用 | 强调色只用于**该强调的元素**;有语义倾向的颜色(红 / 黄)不做装饰;一页里强调色出现少而准。【触发:目检发现"要点与名称的颜色角色不同源"】 |
| 4 | 奇数条目硬凑对称网格(缩字号 / 拉间距硬对齐) | 允许**刻意不对称**:对齐基准不动(左缘 / 基线),视觉重量用光学微调补差;奇数条目本身是合理选项。【触发:5:4 列表不对称(9 条目固有)】 |
| 5 | 全篇版式要么全同、要么全不同 | 分开两件事:**版式构成**可以每页不同(两栏 / 网格 / 大图),**视觉语言**(字色角色 / 间距刻度 / 重复母题)必须全篇一致。【触发:调研发现("别重复版式"与 CRAP「重复」的表面冲突——正解是二者分工)】 |
| 6 | 标点风格随机漂(同一文档全 / 半角混着来) | 同一文档**同一选择**;若混用是作者文风 → 写成明示决策,不再当缺陷。【触发:标点全 / 半角混用项(与作者文风一致,刻意保留)】 |
| 7 | 拿演讲型字号标准硬压阅读型 deck(或反向) | 先判场景:**放映型**按 Harvard(标题 28 / 正文 18–24 / 行距 ≥1.5);**阅读型**另立梯度并实测校准。【触发:typography.md 记录过"Harvard 18pt+ vs 项目 14–16pt"的表面分歧】 |

## 三、强制程序(动手前后自查)

1. **分诊这处"不对"属哪类:** 间距节奏 / 色彩角色 / 构成平衡 / 文字微排版——先归层再动手(不归层就调 = 打地鼠)。
2. **指不回就不改:** 每处风格改动要能指回本文件一条通例;指不回 → 放过,或标「候选,待否决」交作者。
3. **机器先行:** 先跑 C1–C9;机器判不了的再进本文件逐条对证(本文件不重复硬阈值)。
4. **改动即复验:** 风格调整后重渲染受影响页再确认(既有 fix→verify 纪律)。
5. **价值判断留门:** 风格偏好类结论一律「候选,待否决」——作者是评审 oracle。

## 四、失败模式(危险实现清单)

| # | 最容易被写成 | 为什么错 | 挡它的 |
|---|---|---|---|
| 1 | 自由手调间距,每页"微调一下" | 单页看都对,放一起节奏断裂 | 通例 1 / 事实 1 |
| 2 | 用无限灰阶逼近层次 | 角色不稳 → 层级反转;换背景时崩塌 | 通例 2 / 事实 7 |
| 3 | 强调色滥用("到处都是重点") | 强调失效;语义色混淆 | 通例 3 / 事实 5 |
| 4 | 为对称牺牲可读(缩字号、挤间距) | 交付质量下降,问题被"整齐"掩盖 | 通例 4 / 事实 6 |
| 5 | 把"变化"理解成全篇换色换字体 | 重复性缺失,观感散 | 通例 5 |
| 6 | 混搭场景数值(阅读型套放映型标准,或反向) | 该大的不大 / 该密的疏 | 通例 7 / 事实 8 |
