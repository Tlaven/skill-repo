# 三时间轴:历史 / 当下 / 未来

> 本文件是 skill 的「三时间轴 / 四类路由 / 当下 DoD」正文;E1–E7 的正文在 `evolution-rules.md`。skill 的 `SKILL.md` 只留摘要与入口。
>
> **本 skill 只做沉淀侧**:对话内容如何进入三个时间桶,以及三者如何不互相污染;不规定"怎么提问、怎么质疑、怎么去模糊"这些对话技巧。

## 一、三句话

- **历史只增不改**,只作方向,不作事实。
- **当下不保留旧陈述**:自洽、可读、与代码对标、核心逻辑可执行。
- **未来必须带状态**:处理最小,不混入 `[是什么]`——**唯一例外**是 `[是什么]` 未收敛时的「方向草案」双段(其中**只有方向半段的每行**必须带状态并显式标注方向草案;**现状半段保持事实、不带方向状态**;收敛后移出)。

## 二、映射表

| 时间桶 | 陈述性质 | 住哪 | 真相源 | 维护动作 | 验证 |
|---|---|---|---|---|---|
| **历史** | 决策型 | ADR(决策正典)/ `docs/reviews/`(记录)/ git | 历史 | 只增不改;被推翻标 `⚠️` 保留原文;不复述现状 | 只作方向;不把记录当事实 |
| **当下** | 描述型 + 约束型 | L1 / L2 / L3 / L4 / `docs/glossary.md` | 代码 / 契约 | 指针优先;不保留旧陈述;定期对账 | 脚本 + 多镜复核 |
| **未来** | 方向型 | L1「开放问题」/ 项目计划文件(L3「实现方向」/ ROADMAP / task_plan) | 承诺 | planned → doing → done / dropped;done 移出;dropped 升格 ADR | 状态 / 归属 / 结案条件;不混入事实段(唯一例外:方向草案双段) |

> **记录 vs 正典:** `docs/reviews/` 是记录,不是决策正典;ADR 的「需要跟进的」段也是历史记录,不是未来桶的正典。未来桶 = L1「开放问题」/ 项目计划文件;要让 ADR 的跟进项保持活跃,在项目计划里登记并回指 ADR。

## 三、四类路由(每段对话产出)

每段对话产出立即判类并落盘:

- **决策 / 被拒方案** → 历史(ADR / `docs/decisions/`)。
- **事实 / 不变量 / 术语** → 当下(L1 / L2 / L3 / glossary)。
- **计划 / 开放问题 / 候选** → 未来(L1 开放问题 / 项目计划文件)。**候选是状态,不是落点**:未接受的候选一律标 `候选(待否决)` 并登记在未来桶;接受后 → 历史(ADR)或当下(不变量 / 术语)。
- **未决且决策级** → 开放问题 + 请人拍板;不硬写成结论。

判不准时问一句:**它是关于过去的选择、现在的真相,还是未来的意向?** 三者都不是,可能属于对话技巧,不归本 skill。

## 四、历史的使用三问

1. 读它是为了**理由 / 被拒方案 / 方向**,还是为了**现状事实**?
2. 引用只写在**入口类文档的导航位**,还是写在**现状陈述旁边**?
3. 现状断言是否**自足**,还是挂在记录类文档上当依据?

规则:**历史只作方向,不作事实**。若已拷入 `scripts/`,`scripts/check-doc-refs` 的「现状文档引记录」是这条规则的代理检查(抓显式引用,抓不到语义上的"拿旧结论当现状");未拷则靠复核。

## 五、未来最小协议

未来只需要三件事:

1. **状态**:planned / doing / done / dropped。
2. **归属**:谁拍板。
3. **结案条件**:什么情况下移出。

处理规则:done 移出活跃清单;带理由的 dropped 升格为"不做 X"的 ADR;方向型陈述不混入 `[是什么]`。**唯一例外**是未收敛时 L1 概述的「方向草案」双段:其中只有方向半段的每行带状态并显式标注方向草案;现状半段保持事实、不带方向状态;收敛后移出。

未来**不配检查器**——只在 audit / 复核里看这三条。开放问题 / 计划属于未来(开放问题 + 结案条件),不是历史。

## 六、当下完成标准(DoD)

当下层是三者中最复杂的。四条同时满足才算写完:

1. **自洽** `[需独立复核]`(自洽镜;仅在跑 panel 时要求;未跑复核按 L1「文档完成判据」跳过这条)+ `[脚本可查]`(`check-consistency.py`,警告):一个术语一个定义;一条不变量只在一处成文,别处只留指针;陈述的时态 / 类别正确;跨层引用不产生第二份定义。
2. **可读** `[脚本可查]`(`lint-doc-structure.py`,警告)+ `[只能靠自觉]`(作者自检):主流程 10–20 行;每段有例子或指针;不做实现抄写;标题层级能当目录。**可读性镜是可选加强,不是 DoD 的必需复核**;不跑时由 lint 警告 + 作者自检兜底。
3. **对标** `[脚本可查]`(`check-code-refs.py`)+ `[只能靠自觉]`(`last verified`):描述型事实要么是指针,要么是可核对断言;内联代码引用(路径 / 符号 / flag / 配置键)有效;代码改动映射到文档更新;基线记 `last verified` SHA(可选)。
4. **核心逻辑** `[脚本可查]`(`run-n2-acceptance.py`)+ `[需独立复核]`(N2 镜;N2 变更时必跑;跳过则必须跑 N2 验收并标「未复核」):每条 N2 有步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收 + 失败语义;每个危险项都被某条不变量或验收挡住。

> 工具用法见 skill 侧 `references/tooling.md`;复核镜头见同目录 `review-panel.md`。**脚本未拷入项目时,相关项标「未接 / 未复跑」,不得当成已通过。**

## 七、与 E1–E7 的关系

三条时间定律是**总则**;E1–E7 是实施细则:

- E1 描述型 → {当下}
- E2 方向型 → {未来}
- E3 约束型 → {当下}
- E4 决策型 → {历史}
- E5 对账 → 跨时间(当下 vs 代码 / 历史 vs 当下引用 / 未来 vs 状态)
- E6 代码注释 → 代码与历史的分界
- E7 术语 → {当下}

读 E 规则前先读本文件的三句话;两者冲突时,以三句话为准,并回改 E 规则。
