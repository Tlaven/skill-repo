# 三时间轴:历史 / 当下 / 未来

> 本文件是 skill 的「三句维护律 / 四类路由 / 当下 DoD」正文;E-1–E-7 的正文在 `evolution-rules.md`。skill 的 `SKILL.md` 只留定位与入口。

## 一、三句话

- **历史内容只增不改,存在按寿命裁剪**:仍约束的升格进当下后退役;只作方向,不作事实。
- **当下不保留旧陈述**:自洽、可读、与代码对标、核心逻辑可执行。
- **未来必须带状态**:处理最小,不混入 `[是什么]`——未收敛时概述只写现状(「方向未定」即现状),方向住「开放问题」。

## 二、映射表

| 时间桶 | 陈述性质 | 住哪 | 真相源 | 维护动作 | 验证 |
|---|---|---|---|---|---|
| **历史** | 决策型 | ADR(决策工作台)/ `docs/reviews/`(复核记录)/ git | 历史 | 内容只增不改,存在按寿命裁剪:仍约束 → 升格进当下后退役;有证据地不再约束 → 退役(移出工作区,git 保留);答不出 → 退役候选,交作者;被取代标 `superseded`,前提**有证据地**消失标 `expired`;不复述现状 | 只作方向;不把记录当事实;退役不是删除 |
| **当下** | 描述型 + 约束型 | L1 / L2 / L3 / `docs/glossary.md`（L4 是阅读视图，不是约束的家） | 代码 / 契约 | 能从代码读出的不抄;不保留旧陈述;定期对账 | 脚本 + 多镜复核 |
| **未来** | 方向型 | L1「开放问题」/ 项目计划文件(L3「实现方向」/ ROADMAP / task_plan) | 承诺 | planned → doing → done / dropped;done 移出;dropped 升格 ADR | 状态 / 拍板人 / 结案条件;不混入事实段 |

> **记录 vs 唯一正文归属:** `docs/reviews/` 是记录,不是决策的唯一正文归属;ADR 的「需要跟进的」段也是历史记录,不是未来桶的唯一正文归属。**仍成立的决策理由的唯一正文归属是当下的 `[为什么]` / 不变量**,不是 ADR。未来桶 = L1「开放问题」/ 项目计划文件;要让 ADR 的跟进项保持活跃,在项目计划里登记并回指 ADR。

## 三、四类路由(每段对话产出)

每段对话产出立即判类并落盘:

- **决策 / 被拒方案** → 先判载体:可逆 / 局部 / 一次性 → commit body;需评审 / 跨模块 → PR / RFC;不可逆 / 长期约束 → ADR(`docs/decisions/`)。
- **事实 / 不变量 / 术语** → 当下(L1 / L2 / L3 / glossary)。
- **计划 / 开放问题 / 候选** → 未来(L1 开放问题 / 项目计划文件)。**候选是状态,不是落点**:未接受的候选一律标 `候选(待否决)` 并登记在未来桶;接受后 → 历史(ADR)或当下(不变量 / 术语)。
- **未决且决策级** → 开放问题 + 请人拍板;不硬写成结论。

判不准时问一句:**它是关于过去的选择、现在的真相,还是未来的意向?** 三者都不是,可能属于对话技巧,不归本 skill。

## 四、历史的使用四问

1. 读它是为了**理由 / 被拒方案 / 方向**,还是为了**现状事实**?
2. 现状文档里有没有**指向记录条目 / 记录目录**的引用?(有 = 违规:读者该看到的是现状,不是出处;**稳定条款代号不算**——那是合法引用)
3. 现状断言是否**自足**,还是挂在记录类文档上当依据?
4. 它现在还挡着哪个**具体**的错误改动?(答不出 = 退役候选,只登记交作者;仍挡着但现状文档没有 → 先升格,再退役)

规则:**历史只作方向,不作事实**。活文档里唯一允许出现记录类目录的地方,是入口文档的**活文档索引**那一张表(它只描述"哪份文档管什么")。若已拷入 `scripts/`,`scripts/check-doc-refs` 的「现状文档引记录」是这条规则的代理检查(抓显式引用,抓不到语义上的"拿旧结论当现状");未拷则靠复核。

## 五、未来最小约定

未来只需要三件事:

1. **状态**:planned / doing / done / dropped。
2. **拍板人**:谁做决定。
3. **结案条件**:什么情况下移出。

处理规则:done 移出活跃清单;带理由的 dropped 升格为"不做 X"的 ADR。

未来**不配检查器**——只在 audit / 复核里看这三条。

## 六、当下完成标准(DoD)

当下层是三者中最复杂的。四条同时满足才算写完:

1. **自洽** `[需独立复核]`(自洽镜;仅在跑 panel 时要求;未跑复核按 `docs-templates/methodology.md`「文档完成判据」跳过这条)+ `[脚本可查]`(`check-consistency.py`,警告):一个术语一个定义;一条不变量只在一处成文,别处**不写摘要**(按稳定代号引用不算第二处);陈述的时态 / 类别正确;跨层引用不产生第二份定义。
2. **可读** `[脚本可查]`(`lint-doc-structure.py`,警告)+ `[只能靠自觉]`(作者自检):主流程 10–20 行;**同一层内部自足**（低层默认已读上层；有例子优先；高层不引用低层正文；不靠句子级“见 X”补信息，低层引高层契约不算）；不做实现抄写;标题层级能当目录。**可读性镜是可选加强,不是 DoD 的必需复核**;不跑时由 lint 警告 + 作者自检兜底。
3. **对标** `[脚本可查]`(`check-code-refs.py`)+ `[只能靠自觉]`(`last verified`):描述型事实要么指向文件 / 目录,要么是可核对断言;内联代码引用(路径 / 符号 / flag / 配置键)有效;代码改动映射到文档更新;文档基线记 `last verified` SHA(可选)。
4. **核心逻辑** `[脚本可查]`(`run-n2-acceptance.py`)+ `[需独立复核]`(N2 镜;N2 变更时必跑;跳过时按 `review-panel.md`——有 manifest 才跑 `--run`，无 manifest 标「未复跑」，并在留档标「未复核」):每条 N2 有步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收 + 失败语义;每个危险项都被某条不变量或验收挡住。

> 工具用法见 skill 侧 `references/tooling.md`;复核镜头见同目录 `review-panel.md`。**脚本未拷入项目时,相关项标「未接入(scripts 未拷入)/ 未复跑(脚本在但未执行)」,不得当成已通过。**

## 七、与 E-1–E-7 的关系

三条时间定律是**总则**;E-1–E-7 是实施细则:

- E-1 描述型 → {当下}
- E-2 方向型 → {未来}
- E-3 约束型 → {当下}
- E-4 决策型 → {历史}
- E-5 对账 → 跨时间(当下 vs 代码 / 历史 vs 当下引用 / 未来 vs 状态)
- E-6 代码注释 → 代码与历史的分界
- E-7 术语 → {当下}

读 E 规则前先读本文件的三句话;两者冲突时,以三句话为准,并回改 E 规则。
