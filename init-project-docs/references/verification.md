# 复核 / 核对

> 本文件管两件事：**复核**（独立 agent 复述 / 找缺口 / 判定）与**核对**（E-5 跨时间一致性审计）。
> 读的时机：改代码前 / 版本审计。
> 基座 prompt 在 `teach-back-verifier-prompt.md`；完整校准手册由 skill 维护者保留，不随项目落地。
> 验收造法见 `acceptance.md`；记录寿命见 `lifecycle.md`；脚本见 `scripts/`。

## 一、两者的分界

| | 复核 | 核对 |
| --- | --- | --- |
| **问题** | 文档写没写清 | 文档与代码 / 记录 / 状态是否一致 |
| **对象** | 文档本身 | 文档 vs 现实 |
| **方法** | 独立 agent 复述 + 找缺口 | 逐条摊开比对 |
| **产出** | 通过 / 不通过 / 需人拍板 | 差异清单 + 处置 |
| **不判** | 断言真伪 | 文档内部清晰度 |
| **时机** | 改代码前，按需 | 版本级 / 定期 |
| **阻塞** | 不阻塞实现（N2 规格不合格除外） | 主战场在改代码前 |

两者可以同时跑，但**不合并判定**。两类记录同住 `docs/reviews/`，文件名用日期 + 主题区分。

## 二、复核

**teach-back** = 让独立 agent 复述文档、指出缺口并给判定。

### 2.1 视角

| 视角 | 问什么 | 输入 | 输出 |
| --- | --- | --- | --- |
| **自洽** | 时态 / 类别对不对；同一事实是否多处定义；不变量是否多处成文；跨层引用是否产生第二份定义；三段是否矛盾；记录有没有超过一个核对周期仍未处置 | L1 / L2 / L3 + glossary + 工作台清单 | 缺口 + 判定 |
| **去模糊** | 每个模糊词 / 主观要求是否可判定：两个互斥解释、可测代理指标、或已定义术语 | 文档 + `acceptance.md` | 词句 + 改写建议 |
| **术语** | 一个词一个定义；同物异名、一词多义、废弃别名、未登记新词；含义变化是否触发不变量变更 | 文档 + glossary | 术语清单 + 建议 |
| **代码对标** | 路径 / 符号 / CLI flag / 配置键 / 主流程 / 不变量 / `[已定]` 是否与代码一致；文档基线是否准确 | 文档 + 代码 + 内联引用脚本 | 可核对断言清单 + 差异 |
| **N2 可实现**（N2 变更时必跑） | 步骤级 / 危险实现清单 / 例子 / 可跑验收 / 失败语义 | N2 单元 | 缺口 |
| **可读性**（可选） | 主流程长度、示例、结构、是否抄实现 | 文档 | 警告 + 建议 |

- **判定范围**：L1 / L2 判决策级；L3 / N2 判实现级（N2 一律判实现级，无论住 L2 还是 L3）；**L4 不判**——它不给验收、没人引用，判它等于用错标准。
- 时态 / 类别检查并入**自洽**，不单独开视角；退役检查也并入自洽：只报「超过一个核对周期 / 未处置」的结构缺口，不判记录该不该退。
- **可读性**是唯一可选视角；不跑时由作者自检兜底。
- **N2 视角**在 N2 变更时必跑；跳过时仍必须跑 N2 验收（有 manifest 才 `--run`；无 manifest 标「未复跑」），并在留档标「未复核」。

### 2.2 触发

**四信号决定跑不跑：** ① 单元标了 N2；② 改到了不变量；③ 用词还没有可判定的定义；④ **跨层大改**——内容在层间搬家，或新增 / 删掉一层。四条都不占就跳过；纯 N1 且验收写得出来也跳过。

**C-1 约束性文档** = L1 / `docs/design-contract.md`（若有）/ L2 / `docs/modules/**` / `docs/glossary.md`。`docs/core-analysis.md`（L4）**不算**——它是阅读视图，不给验收、不被引用，改了不影响实现。

**C-2 约束性变更** = 其中不变量、`[已定]`、接口 / 数据结构 / 失败码、术语定义、或约束性断言的增删改；纯措辞 / 链接 / 排版不算。

**P-1 复核档位**（按改动大小选一档，不要一律派四个）：

| 档 | 派什么 | 什么时候 |
| --- | --- | --- |
| **单视角** | 1 个通用视角（只给基座 prompt，不加 addendum） | 四信号命中，但只动一个文件 / 一处措辞 |
| **标准** | 按文件映射的 2–3 个视角 | 命中四信号，动到 2 个以上模块或多份约束性文档，但没有换层 |
| **全档** | 四视角（自洽 / 去模糊 / 术语 / 代码对标），可再加一个通用视角 | 跨层大改，或全量核对 |

- N2 变更时档位不得低于标准（必须含 N2 视角）。
- 约束性变更不是第五个触发条件；`[已定]` 改了就是命中 ②。
- 可读性不进任何档的必跑集。
- **commit（轻量）**：不默认跑 panel；可选 `check-code-refs` + `check-doc-refs`，不等于任何一档。
- **里程碑 / 发布**：不因为「里程碑」本身开 panel；按四信号与是否换层选档。
- **按文件选视角**（标准 / 全档内）：glossary → 术语 + 去模糊；design-contract → 自洽 + 术语；architecture / modules → 自洽 + 代码对标（有 N2 变更时加 N2）；L1 → 自洽 + 术语；core-analysis 不在映射内。

### 2.3 派发

- **攒批**：拷进 `scripts/` 的，先跑 `review-backlog`（不花 token）列出自上次复核以来改了什么；没拷就人工列，并标「未接入 / 未复跑」。只把改动喂给独立 agent。
- 每个视角一个独立 subagent，**互不可见**；看不到本会话历史。
- **基座 prompt** = `teach-back-verifier-prompt.md`（复述 / 缺口 / 判定；`[阻断]` / `[非阻断]` / `需人拍板`；词句类必须逐字引用）。
- 每个视角只加一段 **addendum**（该视角的检查项与输出差异），不复制基座。
- 代码对标视角允许只读代码；其它视角只给文档 + glossary + 相关不变量。这是基座 prompt「唯一输入」段的显式例外，在 addendum 里写明。
- 一个待验证单元 = 一份派发参数；可以并行派多个视角，但每份判定互相独立。**每个被喂的单元要给整节（定义段 + 验收段必须都在）。**
- 第一次跑，「上轮阻断清单」填「无」。
- 通用 teach-back 管「能否据此做决策 / 实现」；panel 管当下层的四个具体问题。两者可以同时跑，但不要合并判定。

### 2.4 反馈回路

1. **第 1 轮**：各视角独立产出；协调者合并、去重、按文件 / 断言定位到具体段落。重复发现算一条，不算四条。
2. **修复**：只改文档，不改提示词；每条阻断项要能指回具体段落。
3. **第 2 轮**：新验证者；先逐条复核上轮阻断项（附证据），再扫描受影响范围。**必须附上轮阻断清单**——不附 = 每轮全量重掷。
4. **校准**：每个视角配一个已知缺陷探针；探针没红，这一视角的「没问题」不可采信。探针清单见本节末的「校准探针」表；拿不到探针 → 留档标「未校准」，该视角判定降为参考。
5. **退出**：无阻断 + 全扫无新发现；`需人拍板` 转作者，不循环改文档。
6. **留档**：`docs/reviews/YYYY-MM-DD-<主题>.md`；覆盖的提交写进 `docs/reviews/.last-review`（游标，不退役）。reviews 按核对周期整批退役——下一次全量核对后，上一批移出工作区（git 保留）。

**校准探针：**

| 视角 | 已知缺陷探针 |
| --- | --- |
| 自洽 | 同一事实两处矛盾 / 一条不变量在两处成文 |
| 去模糊 | 「合理处理」既无阈值、也给不出两个互斥解释 |
| 术语 | 同一词两处定义 / 未登记的同义词 |
| 代码对标 | 引用不存在的路径 / 符号；或代码已改、文档基线未更新 |
| N2 可实现 | N2 缺可跑验收 / 危险清单项无遮挡 |
| 可读性 | 主流程缺失 / 大段无结构 |

### 2.5 输出

每个视角按基座 prompt 输出「复述 / 缺口表 / 判定」；协调者再产出一张合并表：

| 视角 | 阻断 | 非阻断 | 需人拍板 | 覆盖范围 |
| --- | --- | --- | --- | --- |
| 自洽 | | | | |
| 去模糊 | | | | |
| 术语 | | | | |
| 代码对标 | | | | |
| N2（变更时必跑）/ 可读性（可选） | | | | |

**结论只写三档**：通过 / 不通过（文档缺陷）/ 需人拍板。**通过只说明文档内部一致，不证明断言为真。**

### 2.6 视角 addendum（派发时贴在基座 prompt 的「待验证文档」前）

- **自洽视角：** 只报「陈述放错时间桶 / 同一事实多处定义 / 不变量多处成文 / 跨层重述 / 三段互相矛盾」；每条附原文与位置。另报「工作台 / reviews 里存在超过一个核对周期、仍未处置的记录」——只报存在与路径，不判该不该退。不要报词义、不要报代码差异。
- **去模糊视角：** 只报「无法判定」的句子；每条给出两个互斥解释，或一个可测代理指标。不要报术语身份、不要报代码差异。
- **术语视角：** 只报「词的身份」问题——同物异名 / 一词多义 / 废弃别名 / 未登记新词 / 含义变化；附 glossary 对照。不要报句子可判定性。
- **代码对标视角：** 只报可证伪断言——路径 / 符号 / CLI flag / 配置键 / 主流程 / 不变量 / `[已定]`；若已拷入 `scripts/`，先跑 `check-code-refs.py`，再抽查主流程与不变量。不要报文档内部自洽。**输入例外：** 允许只读仓库代码；不得修改文件。
- **N2 可实现视角（N2 变更时必跑）：** 只报步骤级 / 危险清单 / 例子 / 验收 / 失败语义的缺口。
- **可读性视角（可选）：** 只报结构 / 示例 / 主流程长度 / 实现抄写；明确写「这是建议，不是阻断」。

### 2.7 dispatch packet（派发包；可直接复制）

> **基座 prompt = `teach-back-verifier-prompt.md`；不要复制基座全文。** dispatch 文件只写：文件清单 + 视角 addendum + 校准探针 + 输入覆盖 + 输出差异。
>
> **输入覆盖：** 本次是包审计，基座 prompt 的「唯一输入」段由 dispatch 的文件清单覆盖；其余判定纪律（决策级 / 实现级、三档、逐字引用、上轮阻断）全部沿用。代码 / 资产视角可只读运行脚本与读代码；其它视角只读清单内文件。仍不许读会话记录 / notes / 其它 skill，不许改文件。

```
docs/reviews/<YYYY-MM-DD>-<主题>-panel/
  MANIFEST.md
  dispatch/
    lens-01-consistency.md
    lens-02-ambiguity.md
    lens-03-terminology.md
    lens-04-code-assets.md
    lens-05-implementability.md
  probes/                  # 可选：探针独立成文件
  outputs/
    lens-01.md ... lens-05.md
  merged.md
  recheck.md               # 第 2 轮：只列上轮阻断
```

**MANIFEST 最小字段：** 日期 / skill / commit / model / effort；文件清单（路径 + 行数或 sha256）；视角（名称 + 判定范围 + 输入例外）；校准（每个视角：探针 + 命中 / 未命中）；输出路径。

**dispatch 文件模板：**

```markdown
# Lens: <name>

## 0. 先读
- `docs-templates/teach-back-verifier-prompt.md`（基座；项目内路径）
- 本文件「addendum / 探针 / 文件清单 / 输入覆盖」

## 1. 任务
- 对象：init-project-docs skill 包（或指定项目）
- 判定范围：决策级 / 实现级（两者都标）
- 输入例外：代码视角可只读仓库 + 运行脚本；其它视角只读清单内文件

## 2. 视角 addendum
<复制对应视角>

## 3. 校准探针
<3–5 行已知缺陷>
先报告命中 / 未命中；未命中 = 本视角未校准，后续「没问题」不可采信。

## 4. 文件清单
- ...

## 5. 输出
按基座 prompt 的「复述 / 缺口清单 / 判定」；额外加 `## 校准`。
```

**纪律：** 一个视角一份 dispatch，一单元一份派发参数；各视角互不可见；协调者只合并去重；第 2 轮新验证者附上轮阻断清单。派不出独立 agent 时：把待验证正文 + 派发参数封存到 `docs/reviews/<日期>-<主题>-package/`，配 `MANIFEST`（文件清单 + 校验值 + SHA）；另写声明记录标「复核未执行」；不要自评充数。

> 上面的 `lens-05-implementability` 是 **skill 包审计**的实现级纸面走查；项目侧的「全 panel」只需 `lens-01..04`（N2 变更时加 N2 视角；可读性可选）。

### 2.8 边界与兜底

- **复核判的是「文档写没写清」，不是「断言为真」。** 事实类断言靠外部核实（试跑 / 来源）：能试跑先试跑，不能则写出来源或谁拍的板。
- **跳过要留痕**：计划过复核又跳过 → 在任务笔记 / 决策记录里落一行「未复核（日期 / 原因）」。
- **复核不阻塞实现**；但 N2 规格过不了合格线时，先补规格再放行实现（这是规格的闸门，不是复核的闸门）。
- **派不出独立 agent 时**：① 把待验证正文 + prompt + 派发参数封存到 `docs/reviews/<日期>-<主题>-package/`，配 `MANIFEST`（文件清单 + 校验值 + git SHA）；② 另写一份声明，明写「复核没做」；③ 把「跑一次独立复核」列为移交项。不要自评充数，也不要卡死；等不等复核由你定。

## 三、核对（E-5）

**核对 = 把文档与代码 / 记录 / 状态逐条摊开比对，列差异与缺口。**

- **主战场在改代码前**：文档是实现的约束；本节的「触发式 / 集中式」核对是版本级兜底，不是替代事前复核。
- **四类核对：** ① 当下 vs 代码（描述型事实、主流程、`[已定]`）；② 历史 vs 当下引用（现状文档里有没有指向记录的引用——依据、出处行、编号都算）；③ 未来 vs 状态（方向项是否有状态 / 拍板人 / 结案条件）；④ 历史 vs 约束（逐条问 E-4 三问：还挡着哪个错误改动 / 会否复发 / 现状能否读出 → 升格或退役）。
- **触发式**：每次版本级变更合并前，对照检查本次改动触碰的模块，其 L1 / L2 / L3 文档、不变量、危险清单、`[已定]` 项是否被改动（改了必须有 ADR），以及外部 AI 接口文档是否需要同步。
- **集中式**：每隔几个版本做一次**全量核对**：通读 L1 + `docs/architecture.md`，凡与代码现状不符的陈述当场修正；发现「文档说有但代码没有 / 代码有但文档说没有」的，修文档并记下当初漏更新原因。
- **先验真假再改**：核对里出现的「文档自相矛盾」，先拿数据（对拍 / 脚本）判谁错再动刀——**别默认「文档写得晚所以文档对」**。
- **产出落档**：每次核对（含 teach-back 与全量核对）写一份到 `docs/reviews/YYYY-MM-DD-<主题>.md`；并改文档本身；若漂移暴露流程问题，把对策写进 L1。

### 3.1 保留与退役

- 每次**全量核对**完成后，上一批 `docs/reviews/` 整体退役（移出工作区；git 保留）；本批留到下一次。`.last-review` 是游标（SHA + 日期），不是历史，永不退役。
- **退役前检查**：本批 reviews 里未闭合的 finding 必须已经（改文档 / 进开放问题 / 有 ADR）；有未闭合项 → 不许整批退役，先处置。
- ADR 按 E-4「记录寿命」处理；全量核对是唯一的批量退役点。退役候选（答不出三问）只登记，交作者拍板；每批退役在核对记录里留一行清单。
- reviews 不做摘要 / 索引：唯一的「压缩产物」是写进 L1 的流程修正那一条。
- 非 git 项目只标 `expired`，不退役。

## 四、自检

**复核：**

- [ ] 命中了四信号中的哪一条？一条都不占就跳过了吗？
- [ ] 复核档位选对了吗？N2 变更有没有低于标准？
- [ ] 每个视角是否独立、互不可见？
- [ ] 有没有复制基座 prompt、把 addendum 写成全文？
- [ ] 探针红了吗？没红有没有标「未校准」？
- [ ] 第 2 轮有没有附上轮阻断清单？
- [ ] 结论是否只写三档？「需人拍板」有没有转作者？
- [ ] 派不出时有没有封存 + 声明 + 移交？

**核对：**

- [ ] 四类核对都做了吗？
- [ ] 触发式 / 集中式选对了吗？
- [ ] 文档自相矛盾时，先拿数据判真假了吗？
- [ ] 产出落档了吗？文档本身改了吗？
- [ ] 退役前未闭合的 finding 都处置了吗？
- [ ] 退役有正面证据吗？
