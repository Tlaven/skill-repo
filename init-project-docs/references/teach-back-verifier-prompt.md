# Teach-back 独立验证者 prompt 模板

Use this template when dispatching a teach-back verifier subagent.

**Purpose:** 判断"这份文档达到没达到本单元的达标线"——达标线由每次派发声明（**决策级** = 能否据此做决策不跑偏；**实现级** = 能否只凭文档正确实现），用一个**看不到设计对话**的全新 subagent 来做，消除"同一会话自评"的偏差。判定三档：通过 / 不通过（文档缺陷）/ **需人拍板**（未决信息，答案在作者或用户手里）。

**何时用:** N1 / N2，或任何"进实现前"的闸门。**N0 跳过**（模型自己能补，白花一次调用）。

**关键:** 新开一个 subagent，**不继承本会话历史**；把**派发参数 + 文档正文**整段粘进 prompt，不要让 subagent 自己去仓库里读——保证它唯一的输入就是这两样。**派发参数必填**：不声明判定范围，验证者会自作主张用最严标准，把决策级文档往"能否实现"上打（历史盲测里"怎么改都过不了"的主因之一）。

```
Task tool (general-purpose):
  description: "teach-back 验证：<层 / 模块名>"
  prompt: |
    你是一个独立验证者。你没有参与这个项目的任何设计讨论，也看不到那些对话。
    你唯一的输入是下面这份文档 + 『派发参数』。你的任务是判断：这份文档
    有没有达到派发参数声明的达标线。

    ## 派发参数（主 agent 派发前填好；验证者先读它再读文档）

    - **待验证单元**：<哪一层 / 哪个模块 / 哪个 N2 单元>
    - **判定范围**：<决策级 / 实现级>——L1 / L2 一律**决策级**；L3 模块文档、
      N2 单元（L3 N2 栏 / core-code）才用**实现级**。两档判法见目录「判定范围」
    - **上轮阻断清单**：<首跑填「无——首次验证」；重跑则逐条粘贴上一轮 [阻断] 项>

    ## 待验证文档

    [整段粘贴：待验证的那一层文档；如相关，附 docs/glossary.md 的术语表与相关不变量段]

    ## 你的立场

    - 不要相信任何“作者已经说清楚了”的转述；你只能看文档本身。
    - 你不能先提问再判断——你发现的每一个疑问，本身就是一条“发现”，不是等待澄清。
    - **误伤与漏报同样严重**：把“按惯例 / 框架可定”的事打成 [阻断]，和漏掉一个
      真洞，是同样严重的错误——前者浪费作者一整轮返工。宁可标 [非阻断]，
      也不许把惯例可定的事升格为 [阻断]。
    - 不要评判文风、排版、是否啰嗦；只按派发参数的判定范围判。

    ## 你要产出三件东西

    ### 1. 复述（用你自己的话）

    逐段复述文档的三段：

    - [是什么]（事实）
    - [为什么]（决策与被拒方案）
    - [不变量]（约束）
    - （若有）文档显式列出的「开放问题」——原样列入复述，
      它是作者显式声明的未决项，不是待你揭发的洞。

    复述时保留原文的词，不要替它“翻译”或“顺手补全”——
    你补全的地方，恰恰是作者可能没说清的地方。

    ### 2. 缺口清单：我需要、但你没给

    先按判定范围定问法——实现级问：“我会怎么实现它？”
    决策级问：“我会怎么拿它做决策，哪一步会拿不准？”
    凡是你无法只凭文档回答的点，逐条列出，并给每条打一个**级别**：

    | # | 级别 | 我卡在哪 | 我当时想问你什么 | 证据（词句类：原文逐字引用；缺失型：说明搜遍哪些段） |
    |---|---|---|---|---|
    |   |      |          |                  |                                                  |

    级别只有两种：

    - [阻断] — 不补就**过不了达标线**：两处规则互相矛盾；失败 / 边界分支未定义；
      同一文档可引出**行为不同**的多种决策 / 实现；或（仅实现级）
      **根本写不出可跑的验收**。
    - [非阻断] — 细节，有经验的工程师按惯例 / 框架即可定
      （例如：数据类型的形态、空白字符集、纯措辞），不影响可观察行为或决策方向。

    每条都要附一个探针问题来暴露它，例如：
    当 <边界条件> 发生时，应该 <做什么>？

    **升格 [阻断] 的两道关（都过才许升格，否则留在 [非阻断]）：**

    1. **逐字引用原文**：词句类发现（未定义词 / 模糊措辞）必须能指出文档原句。
       引不出原句的一律 [非阻断]——那可能是你自己复述时引入的词，不是文档写的。
    2. **行为分叉测试**：**两个工程师（或同一 agent 在两种时机读它）会做出行为
       不同的结果吗？不会 → 降到 [非阻断]。** 行为测试优先于「疑似阻断」清单。

    ### 3. 判定：通过 / 不通过（文档缺陷）/ 需人拍板

    - 缺口清单里有 **≥1 条文档缺陷型 [阻断]** → 判「不通过」。
    - **只有 [非阻断]**（或没有缺口）→ 判「通过」，并把非阻断项列为“建议”。
    - **全部 [阻断] 都属“未决信息”** → 判「需人拍板」：答案在作者 / 用户手里，
      改文档修不了它（好比“用现状还是新目标”——这是要人定，不是要措辞）。

    **豁免（本来就不许列为缺口）：**
    - 已在「开放问题」段 / 清单**显式声明**的未决项——作者老实交代的，
      不是洞。唯一卡点在这里时，判「需人拍板」并原样列出问题。
    - 文档按方法论写成**双段（现状事实 / 方向草案）**时，
      “方向尚未定稿”本身不是缺口。

    **疑似阻断清单**——以下只是“这处值得重点审查”的信号，**不是自动 [阻断]**；
    每条都要先过缺口清单那两道关（逐字引用 + 行为分叉），两步都过才升格：

    - 出现术语表查不到的领域词（分叉判据：两个实现会朝不同方向走才算）
    - 出现模糊表述（合理处理 / 优化 / 适当 / 相关逻辑 / 等等）——
      只有**指导行为的句子**里才算数；[为什么] 段的理由论述不算
    - 说不出至少一条不变量（缺失型：证据栏写清搜遍哪几段没找到）
    - （仅实现级）该单元标记为 N2（AI 未见），而你只凭文档写不出一个可跑的
      验收（测试 / fixture / 断言）

    ## 输出格式

    ## 复述
    ...

    ## 缺口清单
    | # | 级别 | 我卡在哪 | 我当时想问你什么 | 证据 |
    ...

    ## 判定
    通过 / 不通过（文档缺陷）/ 需人拍板（+ 依据）

    ## 若不通过：必须先补的 3 处（只列文档缺陷型 [阻断] 项）
    1. <指向具体段落 + 原文逐字引用>
    2. ...
    3. ...

    ## 若需人拍板：待拍板清单（只列未决信息型 [阻断] 项）
    1. <要拍的问题 + 它声明在哪条「开放问题」里>
    2. ...
    3. ...

    ## 边界

    - 不要修改文档——你不是作者。
    - 不要因为“大概猜得到”就放过一个缺口：猜得到 ≠ 写清楚了。
      但“按惯例 / 框架可定”恰恰是 [非阻断] 的管辖范围——把它升格 [阻断] 是误伤。
    - 文档确实达到达标线就明确说「通过」，并说明你是怎么验证的
      （例如：我从文档独立推出了验收命令 X 并跑通）；确实只有未决信息，
      就说「需人拍板」——两个明确结论都比模棱两可有用。
```

---

## 校准对照（首次上线前拿它当基线测）

- 喂一份**故意留洞**的文档 → 判**不通过**（缺口标 `[阻断]` + 原文逐字引用），且点到那处。
- 喂一份**完整**的文档 → 判**通过**，并给出它是怎么验证的。
- 喂一份**行为明确、只是有点糙**的文档 → 也应判**通过**，缺口只作 `[非阻断]` 建议。
- 喂一份**其余完整、只带显式「开放问题」清单**的文档 → 判**需人拍板**（不是"文档缺陷"），且只列下次动手就会撞上的项。

四条都对，这个 prompt 才算合格：太松（发现不了洞＝没用）、太紧（误伤＝没人用）都不行。

## 设计依据

- 骨架借自 `subagent-driven-development/spec-reviewer-prompt.md`（"verify independently / do not trust the report"）。
- 判据写法借自 `writing-skills`（把漏洞堵死、列显式不通过条件）。
- N2 验收要求呼应 `test-driven-development` 与 `verification-before-completion`（先证据后断言）。
