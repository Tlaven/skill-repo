# 演化期规则(E = Evolution;E-1–E-7)——立项之后,文档怎么不死

> **本文件是 E-1–E-7 的唯一正文归属**,随项目落地到 `docs-templates/evolution-rules.md`。
> L1 记忆文件只在「活文档索引」里列出本文件;子文档、决策记录、代码注释都不重述。
> **何时读:** 做文档演进 / 对账 / 大改动前。

**先看总表**——三段式是"容器";每段里的陈述按**性质**分四类,腐烂方式与维护动作各不相同。E-1–E-7 是这张表的分项细则。

| 性质 | 时间轴 | 真相源 | 会怎么烂 | 维护动作 | 细则 |
|---|---|---|---|---|---|
| **描述型**(现状) | 当下 | 代码 | 变假 | 能从代码读出的不抄;改代码后同步;**不保留过时旧陈述** | E-1 |
| **决策型** | 历史 | 历史 | 悬置 | 内容只增不改;存在有寿命:仍约束 → 升格进当下后退役;退役须有正面证据(升格 / 前提消失 / 作者拍板),答不出 → 候选交作者;被取代标 `superseded`,前提有证据地消失标 `expired`;该记才记 ADR | E-1 / E-4 |
| **约束型**(不变量) | 当下 | 契约 | 被悄悄违反 | 每条标 **强制 / 约定**;违反 → 修订原文 / 加例外 / 放弃改动 | E-3 |
| **方向型** | 未来 | 承诺 | 悬置 | 状态机 `planned→doing→done/dropped`;集中安置 | E-2 |

## E-1: 描述型(当下)——陈述退役,[是什么] 不许保留过时的旧陈述

- **[是什么] 段是"现状快照",不是历史博物馆。** 某事实不再成立时,直接改写或删除,**禁止**留旧陈述与新陈述并存(哪怕标注"旧的"),并存 = 读者不知道信哪个。
  > **限定:** "不保留旧陈述"针对**所有活文档**——[为什么] 里的决策论述被推翻时,同样**改写或删除**:不标"已被推翻"、不留原文、不附编号;原话在 git 里(ADR 退役后亦然),那才是记录的家。**方向型**(E-2)保留状态,因为"还没做"是当下事实,不是旧陈述。
- **能从代码 / git 验证的事实不抄**:文件清单、函数名、参数表这类,文档里不重抄——抄写必然漂移。文档只留代码里**读不出来**的事实(边界、数据流方向、协作契约);确有必要指出住处时,指到**文件或目录**(如 `src/`),不指行号、函数名或小节。
- **提示与证据不占正文**:防坑提示("别用 X 去做 Y")、实测比例、轮次与日期、"旧版曾用…""已落地"这类过程叙事——**都不住正文**。正文只留**规则**与**可跑 fixture**(fixture 里也不写"这是第几轮抓的");提示的**理由**:仍成立 → 当下正文(危险清单 / `[为什么]`),过程证据 → ADR / `docs/reviews/`。
  > 判据:**这句删掉之后,读者还知道该怎么做吗?** 知道 ⇒ 它是提示 / 叙事,删;不知道 ⇒ 它是规则,留(并写短)。
- **引用只指稳定代号,不指位置**:正文里可以写 **`D-14` / `A-1` / `R-5` 这类稳定编号**——前提是该编号有一处正文定义、退役编号不复用;**不写**指向小节标题、行号、页码的引用("见上面第 3 节"这种指过去就腐),也不在句子旁挂"见 ADR-0NN"。**条款引用的合法性 = 目标在读者的前置读集合内**(前置读 = 这次工作默认加载的文档)。"只往上"是这个判据的近似:上层总被加载,下层不一定——所以指向更细一层(模块文档、L4)通常说明这句话放低了。同层互指(模块 ↔ 模块)是**允许的例外**:它同样要求读者额外加载一次,只是禁止它就得重述,代价更大;真成常态就把内容上移。**引用补不了加载**——写"见 `C-3`"不会让 `C-3` 被读到;读者若必须去别处取,说明内容放错了层。**索引方向相反:上指下**——文档级目录只写"哪份文档管什么",由上层列下层(契约 → world / upgrade;架构 → modules);模块不写文档目录（由 L2 / L1 列出）；L4 没有下层，也不写目录。读者要知道"去哪份文档",看索引表:**L1 的活文档索引是总表**,各层子索引只是它的分层展开,不能互相替代。那张表只写**每份文档管什么**(例:「完整决策过程 → `docs/decisions/`;仍成立的理由在各层 `[为什么]`」)。**记录目录不进子索引**:`docs/decisions/` / `docs/reviews/` 这类只在 L1 出现一次;子索引(架构 → 模块等)列它们 = 把历史当导航目标。
  > 判据一:索引条目后面能接"这是一份讲 X 的文档"吗?能 → 目录条目;不能 → 去掉。
  > 判据二:删掉它,读者会怎么做?**需要去别处** → 说明这段放置错了,该搬走或删;不需要 → 它是噪声。两个分支都不成立。
- **现状 / 规则陈述必须自足**:不许把它挂到记录类文档上当依据——"旧称已退役,只写现行称(ADR-002)"这种写法是**错的**:ADR 是**记录**、明说了不与现状同步,拿它当依据 ＝ 让现状陈述挂在一份预期会过期的文档上(它被推翻时不会自我更新)。
- 引用前先分清对方是**记录**(决策型:预期它不与现状一致,"不符"不是病、别去修)还是**待办**(方向型:引用即承诺,过期即失效,见 E-2)。
- **历史只作方向,不作事实:** 读 ADR / reviews 是为了理由、被拒方案、方向;不要拿它们回答"现在是什么"。
- **[为什么] 的论述被推翻时,直接改写或删除**:不标"已被推翻"、不留原文、不附编号——读者只该看到仍然成立的理由。原话在 git 里(ADR 退役后亦然);判断"与旧决策是否冲突"看当下的活文档,不看历史。
  > `⚠` **只表示"注意"**(危险实现清单里的强调),**不表示"已被推翻"**——看到它不要去找旧论述,没有旧论述。
- 修改 [是什么] 时顺手检查同文件 [为什么]:两者矛盾 = 有人只更新了一半,当场修掉。

## E-2: 方向型(未来)——意向不搬家就悬置

- 三段式内容实际混合了不同**性质**的陈述(见上表四类),腐烂方式各异:**描述型**说现状(真相源 = 代码,会变假)、**决策型**(真相源 = 历史,内容只增不改、存在有寿命,被取代标 `superseded`、前提**有证据地**消失标 `expired`)、**方向型**说意向("计划做 X""需要跟进"),真相源 = 承诺,**不会变假,只会悬置**——没人知道它是 planned、已做完还是已放弃。

方向型最容易混进 [是什么] 伪装成事实。治理:

- **集中安置**:方向型陈述住在**未来桶**(L1「开放问题」/ 项目计划文件,含 L3「实现方向」/ ROADMAP / task_plan);**ADR「需要跟进的」段是历史记录,不是未来桶的唯一正文归属**——要跟进时在项目计划登记并回指 ADR。状态只在有数的地方维护;散落在事实段里的方向性内容就地清除。
- **状态流转**:planned → doing → done / dropped。**done 移出**:完成的方向不再留在活跃清单(历史在 git);"带理由的 dropped"往往应升格为决策型("不做 X"是约束,走 ADR)。
- **未来最小约定:** 状态 / 拍板人 / 结案条件。未来不配检查器——只在 audit / 复核里看这三条;方向型陈述不混入 `[是什么]`。
- 方向性陈述在 [是什么] 里裸留(无状态、无集中安置)= 过时旧陈述的另一种形态,对账(E-5)时同样清。**未收敛也不例外**:概述写「方向未定」这个事实,方向住「开放问题」。

## E-3: 约束型(当下)——推翻不变量 = 必须走 ADR + 修订原文

- 不变量是一次性对话产物,会随功能演化过时。**任何一次改动若与现有不变量冲突,必须从三条出路里选一条并执行**:修订 L1/L2 里的不变量原文、给不变量加例外说明、或放弃该改动。**禁止**只改代码不动文档——那是不变量失效的开端。
- 推翻重大不变量的改动(如"标识符必须 ASCII"→ 允许 Unicode)必须升格为 ADR,哪怕当时觉得"顺手改的"。
- 新理由落进当下正文后,ADR 只是过程载体:按 E-4「记录寿命」升格或退役——**不要让 ADR 变成新不变量的第二处出处**。
- 判据:**当你会说"这条不变量过时了"时,就是 ADR 触发点。**
- **一条不变量跨多层成立时,只有一处是"正文定义"**——通常放在它**最常被违反的那一层**(项目级 → L1,架构级 → L2,模块级 → L3,核心级(函数 / 表示 / 协议) → 承载它的 N2 单元节:L2 的「N2 单元规格」或模块 L3);别处**不写**(不写摘要、不重述;按代号引用可以)。**L4 不承载不变量正文**——它是阅读视图。跨层写两份必然出现两个版本,正是 E-1 警告的漂移。这也适用于 `[不变量]` 与"危险实现清单"。**编号约定:** 不变量用稳定编号(`I-1`、`I-2`…),开放问题用 `Q-1`…——编号既供**复核 delta 扫描与拍板引用**,也是**跨文档引用的唯一合法手柄**;引用处**不复述内容**,退役编号**不复用**。
- **不变量引用了未拍板的术语 = 这条不变量本身未定**:当场标 `本条未定:取 <X> 读;若 Q-N 拍板为 <Y>,本条须改写`,并确保 Q-N 登记在「开放问题」里。别让一条不可判定的约束混过去——验证者会按"不变量未定"判需人拍板。
- 联动义务(在记录里标 `superseded` 只算 50%——记录状态不改变当前真相):① 把 L1/L2/L3 里与旧决策绑定的段落**改写或删除**(不标"已被推翻",不留原文,不附编号);② 修订相关不变量;③ 在新 ADR 的"后果"段记下这两步是否完成。

## E-4: 决策型(历史)——ADR 触发粒度(用"惊讶度"判断,不用"规模"判断)

- **必记**:改完之后让后来者"惊讶"的决策(为什么不用 X?为什么这么绕?)——惊讶就是被拒方案没被记录的症状
- **必记**:推翻先前决策 / 引入第二套并行机制 / 改变数据模型身份语义
- **必记**:养出"两套并存物"的决策(两个同名函数、两种标识符规则、两条数据通路)——并存物必须有 ADR 解释区别,否则下一个人会删错一个
- **不记**:单纯的新功能、bug 修复、重构(代码即真相)
- **同一决策的「补充」vs「推翻」**(判据,不是规模):改的是**参数 / 实现方式 / 边界**、被选方案不变 → 在原 ADR 末尾追加带日期的补充(append-only,状态 `accepted(修订)`);改的是**被选方案本身**、或引入第二套并行机制 → 新 ADR，旧 ADR 只改 `status: superseded`，继任记录写 `supersedes: ADR-XXX`，旧记录按「记录寿命」升格 / 退役。补充只增不改——ADR 是**记录**,不是现状文档(见 E-1);最新状态看 frontmatter,最新补充按日期排在文末。
  > **历史只作方向,不作事实:** ADR 用来回答"为什么这么选 / 拒了什么 / 当时的方向";不要用它回答"现在是什么"。ADR 只在入口文档的活文档索引里出现一次,现状陈述必须自足。
  - **有歧义时优先补充:** 若同一子系统已有 ADR、且其补充段已连续承载该子系统的决策,优先追加补充;仅当被选方案本身翻转或引入并行机制时才新建 ADR。补充里写一句「为什么不是新 ADR」——两次冷启动实测在这一步会做出不同但都说得通的选择,写下来是为了让下一个人不用重新猜。

### 记录寿命(写完之后怎么办)

> ADR 是**决策过程**的载体,不是长期档案。稳态目标量 = 0;目录里留的是"还在议 / 还在执行链上 / 理由尚未升格"的记录。

- **先在入口分流,不要什么都写成 ADR:** 可逆 / 局部 / 一次性 → commit body(为什么 + 拒了什么,两行);需评审 / 跨模块 → PR / RFC;不可逆 / 跨模块长期约束 → ADR。**载体选错 = 用最贵的容器装最短命的内容。**
- **三问决定去留**(年龄不是判据,只是审计触发器):
  1. 它现在还挡着哪个**具体**的错误改动?(答不出 ≠ 退役;只说明需要作者判断)
  2. 未来还会有人重新提这个方案吗?(答不出 ≠ 退役)
  3. 现状文档读得出这个理由吗?(读得出 → 可直接退役)
- **退役要有正面证据**,三选一:
  - 理由已升格进当下正文(③ 是);
  - 前提可证伪地消失(依赖移除 / 代码路径删除 / 外部约束失效),并写明证据;
  - 作者拍板退役。
  **"答不出"不是证据**——只登记为**退役候选**(不改 `status`)、进当次对账的待拍板清单,交作者;不自动退役。
- **升格**(① 是、③ 否):把仍成立的理由写进当下的 `[为什么]` / 不变量 / 危险实现清单;写不进任何一段 = 它其实不约束当下,按上一条判退役。升格后本文件退役。
- **退役**:文件移出工作区;字节留在 git(用 `git log -- docs/decisions/` / `git show` 取回)。**不是换目录**:`archive/` 挡不住 `rg` / `git grep`(见 `search-surface.md`)。**每次退役在对账记录里留一行处置证据**(升格到哪 / 前提消失的证据 / 作者拍板)——退役不是静默删除。
- **`superseded` vs `expired`**:被新决定替代 → `superseded`(继任记录写 `supersedes`);前提**有证据地**消失、没有继任决定 → `expired`。两者都退役;`expired` 不是"退役候选"。
- **关系字段跟着继任记录走**:退役记录不再要求可解析的反向链接;继任记录的 `supersedes` 是唯一保留的链。
- **非 git 项目不退役**:确认前提消失后标 `expired` 留在原处(读时按 `status` 跳过),靠 `docs/.ignore` 退出检索面;没有恢复手段。
- **存量归档的迁移**:已有 `archive/` 的项目不强制一次清空;按 E-5 对账逐条判(升格 / 退役),退役前把关系搬到继任记录的 `supersedes`。
- **一次审计只做一遍**:每次 E-5 集中式对账末尾跑一次;不要逐 commit 检查。**复核(teach-back)不是退役判据**——它判文档写没写清,不判记录还值不值得留。

## E-5: 对账——跨时间的一致性审计

**对账 = 把文档与代码 / 记录 / 状态逐条摊开比对,列差异与缺口;不是会计对账,也不是只在事后做。**

- **主战场在改代码前**:文档是实现的契约;本节的"触发式 / 集中式"对账是版本级兜底,不是替代事前复核(见 `review-panel.md`)。
- **四类对账:** ① **当下 vs 代码**(描述型事实、主流程、`[已定]`);② **历史 vs 当下引用**(现状文档里有没有指向记录的引用——依据、出处行、编号都算);③ **未来 vs 状态**(方向项是否有状态 / 拍板人 / 结案条件);④ **历史 vs 约束**(逐条问 E-4 三问:还挡着哪个错误改动 / 会否复发 / 现状能否读出 → 升格或退役)。

- **触发式**:每次版本级变更(按项目自己的版本命名,如 vXXX)合并前,对照检查本次改动触碰的模块,其 L1/L2/L3 文档、不变量、危险实现清单、**`[已定]` 项是否被改动(改了必须有 ADR)**、以及外部 AI 接口文档(如有;指本项目对外提供给 AI 消费的接口描述 / 契约的现状快照)是否需要同步。外部接口文档失真代价最高。
- **集中式**:每隔几个版本做一次**全量文档对账**:通读 L1 记忆文件 + `docs/architecture.md`,凡与代码现状不符的陈述当场修正;发现"文档说有但代码没有 / 代码有但文档说没有"的,修文档并记下当初漏更新原因。
- **先验真假再改**:对账里出现的"文档自相矛盾",先拿数据(对拍 / 脚本)判谁错再动刀——**别默认"文档写得晚所以文档对"**;实践里常见的是**文档错、代码对**(那就改文档,不改代码),也见过**两边都不对**(规格本身没想清)。
- **产出落档**:每次对账(含 teach-back 与全量文档对账)写一份到 `docs/reviews/YYYY-MM-DD-<主题>.md`;并改文档本身;若漂移暴露流程问题,把对策写进 L1 记忆文件。
- **保留与退役:**
  - 每次**全量对账**完成后,上一批 `docs/reviews/` 整体退役(移出工作区;git 保留);本批留到下一次全量对账。`.last-review` 是**游标**(SHA + 日期),不是历史,永不退役。
  - **退役前检查:** 本批 reviews 里未闭合的 finding 必须已经(改文档 / 进开放问题 / 有 ADR);有未闭合项 → 不许整批退役,先处置。
  - ADR 按 E-4「记录寿命」处理;全量对账是唯一的批量退役点。**退役候选(答不出三问)只登记,交作者拍板**;每批退役在对账记录里留一行清单(哪些 ADR / reviews、依据哪条证据)。
  - reviews **不做摘要 / 索引**:唯一的"压缩产物"是写进 L1 的流程修正那一条。
  - 非 git 项目只标 `expired`,不退役。

## E-6: 代码注释与文档的分工

- **代码注释不写版本变更史**(如"v0.13 从 io.js 迁入")——那是 git log(以及决策当时的 ADR)的职责,双轨记录必然漂移。文件头注释只写:该文件的角色定位 + 读者必须先知道的契约。
- **可逆 / 局部的决策**写 commit body(为什么 + 被拒方案,两行),不升级成 ADR;ADR 只给不可逆 / 跨模块 / 需评审的决策(见 E-4「记录寿命」)。
- 判断标准:注释内容若能在 git log 或 `docs/decisions/` 里找到,就不要写在代码里;注释里只留"读这段代码前必须知道的坑"。

## E-7: 术语表是新词的唯一登记处

- 出现**新领域概念** → 当场定义:跨模块的登记进 `docs/glossary.md`,只在一个模块里用的写在该模块的术语小节;再在别处使用。
- 文档里出现**未登记的名词** = 漂移信号:要么补登记,要么改用已登记词。
  > 本条只指**领域词**;代码标识符 / 数据字段名是实现量,不登记,也不在退役范围(见下条)。
- 术语**含义变化** → 视为可能的不变量变更,走 E-3。
- 一个词只在一处定义(单一事实来源);别处只引用,不重述——重述必然产生第二个定义,迟早打架。
- **找不到词先报作者**:要表达一个概念却没有现成词时,先报出(概念 + 拟词 + 拟定义),作者同意后再登记使用;**未获批前不自造词**——自造词必与既有词打架。
- **术语退役 / 改名**:宣布全库退役前**必须 grep 实测**(范围 = `docs/` 全部 + 相关页面 / 脚本的中文叙述),**命中不为 0 不得宣布完成**。退役的两类豁免**逐条记进 ADR**:① 历史原话(在 ADR / 对账记录里作**证据**引用);② 被要求保持原样的件(逐条记明是哪个文件)。**代码标识符与数据字段名不在退役范围**——它们是实现量,不是领域词。
