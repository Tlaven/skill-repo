# M1 建立

> 本模块只做一件事：把系统搭起来（或重建），然后交给 M2。
> 读的时机：开项 / 重建 / 2B–2D 补差。
> 投放清单与权威副本见 `deployment.md`；层 / 深度、验收、复核不在本模块。

## 一、先判起点

| 代号 | 名字 | 判据 | 核心动作 | 最小产出 |
| --- | --- | --- | --- | --- |
| **2A** | 全新 | 无 L1 + 基本空目录（除 `.git` / skill 模板外，没有作者手写文件） | 建骨架，用到哪份建哪份 | L1 + methodology + `task_plan.md` + 脚本状态 |
| **2B** | 合并 | 有 L1 + 想引入这套做法 | 补目录 + 缺的层，不动原文 | methodology + L1 一行目录 |
| **2C** | 嫁接 | 无 L1 + 有作者手写文件（README / 设计 / docs，哪怕一份） | 通读既有文档 → 对应范围 → 落 L1 | L1（标来源）+ methodology |
| **2D** | 补差 | 有 L1 + 已按这套做法跑着 | 核对 → 只补无争议缺口 | 缺口清单 + 补缺 |
| **2R** | 精简 / 重建 | 文档过多（>10 份 / 总量 > 代码 / 同一件事多处写法 / 用户说「看不懂 / 干扰 / 想变少」） | 清点 → 挑 → 归档 → 改目录 → 去时间 | 3–6 份活文档 + 归档 + before/after |

**2R 不是第五种起点**：它是症状，可叠在任何已有文档的起点上。

判不出时问用户，不猜。

## 二、共同前提

1. **人已给出功能和可验收行为**；人定的标 `[已定]`，AI 不改。连功能和验收都由 AI 起草 → 这套做法不适用。
2. **是不是 git？** 不是：补差和 SHA 都用不了，退化成人工清单。
3. **按 `deployment.md` 投核心脚本**；用户不接，就在 L1 标 `scripts: 未接入`，后续命令按「未复跑」处理。**所有起点都要投**，不只 2A。
4. **布局跟着项目走**：已有 `docs/templates/` 就跟随，不强行改成 `docs-templates/`；要统一 → 决策记录 + 用户定。项目自定义模板目录同步进检查脚本的 `DOC_EXCLUDE` / `DEFAULT_EXCLUDE`。

## 三、各起点动作

### 2A — 全新：用到哪份建哪份

1. **默认只建 L1 + methodology + `task_plan.md`**；`docs/.live` 等第一份当前维护的文档出现时再建；`docs/` 里当前维护的文档**不预建**。
2. **按话题建文档**：主流程 / 架构边界 → L2；模块机制 → L3；跨模块词 → glossary；决策 → ADR；跨模块 N2 → L2 的「N2 单元规格」节；模块内 N2 → 模块 L3。没有这个话题就不建，不铺模板。
3. **落地顺序**：L1 模板 → methodology → `task_plan.md` → `.live` → `.ignore` → 核心脚本 → 进 M2。投完 methodology 后，把 L1 索引行的路径填成**实际投放位置**（默认 `docs-templates/methodology.md`），别留占位或二选一。
4. **L1 文件名**按 `templates/l1-memory.md` 顶部对照表；判不出问用户，别硬默认 `AGENTS.md`。同时用几个工具：选一个主文件，其余只写一行指向主文件。
5. 收尾（Step 4）只 2A 做；2B / 2C / 2D / 2R 不动作者内容。

### 2B — 合并：已有 L1

1. 读现有 L1，**不要把方法论插进去**。
2. 按项目现有布局把 methodology 放到位，L1 只加**一行目录条目**；路径填项目里的实际位置。
3. **不动用户原有内容**——唯一例外：把旧 L1 里的方法论正文移到方法论文件。
4. 看到散落的不变量，提示归并，但**让用户决定**。
5. `docs/` 按需创建（先问）；从「补缺」开始。
6. **合并后核对**：methodology 在位 + L1 只有目录条目；硬规则 / 加载表 / 完成判据 / E-1–E-7 不再常驻 L1。

### 2C — 嫁接：已有文档、缺 L1

1. **只要存在作者手写的 README / 设计文档 / docs，就不算空目录**，走 2C。
2. 通读既有文档，对应到范围：
   - 现状事实 → L2 事实源（新 `architecture.md` 只写决策 + 不变量，不搬既有正文）；
   - 设计动机 / 不变量 / 验收 → 按性质归到对应层；
   - 存档 / 旧方案 → 归档区（不是第 5 层；不迁、不删，标清边界，核对时排除）。
3. 落 L1 + methodology；其余文档按话题出现再建。L1 索引行的路径填实际投放位置。
4. 填 L1 时标清「内容从哪来」：证据标来源；猜不到 → 开放问题，别硬填。
5. **冲突时只在新文件顶部加一行「以哪份为准」**，不动作者原有文件；定性冲突记开放问题，交作者定。
6. 从「补既有文档缺的那部分」开始；`architecture.md` 可先当证据草稿（标 `推断，待确认`）。
7. **同名冲突**：既有事实源已占 `docs/architecture.md` → 新文件另起名（如 `architecture-l2.md`），顶部写明以哪份为准，并同步 `deployment.md` / 检查脚本的排除表。

### 2D — 补差：项目已经按这套做法跑着

1. **不要重造、不要重写、不要升级版本。** 动作 = 补缺 + 核对。
2. 先核对：通读 L1 + `docs/.live` + `docs/`，列「这套做法要求 vs 项目现状」的缺口，标哪些要用户定。
3. 只补没有争议的缺口（死链、缺的参考件）；**不改已成文的措辞**。
4. 不擅自升级版本（那是用户的决定）。
5. **默认不新增当前维护的文档**；要新增先列提问清单。
6. 收尾只汇报「补了哪些缺口 / 还差什么没定」。

### 2R — 精简 / 重建

**门槛：**

- 作者点头；
- 作者手写的文档**不删，只归档**；AI 生成的历史记录可以移出工作区（git 里还有）；
- **先提交现状**（或建分支 / `git stash`），保证能退回去；
- **非 git 项目**：没有回退手段，先把现状快照到项目外（或 `docs/archive/` 下的独立快照目录）再动；不能承诺可退回。

**动作：**

1. **清点**：列 `docs/` + 根文件；每份标 `作者写 / AI 写 / 记录`。作者写的改动要确认；AI 写的历史记录可以直接移出，AI 写的其他文档可以归档。
2. **挑要留的**：按加载频率挑 3–6 份。每次都要：L1 / `task_plan` / 当前在做的模块手册 / 设计约束；按任务才用：架构一页 / 2–3 个模块 / 词表。写进 `docs/.live`。
3. **归档**：其余移到 `docs/archive/`（文件名保留日期）或 `docs/experiment/`（脚手架 / 实验日志）；**不删**。AI 生成的历史记录改为移出工作区；上一轮的 reviews 等整轮核对做完再成批移走。
4. **改目录**：L1 只列当前维护的文档；历史记录不进当前文档正文，只在目录里以目录级出现一次；当前维护的文档不拿决策记录 / reviews 当依据；`docs/experiment/scaffolds/` 从入口删掉。
5. **去时间 / 版本**：当前维护的文档里的日期 / 文档版本号删掉或移进归档；只留顶部 `Last verified: <SHA>`；领域版本保留。
6. **数 before / after**：文件数 / 行数 / 字节 / 日期数 / 一致性检查警告；跑项目验收，证明只动了文档。
7. **留个记录**：一条复核记录或笔记记结论；两周后再数一次，涨 >20% 说明生成器没改完。

## 四、最小骨架

四项，缺一项都不算建立完成：

1. **L1 记忆文件在**；
2. **methodology 在**（项目里是 `docs-templates/methodology.md`，不随 L1 自动加载）；
3. **`task_plan.md` 在**（任务笔记 + 未来的项目计划；不是事实源）；
4. **脚本**：已按 `deployment.md` 投，或已标「未接入」。

另加：`docs/.live`（第一份当前文档出现时）、`docs/.ignore`（至少含 `decisions/` / `reviews/` / `archive/` / `experiment/`）。

## 五、建立出口

四项齐备，或缺口有明确标记；另加：

- 待定清单在；
- 脚本状态已知（已投 / 未接入）；
- 第一份当前文档出现时，`.live` 已写；
- 可进入 M2。

**执行面**：没有脚本数骨架四项；缺项必须显式标「未接入 / 待定」。

## 六、首轮收尾（仅 2A）

第一轮交付后清理一遍：

1. **找矛盾**；
2. **只留必需的**；
3. **其余分组到按需加载的文件**；
4. **写进目录**：由上层写，只写「哪份文档管什么」，不写条款摘要，也不写「见 X §Y」；
5. **标出能删的**：冗余 / 太泛 / 显而易见的，全删。

**生成 ≠ 完成。**
