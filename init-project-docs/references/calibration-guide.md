# Verify prompt 校准手册（skill 维护者用）

> 本文件是 `teach-back-verifier-prompt.md` 的校准物料：**prompt 本体**随项目落地到 `docs-templates/`，本手册**只留在 skill 侧、不随项目落地**。
> 改"判定相关措辞"或换模型后，按下面的基线重跑；校准记录见 `.calibration/README.md`（本地留存、不入库）。

## 校准对照（首次上线前拿它当基线测）

- 喂一份**故意留洞**的文档 → 判**不通过**（缺口标 `[阻断]` + 原文逐字引用），且点到那处。
- 喂一份**完整**的文档 → 判**通过**，并给出它是怎么验证的（*完整* 的严格含义见下节——漏一条失败分支就不算完整）。
- 喂一份**行为明确、只是有点糙**的文档 → 也应判**通过**，缺口只作 `[非阻断]` 建议。
- 喂一份**其余完全达标、只带 ≥1 条「决策级开放问题」**的文档（目标 / 范围 / 不变量未定）→ 判**需人拍板**，**不是「通过」**、也不是「文档缺陷」；只列下次动手就会撞上的项。
- 喂一份**只带非决策级开放项**（如“工具是否接 CI”）的、其余达标的文档 → 判**通过**。
- 喂一份**「精确例子」算错**（其余达标）的文档 → 判**不通过**，且必须指出算错的那一步（验证者复算义务）。
- 喂一份**含隐性洞**（未声明的洞）的决策级文档 → 判**不通过**，且必须命中「判定范围」里决策级的显式条件（如"被当既定物引用、却无名 / 无路径的领域词"）。
- 喂一份**系统性错误但内部自洽**的文档（断言在现实中不成立、但**文本内不可证伪**——没有任何可推导的内部矛盾；例子与危险实现清单、验收齐备）→ 判**通过**（自洽层），**且不得把该断言写成"已验证 / 正确"**——真伪不在验证者判定范围内（**边界句在 prompt 的「范围（判定边界）」段**；该夹具**待构造**——2026-10-18 两次尝试均因夹具自身缺口未成立，构造要点见 skill 侧 `.calibration/README`）。

## 基线怎么造 + 稳定性怎么算（实测结论）

- **"完整"基线必须无歧义地完整**：漏一条失败分支（最高频的是"重试耗尽后抛什么"）就会让判定在**通过 / 不通过**之间跨实例翻转——那时你测到的是自己文档模糊，不是 prompt 不稳。
- **"需人拍板"基线请用 L1 / L2（决策级）文档构造**。拿 L3 实现级文档去测这条路线，它会同时命中实现级问题而判成「不通过」——实测出现过 **2:1 分裂**（2 次「需人拍板」/ 1 次「不通过」）。
- **边界文档不能当基线**：文档内部存在"这条算不算阻断"的争议点时，判定本来就会摇摆。基线要选**两端都无争议**的文档。
- **稳定性只比 `OVERALL` 是否一致，不比阻断条数**：同一份缺陷文档实测阻断数在 **4~5** 之间浮动，而 `OVERALL` 三次一致。要求阻断条数一致会永远达不到。
- **判定范围与基线必须配对**：L1 / L2 → 决策级；L3 / N2 → 实现级（**N2 盖过层**：N2 单元无论在 L3、core-code 还是 L2 公共节，都按实现级）。混用 = 验证者用错达标线，测出来的不是稳定性。
- 上表全部基线与本节五条方法约定，合起来就是"prompt 措辞变更后必须重跑"的最小集合（每条 ≥3 次）；结果落档到 `.calibration/README.md`。**触发面只认可能影响判定行为的措辞**（判定条件 / 输出语义 / 边界）与换模型；纯元句（如"何时用"）与编辑性改动不触发。

**稳定性要求（关键）：** 每条基线都要**独立跑 ≥3 次**、判定必须一致——
只跑一次会被验证者的实例方差骗过（同一份文档曾跑出 2 通过 / 2 不通过）。
上表**全部基线**都对、且每条多次都稳定，这个 prompt 才算合格：太松（发现不了洞＝没用）、
太紧（误伤＝没人用）、**太不稳（同一文档抛硬币）** 都不行。

> **模型版本耦合:** 校准结论 = prompt 措辞 × 当次模型 的联合属性——V4 的稳定是"这对组合"稳定。
> 换模型 / 模型升级后**不自动继承**:上表**全部基线** × ≥3 次必须重跑,校准记录见 `.calibration/README.md`(「校准记录」节;本地留存、不入库)。
