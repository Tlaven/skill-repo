# 当下层的多镜复核(review panel)

> **主战场在改代码前**:文档是实现的契约;`check-docs-sync` 在 commit 时只是事后漂移提醒,不能替代事前复核。
>
> 本文件是 skill 的「多镜复核」协议;skill 的 SKILL.md 只留入口。

## 一、镜头

| 镜头 | 问什么 | 输入 | 输出 | 默认触发 |
|---|---|---|---|---|
| **自洽镜** | 陈述的时态 / 类别对不对;同一事实是否多处定义;不变量是否多处成文;跨层引用是否只留指针;三段之间是否矛盾 | L1 / L2 / L3 + glossary | 缺口 + 判定 | 契约级变更(四信号) |
| **去模糊镜** | 每个模糊词 / 主观要求是否可判定:两个互斥解释、可测代理指标、或已定义术语 | 文档 + `verifying-nonfunctional.md` | 词句 + 改写建议 | 契约级变更(四信号) |
| **术语镜** | 一个词一个定义;同物异名、一词多义、废弃别名、未登记新词;含义变化是否触发不变量变更 | 文档 + glossary | 术语清单 + 建议 | 术语定义变更(四信号) |
| **代码对标镜** | 路径 / 符号 / CLI flag / 配置键 / 主流程 / 不变量 / `[已定]` 是否与代码一致;当前基线是否准确 | 文档 + 代码 + 内联引用脚本 | 可核对断言清单 + 差异 | 改代码前(基线);批次 |
| **N2 可实现镜**(N2 变更时必跑,不参与默认四镜) | 步骤级 / 危险实现清单 / 例子 / 可跑验收 / 失败语义 | N2 单元 | 缺口 | N2 变更 |
| **可读性镜**(可选) | 主流程长度、示例、结构、是否抄实现 | 文档 | 警告 + 建议 | 里程碑 |

## 二、边界(否则四镜会重复报同一条)

- **自洽镜**管"有没有互相打架 / 放错时间桶";不管词本身定义得对不对,也不管句子能不能判定。
- **去模糊镜**管"这句话能不能判对错";不管词的身份与别名。
- **术语镜**管"词的身份";不管句子是否可判定。
- **代码对标镜**管"事实真假";不管文档内部是否自洽。
- **时态 / 类别检查并入自洽镜**,不单独开镜:计划有没有写成事实、旧决策有没有当现状、方向草案有没有混进 `[是什么]`。**唯一例外:** 未收敛时 L1 概述的「方向草案」双段允许出现在 `[是什么]` 位置;其中**只有方向半段的每行**必须带状态并显式标注方向草案,**现状半段保持事实、不带方向状态**;收敛后移出;其它情况视为缺陷。

## 三、触发

**契约文件** = L1 记忆文件 / `docs/architecture.md`(或项目实际 L2 名,如 `architecture-l2.md`)/ `docs/modules/**` / `docs/core-code.md` / `docs/glossary.md`。**契约级变更** = 其中不变量、`[已定]`、接口 / 数据结构 / 失败码、术语定义、或契约级断言的增删改;纯措辞 / 链接 / 排版不算。

**唯一裁决:skill 侧 `SKILL.md` Step 3.5 的四信号决定“跑不跑”**(N2 / 改不变量 / 术语无可判定定义 / 跨层大改);**“跑哪几镜”按文件映射**:

- **契约级变更** → 全 panel(4 个必跑镜);非契约小改 → 按文件选镜或不跑。
- **可选镜**:只有**可读性镜**是可选——不进必跑集;不跑时由 lint 警告 + 作者自检兜底。**N2 镜在 N2 变更时必跑**;跳过它时仍必须跑 N2 验收(`run-n2-acceptance --run`),并在留档标「未复核」。
- **commit(轻)**:只跑 `check-docs-sync` + `check-code-refs`;不跑 panel。
- **里程碑 / 发布 / 大改(重)**:全 panel + 校准探针。
- **按文件选镜**:`glossary` → 术语 + 去模糊;`architecture` / `modules` → 自洽 + 代码对标;`core-code` / N2 → N2 + 代码对标;L1 → 自洽 + 术语。

> 每个 commit 都跑全 panel,成本会让人直接绕过它——这正是 skill 侧 `RESEARCH-BACKLOG.md` R-2 记录过的失败模式。

## 四、派发

- **每镜一个独立 subagent,互不可见**;看不到本会话历史。
- **基座 prompt**:`teach-back-verifier-prompt.md`(复述 / 缺口 / 判定;`[阻断]` / `[非阻断]` / `需人拍板`;词句类必须逐字引用)。
- **每镜只加一段 addendum**:该镜的检查项与输出差异;不复制基座。
- **代码对标镜需要只读代码访问**;其它镜只给文档 + glossary + 相关不变量。**这是基座 prompt「唯一输入」段的显式例外**——在该镜的 addendum 里写明"允许只读仓库代码",其它镜仍不许自己读仓库。
- **一个待验证单元 = 一份派发参数**;可以并行派多个镜,但每份判定互相独立。
- 通用 teach-back 管"能否据此做决策 / 实现";panel 管当下层的四个具体问题。两者可以同时跑,但不要合并判定。

## 五、反馈回路

1. **第 1 轮**:各镜独立产出;协调者合并、去重、按文件 / 断言归属。四个镜的重复发现算一条,不算四条。
2. **修复**:只改文档,不改提示词;每条阻断项要能指回具体段落。
3. **第 2 轮**:新验证者;先逐条复核上轮阻断项(附证据),再扫描受影响范围。**必须附上轮阻断清单**——不附 = 每轮全量重掷。
4. **校准**:每镜配一个已知缺陷探针;探针没红,这一镜的"没问题"不可采信。探针清单(详见 skill 侧 `references/calibration-guide.md`):自洽=同一事实两处矛盾;去模糊=`合理处理`无阈值;术语=同一词两处定义 / 未登记的同义词;代码对标=引用不存在的路径;N2=缺验收;可读性=大段无结构。**拿不到探针 → 留档标「未校准」,该镜判定降为参考。**
5. **退出**:无阻断 + 全扫无新发现;`需人拍板` 转作者,不循环改文档。
6. **留档**:`docs/reviews/YYYY-MM-DD-<主题>.md`;把覆盖到的提交写进 `docs/reviews/.last-review`。

## 六、输出格式

每镜按基座 prompt 输出"复述 / 缺口表 / 判定";协调者再产出一张合并表:

| 镜头 | 阻断 | 非阻断 | 需人拍板 | 覆盖范围 |
|---|---|---|---|---|
| 自洽 |  |  |  |  |
| 去模糊 |  |  |  |  |
| 术语 |  |  |  |  |
| 代码对标 |  |  |  |  |
| N2(变更时必跑)/ 可读性(可选) |  |  |  |  |

**结论只写三档**:通过 / 不通过(文档缺陷)/ 需人拍板。不要写"基本通过""差不多"。

## 七、镜头 addendum(派发时贴在基座 prompt 的「待验证文档」前)

- **自洽镜:** 只报"陈述放错时间桶(历史 / 当下 / 未来)/ 同一事实多处定义 / 不变量多处成文 / 跨层重述 / 三段互相矛盾";每条附原文与位置。不要报词义、不要报代码差异。
- **去模糊镜:** 只报"无法判定"的句子;每条给出**两个互斥解释**,或一个可测代理指标。不要报术语身份、不要报代码差异。
- **术语镜:** 只报"词的身份"问题——同物异名 / 一词多义 / 废弃别名 / 未登记新词 / 含义变化;附 glossary 对照。不要报句子可判定性。
- **代码对标镜:** 只报**可证伪断言**——路径 / 符号 / CLI flag / 配置键 / 主流程 / 不变量 / `[已定]`;若已拷入 `scripts/`,先跑 `check-code-refs.py`,再抽查主流程与不变量。不要报文档内部自洽。**输入例外:** 允许只读仓库代码(覆盖基座 prompt 的「唯一输入」段);不得修改文件。
- **N2 可实现镜(N2 变更时必跑):** 只报步骤级 / 危险清单 / 例子 / 验收 / 失败语义的缺口。
- **可读性镜(可选):** 只报结构 / 示例 / 主流程长度 / 实现抄写;明确写"这是建议,不是阻断"。

## 八、反模式

- **改完代码才跑 panel** → 事后对账冒充事前拦截。
- **每个 commit 跑全 panel** → 被绕过。
- **四镜重复报告同一条,不去重** → 作者分不清该改哪份。
- **没有校准探针就宣布"没问题"** → 不可采信。
- **把"通过"当成"断言为真"** → 通过只说明文档内部一致;事实另靠外部核实(试跑 / 来源)。
- **用 panel 代替作者拍板** → `需人拍板` 必须回到人。

## 九、dispatch packet(可直接复制)

> **基座 prompt = `teach-back-verifier-prompt.md`;不要复制基座全文。** dispatch 文件只写:文件清单 + 镜头 addendum + 校准探针 + 输入覆盖 + 输出差异。
>
> **输入覆盖:** 本次是**包审计**,基座 prompt 的「唯一输入」段由 dispatch 的文件清单覆盖;其余判定纪律(决策级 / 实现级、三档、逐字引用、上轮阻断)全部沿用。代码 / 资产镜可只读运行脚本与读代码;其它镜只读清单内文件。仍不许读会话记录 / notes / 其它 skill,不许改文件。

```
docs/reviews/<YYYY-MM-DD>-<主题>-panel/
  MANIFEST.md
  dispatch/
    lens-01-consistency.md
    lens-02-ambiguity.md
    lens-03-terminology.md
    lens-04-code-assets.md
    lens-05-implementability.md
  probes/                  # 可选:探针独立成文件
  outputs/
    lens-01.md ... lens-05.md
  merged.md
  recheck.md               # 第 2 轮:只列上轮阻断
```

**MANIFEST 最小字段:** 日期 / skill / commit / model / effort;文件清单(路径 + 行数或 sha256);镜头(名称 + 判定范围 + 输入例外);校准(每镜:探针 + 命中/未命中);输出路径。

**dispatch 文件模板:**

```markdown
# Lens: <name>

## 0. 先读
- `docs-templates/teach-back-verifier-prompt.md`(基座;项目内路径;skill 侧对应 `references/teach-back-verifier-prompt.md`)
- 本文件「addendum / 探针 / 文件清单 / 输入覆盖」

## 1. 任务
- 对象:init-project-docs skill 包(或指定项目)
- 判定范围:决策级 / 实现级(两者都标)
- 输入例外:代码镜可只读仓库 + 运行脚本;其它镜只读清单内文件

## 2. 镜头 addendum
<从 §七 复制对应镜头>

## 3. 校准探针
<3–5 行已知缺陷>
先报告命中 / 未命中;**未命中 = 本镜未校准,后续“没问题”不可采信**。

## 4. 文件清单
- ...

## 5. 输出
按基座 prompt 的「复述 / 缺口清单 / 判定」;额外加 `## 校准`。
```

**纪律:** 一镜一 dispatch,一单元一份派发参数;各镜互不可见;协调者只合并去重;第 2 轮新验证者附上轮阻断清单。派不出独立 agent 时:把待验证正文 + 派发参数封存到 `docs/reviews/<日期>-<主题>-package/`,配 `MANIFEST`(文件清单 + 校验值 + SHA);另写指针记录标「复核未执行」;细节见 skill 侧 `SKILL.md` 的 Step 3.5。不要自评充数。

> 上面的 `lens-05-implementability` 是 **skill 包审计**的实现级纸面走查;项目侧的「全 panel」只需 `lens-01..04`(N2 变更时加 N2 镜;可读性可选)。
