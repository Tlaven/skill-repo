# 对话地图(L1 三段式的问题清单)

> 给 agent 的**对话地图,不是问卷**——根据用户回答自然展开,不要机械地一条条问。
> 每答完一段就立即写入对应文档;对话产出按 `temporal-model.md` 的四类路由落盘。

## [是什么] 段——项目定位

- 这个项目要解决什么问题?(一句话能说清吗)
- 谁会用?用在什么场景?
- **不做什么**(明确边界同样重要,边界外写出来)
- 主要功能 / 模块的大致预想?

## [是什么] 段——术语(填 `docs/glossary.md`)

- 有没有**外人听不懂**的词?(行业黑话、自定义概念)
- 哪些词**最容易混**?(记下来当反例)
- 有没有**旧叫法**已废弃?(记下来当"禁用别名")
- 生成代码时必须知道**类型 / 结构**的词有哪些?

## [为什么] 段——设计哲学

- 为什么用这个技术栈 / 架构风格?(强约束还是偏好)
- 核心价值观 / 设计哲学,2-3 条?(例:统一模型优先于扩展、性能优先于优雅)
- 考虑过哪些替代方案?为什么拒绝?(被拒方案要记下"为什么不")

## [不变量] 段——硬约束

- 性能预算?(响应时间、吞吐、内存上限)
- 技术栈锁定?(必须用 / 必须不用什么)
- 可维护性底线?(测试覆盖、文档要求)
- 安全 / 合规约束?
- **最怕写成什么样?** 让对方列 3 种"看起来对、语义却错"的实现(例:重试没做幂等 / 时间按本地时区算 / 权限只查角色不查资源归属)——这就是**危险实现清单**,每条后面必须跟一句"由哪条不变量 / 验收挡住"
- **失败路径分别怎么表现?**(超时 / 部分成功 / 冲突并发 / 越权)——落到 `docs/modules/<name>.md` 的失败语义表,**别接受"合理处理错误"**

## 时间轴追问(贯穿各段)

- 这条是**过去的选择**(历史)、**现在的真相**(当下),还是**未来的意向**(未来)?
- 如果是未来:状态是什么?谁拍板?什么情况下移出?
- 如果是历史:读它是为了理由 / 被拒方案 / 方向,还是现状事实?
- 如果是当下:它和代码对得上吗?有没有第二处定义?
