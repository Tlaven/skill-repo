## R-1:N2 的「家」是否必须是 L3 / L4?(第一轮已跑,未结案)

- **观察:** 项目零 L2/L3/L4,N2 级逻辑(时间最优姿态控制、喷口混控、吸地倒挂)住在 **ADR 补充段 + 24KB 可执行 smoke 套件 + 代码契约注释**里;按现行路由(模块内 N2 → 先补 L3)它属于违规,但项目在两轮高密度迭代后仍可维护。
- **待答:** 满足哪些最小性质(被拒方案可查 / 验收可失败 / 不变量在代码旁可查)之后,L3 就不是必需品?还是它只是「欠债未爆」?
- **结案条件:** ① 下一个实践案例做对照(一个用 L3,一个用 ADR + 验收);或 ② 对 hoverster 做冷启动接手测试(新 agent 只凭现有文档改一个 N2 单元,看能否正确落点)。
- **若结案为「不需要 L3」:** 把「N2 的家」改成 bootstrap 时的**显式选择点**(写进 L1),而不是默认补 L3。

### 第一轮:冷启动接手(2026-10-19,n=1)

- **做法:** 从 hoverster HEAD(`9385e6e`)建隔离 worktree,派一个**看不到本会话**的 general subagent;只给仓库路径 + 一个 N2 改动任务(平时档翻转完成加低空高度门控),**不提本 skill / R-1**。子代理跑到 100 轮上限,收尾报告未产出,但产物完整。
- **结果:** 实现正确;`npm run smoke` 28 段全绿(新段 `[平时档·低空]` 门控开 222° / 对照 370°);`check-doc-refs -Strict` 与 `check-docs-sync` 退出码 0(我独立复跑)。
- **关键行为(回答 R-1):** 它**没有**把规则停放在「ADR + smoke + 代码注释」,而是新建了:
  - `adr-004-calm-flip-altitude-gate.md`(决策 + 4 个被拒方案);
  - `docs/modules/flight-assist.md`(项目第一个 L3:N2 步骤级 / 危险实现清单 / 精确例子 / 验收 / 失败语义);
  - `docs/reviews/...-未复核.md`(按 A3 的退化路径:未复核 + 指针 + 行数 / sha256 指纹)。
- **修正原假设:** 「N2 住在 ADR + smoke + 代码注释」在**热会话**成立,在**冷启动**不成立——冷启动需要一份实现级规则文档(L3);ADR 负责「为什么 / 被拒」,smoke 负责「可跑验收」,L3 负责「步骤与危险清单」,三者分工清楚。
- **关键混杂(必须记):** 项目 L1 本身就写着「模块内 N2 → 若还没有 L3,先补一份」。所以这轮验证的是「规则被读懂并执行」,**不是**「没有规则时 L3 仍必需」。要分离变量,需要下一轮对照。
- **A1 边界:** 它选择**新建 ADR-004**而不是给 ADR-003 追加补充,理由是改动改变了「翻转完成」的目标语义(高空行为也变了),不是纯参数修正——与 A1 判据一致,但边界仍靠判断。
- **A3:** 被直接使用(无可派子代理 → 写「未复核」指针,而不是自评冒充复核)。
- **成本 / 小漂移:** 100 turns / 120 tool calls / ~33M tokens;复核记录日期写成 2026-10-18(实际 10-19),像是沿用仓库最新条目日期。

### 第二轮:对照——去掉 L1 路由提示(2026-10-19,n=1)

- **设计:** 同一 HEAD(`9385e6e`)、同一任务、同一 prompt;唯一操纵 = 工作区 `AGENTS.md` 删掉「若还没有 L3,先照 module-doc 补一份」与「该不该开一份 L3」两处提示。
- **结果:** 仍新建 L3(`docs/modules/auto-layer.md`);smoke 27 段全绿,新增 3 段(低空 245° / 关掉对照 400° / 高空对照 400°);`check-doc-refs -Strict` 与 `check-docs-sync` exit 0(我独立复跑)。
- **操纵失败(关键):** ① `docs-templates/module-doc.md` 自己就写着「存量模块同样适用」;② 冷启动 agent **发现工作区 AGENTS.md 有未提交修改,并用 `git show HEAD:AGENTS.md` 找回了被删的两句**——它明确按 HEAD 版执行。→ 在 git 仓库里,「删掉一条规则」删不干净;历史也是文档面。
- **另一处分歧:** 它选择给 ADR-003 追加「补充 7」,而不是新建 ADR(第一轮选了新 ADR-004)。两者都能自圆其说:新 ADR 侧重「目标语义变了」;补充侧重「ADR-003 已是该子系统的唯一决策载体(补充 1–6),另起会分裂」。→ A1 的「补充 vs 新 ADR」边界需要 tie-breaker(已作为候选补进 E4:有歧义时优先补充)。
- **A3 再次验证:** 写了 `docs/reviews/2026-10-19-...-未复核.md`(日期正确),明示未复核 + 派发参数 + 薄弱点。
- **A4 再次验证(更强):** 两组内置 differential 对照 + 两次真实变异(只换目标不提刹车权限 → 400° 断言失败;门控不看高度 → 高空对照失败),并跑了 `node --check` 与 `npm run build`。
- **它报告的文档缺口:** 「离地高度」仓库里有三种口径(HUD / 相机 / 落地档);「总转角不超过一圈」若计到完全收住会恒真(它改成「翻转完成阶段」并写死口径);落地档是否该一起门控未定;`docs/architecture.md`(L2)不存在,跨模块 N2 无合法家。
- **成本:** 85 turns / 113 tool calls / ~31M tokens(未触顶,完整报告)。

### 阶段性结论(两轮后)

- 两轮冷启动都**自发使用 L3** 承载 N2 规则;「ADR + smoke + 代码注释」足以替代 L3 的假设在冷启动下没有证据支持。
- 但两轮都没能证明「没有 L3 会失败」——规则在模板 / git 历史里仍有备份。要真正结案,需要一个**没有 module-doc 模板提示、且历史不可回溯**的样本(全新项目或 squash 后的仓库),或接受「实践中 L3 就是默认家」,把研究问题改成「L3 的最小必需内容」。
- 两轮都主动写了:步骤级说明 / 危险实现清单 / 精确例子 / 可跑验收 / 失败语义——可作为 L3 的默认最小集候选。
- **下一步:** ① 若要干净分离变量 → 第三轮用无模板提示 + 无历史的样本;② 若接受现状 → R-1 可结案,转而研究 L3 最小集与 A1 tie-breaker 的稳定性。

## R-4:文档协议的「过写」失败模式(未结案)

- **观察:** Cellwork(第二个实践样本,2026-10-25)出现与 hoverster 相反的失败:不是漏写,而是过写。活文档 233 KB > 代码 196 KB;单模块 `theme.markdown` 701 行(Anthropic 对 always-loaded 文件的建议是 <200 行);同一份地形规格在 README / L2 / L3 / 术语表有四个副本;`TERRTEST` 项数 1491 与 1626 并存。两个清理轮次(10-17 `doc-trim`、10-18 `live-docs-declutter`)都只改文本、没改生成规则,两周后回到原样。
- **外部校准:** AGENTS.md 配置异味研究(arXiv:2606.15828)在 100 个仓库里给出 Context Bloat 42%、Skill Leakage 35%、Lint Leakage 62%、Conflicting Instructions 28 例(精度 57%);并给出 200 行 / 单 commit 的检测门槛。Anthropic 建议每份 CLAUDE.md <200 行;HumanLayer 建议 ~150–200 条指令、根文件 <60 行、"prefer pointers to copies"。
- **待答:** ① 预算该按"加载频率"还是按"文件类型"?② "自足是唯一正文的属性"能否在不制造死链的前提下替代"每层复述"?③ 副本 / 体量比能否成为完成判据的一部分而不变成形式主义?④ 记录(reviews)只写不读,索引是否足够,还是必须把结论强制并入唯一正文?
- **结案条件:** ① 在 Cellwork 上完成"单一归属 + 预算 + 指针"改造,三个月后量副本数与体量比;② 第三个项目复现"过写"或证明预算无效;③ 至少一次清理**改了生成器**(模板 / 规则 / 检查器)而非只改文本。
- **候选改动(已落一部分,待第三样本验证):** E1 补"自足是家的属性 / 依据≠出处";模块模板去掉"写被拒方案"与"禁引 ADR"的矛盾;术语表补"单模块词不下沉、二次使用才提升";「活文档引记录」已按 `> 出处：` 行豁免。若第三样本证明这些规则空转,回滚并把原因记到本文件。
