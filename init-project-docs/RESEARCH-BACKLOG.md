# 研究:什么不合适(方法论演化用)

> skill **维护者**的研究清单,不随项目落地。
> 只写两样:**结论**(什么不合适 / 该怎么改)与**为什么**。不记日期、不记轮次、不记提交链——过程在 git,证据在项目侧的对账记录。
> 未结案的条目必须能回答"怎么算结案";答不出的不进本文件。**单案例观察 ≠ 规则。**

## 一、已落:试过才知道不合适

- **把"不重述"实现成"必须指回"** —— 文档会变成指针堆,而且越守规矩指针越多。指针的读者问题应是"我该读哪份",不是"这句话凭什么";句子级指针只有两种结局:读者需要去别处(说明放置错了)或不需要(噪声)。
- **给指针发免检通行证** —— 写指针比写内容便宜,于是没人补内容。检查器曾对 `⚠` 行、`> 出处：` 行、整个"指针形文件"豁免,还把"验收见 docs/…"当计数凭证;激励一反向,规则就死了。
- **用"删掉一条规则"做对照实验** —— 删不干净:模板里有备份,git 历史也能被 `git show` 找回,冷启动 agent 会按 HEAD 版执行。**历史也是文档面。**
- **只改文本、不改生成器** —— 清理完两周回原样。要动就动模板 / 规则 / 检查器。
- **判据只防"欠写"** —— 过写同样失败:活文档体量超过代码、同一规格四个副本、同一计数两处并存。体量与副本数要进判据,否则"写全"永远比"写准"划算。
- **用"墓碑"保历史** —— `⚠️ 已被 X 推翻` + 保留原文,单调增长、无回收。决策是覆盖的:推翻就改写或删除,原话在记录里。
- **把记录当现状的依据** —— 现状陈述挂在预期会过期的文档上;它过期时不会自我更新。
- **单案例观察直接写进主流程** —— 只看一次就定规则,通常是在给样本的偶然性立规矩。
- **给同一个目录再写一份索引** —— 同目录 `ls` 就是名单,索引是第二处存储:手写的会漂,自动生成的只是把"一个会漂的副本"换成"一个要维护的生成器 + 测试 + 多处文档同步"(ADR 索引已按此删除)。状态会随时间变的记录,靠每份文件自带 `status` 与"退役即移出工作区"(归档目录挡不住检索);名字层交给目录。
- **把历史当档案** —— 记录默认不记;内容只增不改,但存在有寿命:仍约束 → 升格进当下正文;其余要有正面证据才退役,答不出只登记候选。过期记录不是零资产,是负资产(agent 会把检索到的旧理由当证据);`archive/` 只换路径,不改检索结果。**结案:** 已落 E-4「记录寿命」/ E-5「保留与退役」。

样本里验证过、可以直接当规则的做法:append-only 补充、跳过复核留痕、teach-back 白名单派发、冻结计数复算、记录类不扫现状检查器。细节在各规则文件里,这里只记"验证过"。

## 二、未决

- **N2 的家是否必须是 L3/L4** —— 两轮冷启动都自发建了 L3,但都没能证明"没有 L3 会失败"(规则在模板与 git 里仍有备份)。待答:满足哪几条最小性质(被拒方案可查 / 验收可失败 / 不变量在代码旁可查)之后,L3 不再是必需品?结案条件:一个没有模板提示、历史不可回溯的样本;或接受"L3 是默认家",改问"L3 的最小必需内容"。
- **teach-back 为什么总被跳过** —— 是成本,还是触发条件不够可判定?已先落"跳过要留痕"。结案条件:在 1–2 个真实项目里看"未复核"标记是否真出现、是否被作者消费。
- **多镜 panel 是否比单镜多抓到真问题** —— 待答:误报率与成本多少?"commit 轻量 / 批次完整"能否避免被绕过?结案条件:≥3 次 panel 记录命中 / 误报 / 成本,并与同批单镜对照;无净增益就降为单镜 + 脚本。
- **证据链的保留边界** —— 多团队 / 合规 / 对外承诺场景是否需要长期保留 ADR / reviews?待答:哪类证据的保留期由外部规定、哪类可以退役?结案条件:一个真实合规或跨团队样本;在此之前,项目级例外写进 L1(默认仍按本 skill 退役)。
- **预算与"过写"** —— 待答:预算按加载频率还是文件类型?副本 / 体量比能否成为完成判据而不变形式主义?结案条件:一个项目完成"单一归属 + 预算"改造后量副本数;或第三个项目复现过写 / 证明预算无效。
- **检查器的边界**(已知限制,短期不打算修) —— `term-demote` 按提及次数粗判,不是"当作规则使用";`duplicate-alias` 依赖术语表反引号,术语下沉后失效;改写式副本逃过机器检查;纯文本引用(`见对账记录 2026-01-01`)抓不到,加检测易误伤。结论:**机器只收字面,语义归复核。**

## 三、已弃

- **合并"三份方法论副本"** —— 问题不存在:那是多文件 `rg -c` 输出错位读出来的(有 0 命中的文件不输出行,按位置对齐就把 A 的计数安到了 B 头上)。实测只有"三时间轴"一条真重复,已按"概念归 protocol、维护律归 temporal-model"拆开。**教训:多文件比较必须带 `--with-filename` 或逐文件跑。**
- **放开检索面(`docs/.ignore`)来补偿删掉的指针** —— 删指针不需要放开检索面;放开只会把旧结论搜进现状。
- **为零散想法立 ADR** —— 从未立项的想法,在跟进段标 dropped + 理由就够。
- **给"现状文档引记录"加纯文本检测** —— 误伤大,收益小。

## 四、回灌约定

1. 实践观察先记这里,写清**结论 / 为什么 / 结案条件**;单案例只记账,不动主流程。
2. 结案时判断落点:文档方法论问题 → 本 skill;skill 设计问题 → `seeding-skills`。
3. 同一结论只在一处成文——这里记"什么不合适",规则条文归对应规则文件。
4. 过程历史交给 git。
