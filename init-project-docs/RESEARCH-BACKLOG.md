## R-1:N2 的「家」是否必须是 L3 / L4?(第一轮已跑,未结案)

- **观察:** 项目零 L2/L3/L4,N2 级逻辑(时间最优姿态控制、喷口混控、吸地倒挂)住在 **ADR 补充段 + 24KB 可执行 smoke 套件 + 代码契约注释**里;按现行路由(模块内 N2 → 先补 L3)它属于违规,但项目在两轮高密度迭代后仍可维护。
- **待答:** 满足哪些最小性质(被拒方案可查 / 验收可失败 / 不变量在代码旁可查)之后,L3 就不是必需品?还是它只是「欠债未爆」?
- **结案条件:** ① 下一个实践案例做对照(一个用 L3,一个用 ADR + 验收);或 ② 对 hoverster 做冷启动接手测试(新 agent 只凭现有文档改一个 N2 单元,看能否正确落点)。
- **若结案为「不需要 L3」:** 把「N2 的家」改成 bootstrap 时的**显式选择点**(写进 L1),而不是默认补 L3。

### 第一轮:冷启动接手(2026-10-19,n=1)

- **做法:** 从 hoverster HEAD(`9385e6e`)建隔离 worktree,派一个**看不到本会话**的 general subagent;只给仓库路径 + 一个 N2 改动任务(平时档翻转完成加低空高度门控),**不提本 skill / R-1**。子代理跑到 100 轮上限,收尾报告未产出,但产物完整。
- **结果:** 实现正确;`npm run smoke` 28 段全绿(新段 `[平时档·低空]` 门控开 222° / 对照 370°);`check-doc-refs -Strict` 与 `check-docs-sync` 退出码 0(我独立复跑)。
- **关键行为(回答 R-1):** 它**没有**把规则停放在「ADR + smoke + 代码注释」,而是新建了:
  - `adr-004-calm-flip-altitude-gate.md`(决策 + 4 个被拒方案);
  - `docs/modules/flight-assist.md`(项目第一个 L3:N2 步骤级 / 危险实现清单 / 精确例子 / 验收 / 失败语义);
  - `docs/reviews/...-未复核.md`(按 A3 的退化路径:未复核 + 指针 + 行数 / sha256 指纹)。
- **修正原假设:** 「N2 住在 ADR + smoke + 代码注释」在**热会话**成立,在**冷启动**不成立——冷启动需要一份实现级规则文档(L3);ADR 负责「为什么 / 被拒」,smoke 负责「可跑验收」,L3 负责「步骤与危险清单」,三者分工清楚。
- **关键混杂(必须记):** 项目 L1 本身就写着「模块内 N2 → 若还没有 L3,先补一份」。所以这轮验证的是「规则被读懂并执行」,**不是**「没有规则时 L3 仍必需」。要分离变量,需要下一轮对照。
- **A1 边界:** 它选择**新建 ADR-004**而不是给 ADR-003 追加补充,理由是改动改变了「翻转完成」的目标语义(高空行为也变了),不是纯参数修正——与 A1 判据一致,但边界仍靠判断。
- **A3:** 被直接使用(无可派子代理 → 写「未复核」指针,而不是自评冒充复核)。
- **成本 / 小漂移:** 100 turns / 120 tool calls / ~33M tokens;复核记录日期写成 2026-10-18(实际 10-19),像是沿用仓库最新条目日期。
- **下一步(结案条件修订):** ① 去掉 L1 路由规则的对照(看是否仍建 L3,还是塞回 ADR / 代码注释);或 ② 纯参数改动的对照(看是否过度建 L3)。两者取一即可结案。
