# Init Project Docs — 项目记忆做法

> 本文件只做入口：契约、引用/索引、五段主线、路由。规则正文在 `references/` 的模块里；模块边界见 `references/modules.md`。

## 0.1 契约

**产出**：项目根的 L1 记忆文件（`AGENTS.md` / `CLAUDE.md` / …，按宿主定）；`docs-templates/methodology.md`；`docs/` 里当前维护的文档（L2 / L3 / 术语 / 决策 / 复核记录）；`task_plan.md`；`docs/.live` / `.ignore`；`scripts/`（或标「未接入」）。L1 文件名按 `templates/l1-memory.md` 顶部对照表；判不出问用户，别硬默认 `AGENTS.md`。

**不适用**：人没有给出功能和可验收的行为；连功能和验收都由 AI 起草。

**作者边界**：

- 不替用户写内容；可以从代码 / 已有文档 / git 推断，但必须标「推断，待确认」+ 来源；禁止编造。
- 没证据时给方案，不给结论（只限「为什么 / 不变量 / 方向」）：≥2 个方案、各自标代价；未接受前留在开放问题，不悄悄转正。
- 人定的接口 / 数据结构 / 失败码 / 命名标 `[已定]`，等同不变量；AI 不得顺手优化。

**硬约束**：

- 每段对话产出立刻落盘；计划不写成事实。
- 一条规则只在一处成文；别处只写指针。
- L4（`docs/core-analysis.md`）不承载规格；建它先问作者。
- 「通过」只说明文档内部一致，不证明断言为真；标了「未接入 / 未复跑 / 未复核」的都不算通过。

## 0.2 引用与索引

- **索引**：上指下。只写「哪份文档管什么」；L1 列 L2 / L3，L2 列模块；模块不自列；记录目录只在总表出现一次。
- **引用**：下指上。只写稳定代号，不写小节 / 行号，不复述；目标必须在读者的默认加载集里。
- **代号**：一条一义；定义一次；不复用；前缀语义只在项目的代号表里登记一次（没有表就用 `I-` / `Q-` / `E-`）。
- **同侧引用**：**引用条款时**，skill 正文只指 `references/` 和 `templates/`，项目正文只指 `docs/` / `docs-templates/`；产出 / 产物描述、部署清单、dual-use 部署件除外（部署件用裸文件名）。两侧的对应关系只写在 `references/deployment.md` 的清单里。
- **同层互指**：模块 ↔ 模块允许，但只作例外；真成常态就把内容上移。
- **目录 vs 条款**：索引指文档，引用指条款；两者不混用。
- 轴名就地写：层 L1–L4、深度 N0–N2、起点 2A–2D（2R 是叠层）、演化 E-1–E-7；术语见 `references/glossary.md`。

## 0.3 五段主线

| 段 | 进入 | 产出 | 出口 |
| --- | --- | --- | --- |
| **建立** | 无骨架 / 重建 | 骨架四项 + 投放件 | 四项齐 + 待定清单 |
| **写入** | 骨架齐 | 三段落位 / L2 主流程 / L3 / 术语 / 决策 | 每段已落盘 |
| **复核** | 命中四信号 | `docs/reviews/` 记录 + `.last-review` | 结论留档，或标「未复核」 |
| **交付** | 本轮要交 | 交付清单 | 骨架 + 待定 + 复核结论 |
| **收尾** | 仅 2A | 精简后的活文档 | 五步清理完成 |

- **起点**：2A 全新 / 2B 合并 / 2C 嫁接 / 2D 补差；**2R 是叠层，不是第五种起点**。
- **复核四信号**：N2 / 不变量 / 用词未定义 / 跨层大改。四条都不占就跳过。
- **验收**：teach-back（独立复核）；「通过」或「要人定」都算验过；「不通过」先改文档，重跑时附上轮阻断清单。
- **交付**：第一轮按 L1 + 已出现的话题文档交付；「要人定」是正常终点，不是失败。
- **收尾只做 2A**；2B / 2C / 2D / 2R 不动作者内容。
