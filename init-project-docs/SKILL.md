# Init Project Docs — AI 协作时代项目文档初始化

## 定位

项目文档**骨架**的引导者。不是文档内容的作者——内容靠和用户对话涌现。

skill 提供三样东西:

1. **方法论框架**——让 agent 知道有这套思维方式(三段式 × 4 层)
2. **文件结构骨架**——项目应该有哪些文档文件、放哪里
3. **对话地图**——告诉 agent 该问什么,而不是替用户答

**关键边界:** 不要替用户写文档内容。具体的项目目标、设计哲学、模块清单、不变量——这些必须通过对话产生。skill 给的是空的骨架 + 引导提示。

---

## 核心理念

文档是人和 AI 的"共享内存"。写**决策需要的信息**,不写**实现需要的信息**。

- 人类 vibe coding 不读代码 → 文档是人类对项目的唯一心智模型
- AI 不会自动读全部代码 → 文档是 AI 加载项目上下文的入口
- 双方必须在同一份信息上对齐 → 文档是唯一共享协议

具体内容靠对话产生,因为对话本身就是确立文档内容的核心方法。**skill 不能跳过对话**。

---

## 何时使用

**适合:**
- 用户开始新项目(空目录或刚 git init)
- 用户明确说"写 CLAUDE.md"/"项目初始化"/"立项"/"init docs"
- 已有项目但没有 CLAUDE.md,用户想补
- **已有 CLAUDE.md 但用户想引入这套方法论**(走合并模式,见 Workflow Step 2B)
- 项目结构变了,需要重建文档骨架

**不适合:**
- 已有完整 CLAUDE.md 且用户没说要改(应看现有结构,不主动推销)
- 单次任务、一次性脚本(不需要长期文档)
- 用户没明确要求(避免主动推销方法论)

## 方法论速查

### 三段式(每层文档的内部结构)

```
[是什么]   事实:这一层的内容(模块清单 / 函数清单 / etc)
[为什么]   决策:考虑过的方案 + 选择 + 理由 + 被拒方案
[不变量]   约束:必须满足的条件(功能性 + 非功能性)
```

### 4 层(粒度递进,L4 默认不要)

| 层 | 文件 | 内容 | 何时写 |
|---|---|---|---|
| L1 整体定位 | `./CLAUDE.md` | 项目目标、设计哲学、不变量 | 项目立项时 |
| L2 架构层 | `docs/architecture.md` | 模块清单、模块关系、主流程叙述 | 架构设计时 |
| L3 模块详细 | `docs/modules/<name>.md` | 模块需求、实现方向、注意事项 | 每个模块开发前 |
| L4 核心代码 | (按需,默认不写) | 牵一发动全身的函数 + 不变量 | core 沉淀后,看项目复杂度 |

L4 默认不生成。只有用户明确说"这个项目有 core 代码"或问"要不要 L4"时才加。

## Workflow

### Step 1: 检查环境 + 决定模式

- 当前目录是否已有 `CLAUDE.md`?
  - **没有** → 走 **Step 2A 全新模式**
  - **有 + 用户想引入这套方法论** → 走 **Step 2B 合并模式**
  - **有 + 用户没说要改** → 不要主动推销,只回应具体问题
- 是否 git 仓库?是否基本空目录?(影响对话起点——空项目从零问,已有代码则让用户介绍)

### Step 2A: 全新模式——只创建 CLAUDE.md 一个文件

**关键:不要一次性把所有模板复制过去。** 那是反模式——agent 自然工作流是"对话→产出→写入",被强制"先建空骨架"会被绕过,文件最终空着。

只复制 `templates/claude.md` → `./CLAUDE.md`,然后立即进入 Step 3 对话。其他模板文件**按需在对应阶段创建**:
- 进入 L2 讨论 → 创建 `docs/architecture.md`
- 开发某模块前 → 复制 `templates/module-doc.md` 到 `docs/modules/<name>.md`
- 决策发生时 → 复制 `templates/adr-template.md` 到 `docs/decisions/adr-XXX-*.md`
- 用户明确要 L4 → 复制 `templates/core-code.md` 到 `docs/core-code.md`

### Step 2B: 合并模式——已有 CLAUDE.md

**核心原则:不破坏现有内容,只补方法论 + 缺失层。**

1. **读现有 CLAUDE.md**,识别已有段落(项目概述、命令、架构、约束等)
2. **插入"文档方法论"段**(从 `templates/claude.md` 的"文档方法论"章节复制),插在合适位置(通常是项目概述之后、架构之前)
3. **不动用户原有的项目概述等**——不要替换、不要重排
4. **检查现有内容里 [不变量] 信息**:很多项目把约束散落在 CLAUDE.md 各段,可以提示用户"把这些归并到 L1 [不变量] 段",但**让用户决定**,不主动改
5. **docs/ 目录按需创建**:先问用户是否要补 L2/L3/ADR 目录。同意才创建;不同意就先只加方法论段
6. 进入 Step 3 对话,但**起点是补缺**,不是从零问 L1(用户已有的内容跳过,只问还没说的)

### Step 3: 边对话边写入(核心步骤)

**铁律:每段对话产出立即写入对应文档段落,让用户看到进度。** 不要囤积——用户说完一段,马上 Edit 到 CLAUDE.md / architecture.md 的对应位置,然后继续下一段。

**第一阶段(填 L1 主轴):**
按"对话地图"的 [是什么] → [为什么] → [不变量] 顺序,每个段问 1-2 个核心问题。用户回答后,**立即**用 Edit 写入 CLAUDE.md 对应段落。

**第二阶段(填 L2 主流程):**
等用户对 L1 有基本共识后,**此时才创建** `docs/architecture.md`(从模板复制),重点产出**主流程叙述**(10-20 行,从入口到出口的关键路径)。

**第三阶段(按需,不在初建时一次性做完):**
- 模块开发前 → 创建该模块 L3
- 架构决策发生时 → 创建该条 ADR
- core 沉淀后 + 用户主动提 → 创建 L4

### Step 4: 收尾说明

初轮对话(L1 + L2 主流程)完成后,告诉用户后续机制:

```
文档方法论已落地。接下来:
- 开发新模块前,从 docs/templates/ 复制 module-doc.md 到 docs/modules/<name>.md,先填后写代码
- 重大决策发生时,在 docs/decisions/ 复制 adr-XXX-template.md 记一条
- 大改动前,先更新对应层文档,再写代码
- L4 默认不要——只有 core 代码"牵一发动全身"时才补

CLAUDE.md 已含方法论精要,后续 Claude 启动会自动加载,不需要再调用这个 skill。
```

## 对话地图(L1 三段式的问题清单)

这是给 agent 的对话地图,**不是问卷**——根据用户回答自然展开,不要机械地一条条问。

### [是什么] 段——问项目定位

- 这个项目要解决什么问题?(一句话能说清吗)
- 谁会用?用在什么场景?
- **不做什么**(明确边界同样重要,边界外写出来)
- 主要功能 / 模块的大致预想?

### [为什么] 段——问设计哲学

- 为什么用这个技术栈 / 架构风格?(强约束还是偏好)
- 核心价值观 / 设计哲学,2-3 条?(例:统一模型优先于扩展、性能优先于优雅、简单优先于通用)
- 考虑过哪些替代方案?为什么拒绝?(被拒方案是金矿)

### [不变量] 段——问硬约束

- 性能预算?(响应时间、吞吐、内存上限)
- 技术栈锁定?(必须用 / 必须不用什么)
- 可维护性底线?(测试覆盖、文档要求)
- 安全 / 合规约束?

---

## 铁律(写进 CLAUDE.md,贯穿项目生命周期)

1. **先文档,再代码**——大改动前先更新对应层文档,文档是设计的契约
2. **ADR 即时记录**——决策当下就写,事后补 90% 会丢
3. **被拒方案是金矿**——拒绝的方案要记"为什么不",一年后 AI 提同样方案时是唯一挡箭牌
4. **写决策需要的信息,不写实现需要的信息**——细节让 AI 现场读代码
5. **不变量优先级最高**——三段里"不变量"最不能省,它是 AI 改代码时的护栏

---

## 反模式(checklist)

skill 自身要避免的:

- ❌ **替用户填 L1 内容**(项目目标、设计哲学必须对话产生)
- ❌ **跳过对话直接生成"看起来完整"的文档**(空洞的内容比空骨架更糟)
- ❌ **一次性把所有模板复制到目标位置**(违反"边对话边生长"——空骨架会被遗忘,最终空着。只有 CLAUDE.md 在 Step 2A 立即建,其他按需)
- ❌ **在已有 CLAUDE.md 的项目静默覆盖**(走 Step 2B 合并模式,只补方法论段,不动用户原有内容)
- ❌ **一次问完所有问题**(应该分阶段,边讨论边记录)
- ❌ **囤积对话产出**(用户说一段就要立即 Edit 写入,不要等"问完所有再一起写")
- ❌ **主动生成 L4**(默认不要,用户问了才加)
- ❌ **把 skill 用于已有完善文档的项目**(那是别的需求,不是 init)

## 产出文件结构

```
./CLAUDE.md                           # 项目根,L1 主战场(全新模式 Step 2A 创建)
./docs/
  ├── architecture.md                 # L2 架构层(进入 L2 讨论时创建)
  ├── core-code.md                    # L4 核心代码(可选,用户主动要时才创建)
  ├── templates/
  │   └── module-doc.md               # L3 模板(放项目里方便复制,init 时复制)
  └── decisions/
      ├── README.md                   # ADR 索引(init 时复制)
      └── adr-000-template.md         # ADR 单条模板(init 时复制)
```

模板文件在 skill 目录的 `templates/` 下。**不要 init 时一次性全复制**——按 Workflow Step 2A 的节奏,CLAUDE.md 先建,其他随对话阶段按需创建。

---

## 模板文件清单

| 文件 | 用途 |
|---|---|
| `templates/claude.md` | 项目根 CLAUDE.md,含方法论精要 + L1 占位 |
| `templates/architecture.md` | L2 架构层,含主流程叙述占位 |
| `templates/module-doc.md` | L3 模块详细,每模块 copy 一份(已合并三段式,无冗余段) |
| `templates/core-code.md` | L4 核心代码(可选,用户主动要时才用) |
| `templates/decisions-readme.md` | ADR 索引,列出格式约定 |
| `templates/adr-template.md` | 单条 ADR 模板(状态/背景/方案/选择/后果),末尾附真实示例 |
