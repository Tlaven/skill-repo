## 文档方法论(AI 协作)

本项目采用**三段式 × 4 层**文档方法论。文档是人和 AI 的"共享内存"——写**决策需要的信息**,不写**实现需要的信息**(实现看代码)。

> **边界:** N2 的"步骤级说明"属于**决策 / 规则**,不算实现信息。判据:**删掉这句会让实现产生歧义吗?会 → 留;只是让实现更快 → 删。**

### 三段式(每层文档的内部结构)

```
[是什么]   事实:这一层的内容(模块清单 / 函数清单 / etc)
[为什么]   决策:考虑过的方案 + 选择 + 理由 + 被拒方案
[不变量]   约束:必须满足的条件(功能性 + 非功能性)
```

三者缺一都会让 AI 踩坑:只有事实不知道边界,只有决策不知道现状,只有不变量不知道为什么。

### 4 层(L = Layer;层按"加载图"切,不按抽象粒度切;L4 默认不写)

| 层 | 文件 | 何时写 |
|---|---|---|
| L1 整体定位 | 本文件 | 项目立项 |
| L2 架构层 | `docs/architecture.md` | 架构设计 |
| L3 模块详细 | `docs/modules/<name>.md`(从 `docs-templates/module-doc.md` 复制) | 每模块开发前 |
| L4 核心代码 | `docs/core-code.md` | 出现**被 ≥2 个工作场景共同加载**的核心单元(函数 / 表示 / 协议 / 公共后置条件)后(默认不写) |

> **层按"加载图"切,不按抽象粒度切:** 一层的存在理由,是"有一批工作场景必须同时加载同一批东西"。判"该不该有 L4"看**加载闭包**(该单元被 ≥2 个工作场景当前置读),不看"它抽象不抽象"。**入度只有 1 的 N2,留在它自己的 L3。**

### 跨层工件 + novelty 分档

- **术语表** `docs/glossary.md`:领域词的唯一定义处(受控词汇)。**术语先定义再使用**,文档别处只引用不重述。
- **决策记录** `docs/decisions/`:ADR,记"为什么"和被拒方案。
- **对账记录** `docs/reviews/`:teach-back 与"文档考古"的发现留档(E5 产出)。
- **项目特有的跨层工件族**:在 L1 用**目录 + 归属规则**声明一次(例:"脚手架一律住 `docs/scaffolds/`"——若用 `essentials` skill,其默认落点就是这里),**不逐文件枚举**——新增文件不需要改 L1。
- **novelty 分档:** N0 通用模式 / N1 项目特有 / **N2 AI 未见**。N2 必须给"步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收"。
  - **N2 写在哪(路由):** 属**模块内**逻辑 → 该模块 L3 的 N2 栏(**若该模块还没有 `docs/modules/<name>.md`,先照 `docs-templates/module-doc.md` 补一份**);属**跨模块 / 架构骨架 / 高扇入**(判据:**加载闭包 ≥ 2**)→ 记到**公共处**:建了 L4 记 `docs/core-code.md`,没建 L4 记 L2 的 `[不变量]` 架构级约束(模块边界规则 / 跨模块通信方式)。所谓"L4 默认不写" = 不主动建文件,但命中收录标准的 N2 **必须有家**——**未建层 ≠ 无处可写。**
    - **跨模块逻辑只许一处成文:** 记在公共处(L4,或 L2 的架构级约束),该模块 L3 只留一行指针(E1);**不要两处各写一份**(必然漂移)。若**整个项目的核心就是那套表示 / 骨架**,它属 L2 / L3 正文,**不进 L4**——L4 只收骨架里**横切**的那几条。
  - **信号 · 该不该开一份 L3:** 某模块的细节一直往 L2 / 别的大文档里堆、而不是堆进它自己的 L3 → 这是"该给它开一份 L3"的信号(**不限于"新建模块",存量模块同样适用**)。
  - **分档只回答"有没有先验",不回答"先验对不对"——判 N0 要两条同时成立:** ① 训练见过 / 能检索到;② 存在**明显唯一**的公认写法。**看着眼熟、但存在多个语义相近实现**的领域——金额与舍入、时区与 DST、权限边界、ID 生成、重试与幂等、字符编码、并发读写——**一律不许判 N0**:按 N1 起评,核心单元按 N2。此最危险的一档,因为它的先验不是"没有",而是"有很多个,随机挑一个,并且一样自信"。**这份名单(「易错领域名单」)是示例、不是封闭集合**——判据是"存在多个语义相近实现";任何满足该判据的领域都算(例如排版 / 渲染的确定性、加密参数选择、字符归一化)。**它怎么往里加条目:** 三类触发——① 调研发现新领域;② 真实事故 / 踩坑;③ 复核发现了名单之外的错法——**追加一行 + 来源**;在 E5 对账时顺手做;名单太长时,按本文件开头写的行数预算外置(只留示例 + 指针)。

### 分层加载(AI 协作时按需读取)

| 场景 | 加载哪几层 |
|---|---|
| 平时对话 / 选方向 | 本文件(自动加载) |
| 遇到不认识的领域名词 | + `docs/glossary.md` |
| 做某模块工作 | + `docs/architecture.md` + 该模块 L3 |
| 改核心单元 / 新领域逻辑(N2) | **模块内**的 + 该模块 L3;**跨模块 / 骨架 / 高扇入**的 + 公共处:`docs/core-code.md` **或** L2 的 `[不变量]` 架构级约束(含步骤级说明 / 危险实现清单 / 例子 / 验收) |
| 写非功能需求 / 审美要求 | + `docs-templates/verifying-nonfunctional.md`(确定性 / 性能 / 美观 / 合规怎么造验收) |
| 讨论架构变更 | + L2 的"为什么"和"不变量"段 |
| 讨论性能 / 质量 | + 各层"不变量"段 |
| 排查 bug | L2 主流程叙述 + 相关 L3 + 该 bug 所在的核心单元(core-code,或 L2 的架构级约束) |
| 文档演进 / 对账 / 大改动前 | + `docs-templates/evolution-rules.md`(E1–E7) |

### 日常入口(立项之后怎么用)

- **建新模块**:从 `docs-templates/module-doc.md` 生成 `docs/modules/<name>.md`,先填三段式(标 novelty 档),再写代码 `[脚本可查]`
- **改代码前(每次改动)**:载入相关 L2/L3。**不需要每次跑复核**;攒到你觉得"这批改动值得看一眼"时,跑 `scripts/review-backlog`(`.sh` / `.ps1`;未拷 scripts/ 时:从 skill 目录跑,或用 `git diff --stat <起点>..HEAD -- <L1 文件名> docs/`——L1 文件名按宿主;非 git 人工列),再派独立 agent(见 `docs-templates/teach-back-verifier-prompt.md`)只复核 delta(喂整节:定义段 + 验收段必须同在——否则"没给"会被误判成缺口),复核完把起点写进 `docs/reviews/.last-review`——**推荐在对应实现之前完成** `[只能靠自觉]`
- **做决策**:按 E4 判要不要记 ADR;要记就当场写 `[需独立复核]`
- **收尾(可选)**:若已把 `scripts/` 拷进项目,跑 `scripts/check-docs-sync`(代码动过但文档没动)与 `scripts/check-doc-refs`(死链 / 占位符 / N2 缺 `**验收**` / N2 缺危险实现清单 / 模块缺失败语义 / 危险实现清单行未填 / 现状文档引记录（现状文档把 ADR / 评审记录当依据引用）)（均 `.sh` / `.ps1`）,可再接 pre-commit / CI `[脚本可查]`(Windows:先确保 `.sh` 为 LF——`*.sh text eol=lf`);未接入则跳过——**但文档里"已验证 / 全绿"这类声称要标"未接 / 未复跑":声称不是证据**

### 铁律

> 每条末尾的标签 = **这条靠什么生效**:`[脚本可查]` 检查器能判定 · `[需独立复核]` 要一个独立 agent 判断 · `[只能靠自觉]` 无法强制。
>
> **别与"验证方式"混:** 不变量还有一套"怎么验它"的标注——**强制 / 约定**（其中"约定"=只写在文档里、没有自动检查）；两套轴含义不同，不要互推。

1. **先文档,再代码**——大改动前先更新对应层文档,文档是设计的契约 `[脚本可查]`
2. **ADR 即时记录**——决策当下就写,事后补 90% 会丢(触发粒度见 E4) `[需独立复核]`
3. **被拒方案要记"为什么不"**——拒绝的方案要记下原因,一年后 AI 提同样方案时,这是唯一能挡住它的记录 `[只能靠自觉]`
4. **写决策需要的信息,不写实现需要的信息**——细节让 AI 现场读代码 `[只能靠自觉]`
5. **不变量优先级最高**——三段里"不变量"最不能省,它是 AI 改代码时必须遵守的约束。**先写危险实现清单**(3 种最可能被写出来的"看起来对"的错法)——**互为遮挡:每条不变量至少挡掉一种,每项至少被一条不变量或验收挡住**;清单空 = 不变量还没想清。**人指定的接口 / 数据结构 / 失败码 / 命名标 `[已定]`**,等同不变量——AI 不得"顺手优化" `[需独立复核]`
6. **推翻陈述必须先修文档**——[是什么] 不保留已经过时的旧陈述、[为什么] 被推翻要标状态、不变量被违反时从三条出路里选一条(修订原文 / 加例外 / 放弃改动)。共享内存失真比没有内存更危险 `[需独立复核]`
7. **术语先定义再使用**——出现新领域名词先登记 `docs/glossary.md`;文档里出现未登记名词 = 漂移信号。**术语是分类信号,不是闸门信号**:新词所在的**最小逻辑单元**按 N1 起评、核心单元按 N2(若该词描述的正是领域特有的新行为,直接按 N2——登记时评估,细则见 `docs/glossary.md` 的维护规则)。**只有该词还没有可判定的定义**(词条空白 / 有 ≥2 种互相竞争的含义 / 含义刚被修改)**才值得做复核**——"新增了一个已定义清楚的词"不算信号,否则冷启动时每个单元都触发,复核立刻退化成仪式 `[需独立复核]`
8. **N2 逻辑必须写到可实现**——AI 未见的领域 / 创新核心,必须给"步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收"(怎么造验收见 `docs-templates/verifying-n2.md`),否则 AI 只能猜 `[需独立复核]`
9. **teach-back 是按需工具,不是必经关卡**——命中 **N2 / 不变量 / 术语歧义 / 跨层大改** 时**值得**做,由你主动发起(派发靠自觉);默认**攒批**做——先跑 `scripts/review-backlog`,只把 delta 喂给独立 agent——**推荐在对应实现前完成**。逐次跑太贵。结论记 `docs/reviews/`;另:**它判的是"文档写没写清",不是"断言为真"**——事实类断言靠外部核实(试跑 / 来源):能试跑先试跑,不能则写出来源或谁拍的板(细则见 `docs-templates/verifying-n2.md`)。**跳过要留痕:** 计划过复核又跳过 → 在任务笔记 / ADR 落一行「未复核(日期 / 原因)」——省略不应是无痕的 `[只能靠自觉]`
10. **长期事实只留在 `docs/` 一处**——本次调研 / 试错 / 草稿写进任务笔记(如 `task_plan.md`);一旦确认要长期保留,就登记进 `docs/` 对应文件并从任务笔记里删掉。
    **任务笔记的生命周期:** 它只放工作状态 / 过程 / 交接,**不是事实源**;引用提交 SHA 时,笔记提交必须晚于被引用提交,且**按阶段批量同步**(每轮同步会被后续提交反复打脸);阶段收尾写清"可玩 / 可用清单 · 待作者 · 下一步候选 · 提交链 · 验证结果";体量过大或阶段结束时压成收尾摘要,过程历史交给 git `[只能靠自觉]`
11. **压缩时保护关键上下文**——压缩 / 清理上下文时务必保留:术语表路径、当前不变量、验收命令、未决问题(open questions) `[只能靠自觉]`

### 文档完成判据(什么时候停)

三条**同时**满足即停,不再往里加内容:

1. **如果你做过复核** → 它判「通过」(「通过」只说明文档内部一致——事实断言另靠外部核实(试跑 / 来源),见铁律 9;判「需人拍板」也停笔——把判定为「需人拍板」的那几条未决问题交给用户);**没做就跳过这条**(复核不强制,别为了凑这一条去跑);
2. **危险实现清单**每一项都被某条不变量或某条 `**验收**` 挡住;
3. 每条 N2 都有可跑验收(命令 或 property 断言)。

缺任一条 = 还没写完;三条齐了还想再加,多半是在把实现细节抄进决策层。

### 演化期规则(立项之后,文档怎么不死)

> **E1–E7 的唯一归属是 `docs-templates/evolution-rules.md`**(随项目落地)。本 L1 只留指针——**做文档演进 / 对账 / 大改动前加载它**。
> (一句话:三段式是容器;每段里的陈述按**性质**——描述型 / 决策型 / 约束型 / 方向型——分四类,腐烂方式各异,维护动作见那七条。)
