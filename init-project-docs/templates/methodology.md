# 文档方法论（AI 协作协议）

> **不随 L1 自动加载。** 只在写 / 改 / 审文档时读；项目 L1 的「活文档索引」里列一行。

## 1. 总则

写**决策需要的信息**,不写**实现需要的信息**。

> 删掉这句会让实现产生歧义吗?会 → 留;只是让实现更快 → 删。

### 三段式

```
[是什么]   事实:这一层的内容(模块清单 / 函数清单 / etc)
[为什么]   决策:考虑过的方案 + 选择 + 理由 + 被拒方案
[不变量]   约束:必须满足的条件(功能性 + 非功能性)
```

### 三时间轴(历史 / 当下 / 未来)

> 历史 = 决策记录桶,当下 = 现状与约束桶,未来 = 方向与开放问题桶。**文档层 L1–L4 是另一根轴**。

### 时间与版本纪律

- 当前文档用**现在时**：不写日期、文档版本号、变更史、旧状态。
- 只允许顶部一行 `Last verified: <commit SHA>`（可选）。用 SHA。
- 领域版本号可以留（save / API / schema `v1`），但只在术语 / 约束定义一次。
- 日期只出现在归档文件名、ADR、reviews、changelog；活文档标题不带日期。
- 需要“当时快照” → 放 `docs/archive/<name>-YYYY-MM-DD.md`；活文档只留当前真相。

### 4 层

| 层 | 文件 | 何时写 |
|---|---|---|
| L1 整体定位 | 项目根 L1（`AGENTS.md` / `CLAUDE.md`） | 项目立项 |
| L2 架构层 | `docs/architecture.md` | 主流程 / 架构边界需要单独讲清时 |
| L3 模块详细 | `docs/modules/<name>.md`(从模块模板复制) | 某个模块的机制需要单独讲清时 |
| L4 核心分析 | `docs/core-analysis.md` | 需要把项目新颖性核心从上层代码中剥出来分析时（可选） |

> **层按抽象度切:** 高层指方向,低层做具体;读低层文档时默认已经读过它的上层文档;同一层内部自足。L4 由 L1 索引单独列出。**N2 不落 L4**:模块内的留 L3,跨模块的进 L2。

> **N1 / N2 条件化:** 模块文档默认 **N1 一页**(是什么 / 为什么 / 不变量);只有 `novelty=N2` 才加"步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收 + 失败语义"。

### 唯一正文归属

| 主题 | 唯一正文 |
|---|---|
| 项目定位 / 当前约束 / 命令 / 活文档索引 | 项目 L1 |
| 方法论 / 铁律 / 加载表 / novelty | 本文件（协议） |
| 当前活文档清单 | `docs/.live` |
| 世界是什么 / 模块骨架 / 主流程 / 未决 | `docs/architecture.md`(L2) |
| `<模块 A>` 的机制 / 公式 / 默认值 | `docs/modules/<a>.md`(L3) |
| 跨模块术语与约束性取值(键 / 字段 / 判据 / 恒同) | `docs/glossary.md` |
| 单模块机制词 | 该模块的术语小节 |
| 验收跑法与覆盖项 | `<一处,如 docs/modules/<engine>.md>` |
| 被拒方案 / 历史来由 | 仍成立的被拒理由 → 该模块的 `[为什么]`；完整过程 → `docs/decisions/`（工作台，稳定后退役） |
| 当前仍成立的设计理由 | 该模块的 `[为什么]` |
| 核对发现 | `docs/reviews/` |
| 过程材料 | 任务笔记 / `notes/` |

> 入口类文档(如 README)只写"怎么点";**过程材料活文档不得引用**。

> **索引与引用方向相反:** **索引**(文档级目录,只写"哪份文档管什么")**上指下**——项目 L1 的活文档索引是总表,约束 → `world` / `upgrade-system`、架构 → `modules/` 各是它的分层展开;**引用**(条款依据)**下指上**——正文只写稳定代号(`A-1` / `R-5`)。模块不写文档目录（由 L2 / L1 列出）；L4 没有下层，也不写目录。

### 当前文档清单与减法

- **`docs/.live`** 一行一个路径（相对 `docs/`）；只有白名单里的文档算“当前”，未列出的按历史 / 参考处理，不进日常加载。
- Python 检查器（`check-consistency` / `run-n2-acceptance`；可选 `check-code-refs`）默认只扫白名单 + L1；`check-consistency --all-docs` 才扫全库（迁移 / 核对用）。`check-doc-refs` 仍按目录排除（archive / experiment / decisions / reviews / templates 不扫）。
- **net-negative:** 新增一个活文档，必须合并 / 替换 / 归档一个。
- 行数是**项目自定的软预算**：要查就显式传 `--max-lines N`；超了只警告、不阻断。
- **历史内容只增不改，存在按寿命裁剪**：仍约束 → 升格进当下后退役；有证据地不再约束 → 退役（移出工作区，git 保留）；答不出 → 退役候选，交作者。`docs/archive/`、`docs/decisions/`、`docs/reviews/`、`docs/experiment/` 都不是日常入口。

### 跨层工件 + novelty 分档

- **术语表** `docs/glossary.md`:跨模块领域词的唯一定义处(受控词汇);**单模块机制词归该模块的术语小节**,被第二个模块当作规则 / 判据使用才提升。**术语先定义再使用**,文档别处只引用不重述。
- **决策记录** `docs/decisions/`:ADR,记"为什么"和被拒方案。
- **核对记录** `docs/reviews/`:teach-back 与**全量核对**的发现留档(E-5 产出);按核对周期**整批退役**,`.last-review` 是游标。
- **时间轴 / 演化规则 / 复核 / 核对约定**:`docs-templates/lifecycle.md` / `docs-templates/verification.md`(直引规则;由本文件的加载表引用)。
- **项目特有的跨层工件族**:在 L1 用**目录 + 归处规则**声明一次(例:"实验脚手架一律住 `docs/experiment/`"——与游戏 / 产品开发入口分开)——新增文件不需要改 L1。
- **novelty 分档:** N0 通用模式 / N1 项目特有 / **N2 AI 未见**。N2 必须给"步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收 + 失败语义"。
  - **N2 写在哪(路由):** 属**模块内**逻辑 → 该模块 L3 的 N2 栏（若该模块还没有模块文档，先照模板补一份）；属**跨模块 / 架构骨架 / 高扇入**（判据：**被 ≥2 个模块的工作场景默认加载**——只被本模块需要就留 L3，第二个模块也要读它才上 L2）→ 五件套（含 `**验收**` 与失败语义）记到 **L2 `docs/architecture.md` 的「N2 单元规格」节，一个单元一节**。模块文档的 `novelty=` 照**模块概念**填：五件套上移之后那里仍是 `N2`，档位不因摆放位置降级。
    - **跨模块逻辑只许一处成文:** 五件套（含验收与失败语义）记在 L2（模块内 N2 记 L3），该模块 L3 **不复述；要指就用稳定代号**；正文只写在**承载它的那份**里——模块文档保留 `novelty` 档位标记，但不再重复五件套。
  - **信号 · 该不该开一份 L3:** 某模块的细节一直往 L2 / 别的大文档里堆、而不是堆进它自己的 L3 → 这是"该给它开一份 L3"的信号(**不限于"新建模块",存量模块同样适用**)。
  - 判 N0 要两条同时成立: ① 训练见过 / 能检索到;② 存在**明显唯一**的公认写法。**看着眼熟、但存在多个语义相近实现**的领域——金额与舍入、时区与 DST、权限边界、ID 生成、重试与幂等、字符编码、并发读写——**一律不许判 N0**:按 N1 起评,核心单元按 N2。

### 分层加载

| 场景 | 加载哪几层 |
|---|---|
| 平时对话 / 选方向 | 项目 L1(自动加载);方法论按需 |
| 遇到不认识的领域名词 | + `docs/glossary.md` |
| 做某模块工作 | + `docs/architecture.md` + 该模块 L3 |
| 改核心单元 / 新领域逻辑(N2) | **模块内**的 + 该模块 L3；**跨模块 / 骨架 / 高扇入**的 + `docs/architecture.md` 的对应 `N2: <单元>` 节 |
| 写非功能需求 / 审美要求 | + `docs-templates/acceptance.md`(非功能 / 主观需求怎么造验收) |
| 讨论架构变更 | + L2 的"为什么"和"不变量"段 |
| 讨论性能 / 质量 | + 各层"不变量"段 |
| 排查 bug | L2 主流程叙述 + 相关 L3 + 该 bug 所在单元的规格（L2 的 `N2: <单元>` 节 / 模块 L3）；想看核心怎么串起来再看 L4（可选） |
| 文档演进 / 核对 / 大改动前 | + `docs-templates/lifecycle.md`(E-1–E-7) + `docs-templates/verification.md`(E-5 执行) |
| 写文档 / 改代码前 | + `docs-templates/lifecycle.md` + `docs-templates/verification.md`(当下 DoD / 复核 / 核对) |

### 日常入口

- **建新模块**:从 `docs-templates/module-doc.md` 生成 `docs/modules/<name>.md`,先填三段式(标 novelty 档),再写代码 `[脚本可查]`
- **改代码前(主战场)**:载入相关 L2/L3;按 `docs-templates/lifecycle.md` 的当下 DoD 自检;命中信号时跑 `docs-templates/verification.md` 的多视角复核(攒批:若已拷入 `scripts/`,先跑 `scripts/review-backlog` 取 delta;未拷则人工列 delta 并标「未接入 / 未复跑」,复核完把起点写进 `docs/reviews/.last-review`)。`[只能靠自觉]`。
- **改代码前 / commit(工具)**:若已拷入 `scripts/`(含共享模块 `_doc_common.py`):改代码前可选跑 `scripts/check-code-refs.py`(约束性变更加 `check-consistency.py`,N2 变更加 `run-n2-acceptance.py`);commit 不默认接脚本。未拷则跳过并标「未接入 / 未复跑」。
- **做决策**:按 E-4 判要不要记 ADR;要记就当场写 `[需独立复核]`
- **收尾(可选)**:若已把 `scripts/` 拷进项目,跑 `scripts/check-doc-refs`（`.sh` / `.ps1`）,可再接 pre-commit / CI `[脚本可查]`(Windows:先确保 `.sh` 为 LF——`*.sh text eol=lf`);未接入则跳过——**但文档里"已验证 / 全绿"这类声称要标"未接入 / 未复跑":声称不是证据**

### 铁律

> 每条末尾的标签 = **这条靠什么生效**:`[脚本可查]` 检查器能判定 · `[需独立复核]` 要一个独立 agent 判断 · `[只能靠自觉]` 无法强制。

1. **先文档,再代码**——大改动前先更新对应层文档,改代码前按需跑复核 / panel `[只能靠自觉]`
2. **决策当场记**;记什么、记成什么载体、留多久,归演进规则 `[需独立复核]`
3. **被拒方案要记"为什么不"** `[只能靠自觉]`
4. **写决策需要的信息,不写实现需要的信息** `[只能靠自觉]`
5. **不变量优先级最高**。**先写危险实现清单**(3 种最可能被写出来的"看起来对"的错法)——**互为遮挡:每条不变量至少挡掉一种,每项至少被一条不变量或验收挡住**;清单空 = 不变量还没想清。**人指定的接口 / 数据结构 / 失败码 / 命名标 `[已定]`**,等同不变量——AI 不得"顺手优化" `[需独立复核]`
6. 文档与代码不同真时,先修文档再谈改动 `[需独立复核]`
7. **术语是分类信号,不是闸门信号**:新词所在的**最小逻辑单元**按 N1 起评、核心单元按 N2(若该词描述的正是领域特有的新行为,直接按 N2——登记时评估,细则见 `docs/glossary.md` 的维护规则)。**只有该词还没有可判定的定义**(词条空白 / 有 ≥2 种互相竞争的含义 / 含义刚被修改)**才值得做复核** `[需独立复核]`
8. **N2 逻辑必须写到可实现**——AI 未见的领域 / 创新核心,必须给"步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收 + 失败语义"(怎么造验收见 `docs-templates/acceptance.md`) `[需独立复核]`
9. **teach-back 是按需工具,不是必经关卡**——命中 **N2 / 不变量 / 术语歧义 / 跨层大改** 时**值得**做,由你主动发起(派发靠自觉);默认**攒批**做——**若已拷入 `scripts/`**,先跑 `scripts/review-backlog`;未拷则人工列 delta——只把 delta 喂给独立 agent——**推荐在对应实现前完成**。结论记 `docs/reviews/`;另:**它判的是"文档写没写清",不是"断言为真"**——事实类断言靠外部核实(试跑 / 来源):能试跑先试跑,不能则写出来源或谁拍的板(细则见 `docs-templates/acceptance.md`)。**跳过要留痕:** 计划过复核又跳过 → 在任务笔记 / ADR 落一行「未复核(日期 / 原因)」 `[只能靠自觉]`
10. **任务笔记不是事实源**——本次调研 / 试错 / 草稿写进任务笔记(如 `task_plan.md`);一旦确认要长期保留,就登记进 `docs/` 对应文件并从任务笔记里删掉。
    引用提交 SHA 时,笔记提交必须晚于被引用提交,且**按阶段批量同步**(每轮同步会被后续提交反复打脸);阶段收尾写清"可玩 / 可用清单 · 待作者 · 下一步候选 · 提交链 · 验证结果";体量过大或阶段结束时压成收尾摘要,过程历史交给 git `[只能靠自觉]`
11. **压缩时保护关键上下文**——压缩 / 清理上下文时务必保留:术语表路径、当前不变量、验收命令、未决问题(open questions) `[只能靠自觉]`

### 文档完成判据

四条**同时**满足即停:

1. **如果你做过复核** → 它判「通过」(「通过」只说明文档内部一致——事实断言另靠外部核实(试跑 / 来源),见铁律 9;判「需人拍板」也停笔——把判定为「需人拍板」的那几条未决问题交给用户);**没做就跳过这条**(复核不强制);
2. **当下 DoD 四条满足**:自洽 / 可读 / 对标 / 核心逻辑;
3. 每条 N2 都有可跑验收(命令 或 property 断言);
4. **紧凑性**:审计量两样:**同一规格的副本数 = 1**、**跨活文档重复的参数/计数 = 0**(冻结 fixture / 示例除外)。超了先合并 / 删枝节,不靠"转成目录条目"减压。
