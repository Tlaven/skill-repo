# 文档方法论（AI 协作协议）

> **本文件是方法论正文，不随 L1 自动加载。** 只在写 / 改 / 审文档时读；项目 L1 的「活文档索引」里列一行。
> 目标：让当前文档小、历史冷、未来短；防止“过写”。
> 分工：项目记忆在 L1 / `docs/` / `task_plan.md`；协议在本文件。

## 1. 总则

本项目采用**三段式 × 4 层**文档方法论。文档是人和 AI 的"共享内存"——写**决策需要的信息**,不写**实现需要的信息**(实现看代码)。

> **边界:** N2 的"步骤级说明"属于**决策 / 规则**,不算实现信息。判据:**删掉这句会让实现产生歧义吗?会 → 留;只是让实现更快 → 删。**

### 三段式(每层文档的内部结构)

```
[是什么]   事实:这一层的内容(模块清单 / 函数清单 / etc)
[为什么]   决策:考虑过的方案 + 选择 + 理由 + 被拒方案
[不变量]   约束:必须满足的条件(功能性 + 非功能性)
```

三者缺一都会让 AI 踩坑:只有事实不知道边界,只有决策不知道现状,只有不变量不知道为什么。

### 三时间轴(历史 / 当下 / 未来)

> **三个时间桶,不是三个时间点:** 历史 = 决策记录桶,当下 = 现状与约束桶,未来 = 方向与开放问题桶;不是 git 历史 / 当前时刻 / 路线图。**文档层 L1–L4 是另一根轴**,不要和时间桶混。

### 时间与版本纪律

- 当前文档用**现在时**：不写日期、文档版本号、变更史、旧状态。
- 只允许顶部一行 `Last verified: <commit SHA>`（可选）；它记录“最后一次对代码验证”，不是逐条历史。用 SHA，不用日期。
- 领域版本号可以留（save / API / schema `v1`），但只在术语 / 契约定义一次；它不是文档版本。
- 日期只出现在归档文件名、ADR、reviews、changelog；活文档标题不带日期。
- 需要“当时快照” → 放 `docs/archive/<name>-YYYY-MM-DD.md`；活文档只留当前真相。

### 4 层(L = Layer;层按抽象度切:上层指方向,下层做具体;L4 可选)

| 层 | 文件 | 何时写 |
|---|---|---|
| L1 整体定位 | 项目根 L1（`AGENTS.md` / `CLAUDE.md`） | 项目立项 |
| L2 架构层 | `docs/architecture.md` | 主流程 / 架构边界需要单独讲清时 |
| L3 模块详细 | `docs/modules/<name>.md`(从模块模板复制) | 某个模块的机制需要单独讲清时 |
| L4 核心分析 | `docs/core-analysis.md` | 需要把项目新颖性核心从上层代码中剥出来分析时（可选） |

> **层按抽象度切,不按加载图 / 索引切:** 高层指方向,低层做具体;读低层文档时默认已经读过它的上层文档;同一层内部自足。**L4 是核心分析视图,不是引用目标**——它把架在核心上的业务代码剥掉,只看核心运行逻辑;L1 / L2 / L3 不引用 L4 正文,L4 由 L1 索引单独列出。**N2 不落 L4**:模块内的留 L3,跨模块的进 L2;理由见下方「N2 写在哪(路由)」。

> **N1 / N2 条件化:** 模块文档默认 **N1 一页**(是什么 / 为什么 / 不变量);只有 `novelty=N2` 才加"步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收 + 失败语义"。**不要给 N1 模块套 N2 的五件套。**

### 唯一正文归属(先认领,再写)

> 这张表只做**认领**:新项目先在表里认领"谁写什么",再动笔。

| 主题 | 唯一正文 |
|---|---|
| 项目定位 / 当前约束 / 命令 / 活文档索引 | 项目 L1 |
| 方法论 / 铁律 / 加载表 / novelty | 本文件（协议） |
| 当前活文档清单 | `docs/.live` |
| 世界是什么 / 模块骨架 / 主流程 / 未决 | `docs/architecture.md`(L2) |
| `<模块 A>` 的机制 / 公式 / 默认值 | `docs/modules/<a>.md`(L3) |
| 跨模块术语与契约定值(键 / 字段 / 判据 / 恒同) | `docs/glossary.md` |
| 单模块机制词 | 该模块的术语小节 |
| 验收跑法与覆盖项 | `<一处,如 docs/modules/<engine>.md>` |
| 被拒方案 / 历史来由 | 仍成立的被拒理由 → 该模块的 `[为什么]`；完整过程 → `docs/decisions/`（工作台，稳定后退役） |
| 当前仍成立的设计理由 | 该模块的 `[为什么]` |
| 对账发现 | `docs/reviews/` |
| 过程材料 | 任务笔记 / `notes/` |

> 入口类文档(如 README)只写"怎么点",不重列验收清单;**过程材料活文档不得引用**。

> **索引与引用方向相反,别混成一个"指针":** **索引**(文档级目录,只写"哪份文档管什么")**上指下**——项目 L1 的活文档索引是总表,契约 → `world` / `upgrade-system`、架构 → `modules/` 各是它的分层展开;**引用**(条款依据)**下指上**——正文只写稳定代号(`A-1` / `R-5`),不写小节标题 / 行号 / 页码,也不在句旁挂"见 ADR-0NN"。模块不写文档目录（由 L2 / L1 列出）；L4 没有下层，也不写目录。

### 活文档白名单与减法

- **`docs/.live`** 一行一个路径（相对 `docs/`）；只有白名单里的文档算“当前”，未列出的按历史 / 参考处理，不进日常加载。
- Python 检查器（`check-consistency` / `check-code-refs` / `lint-doc-structure` / `run-n2-acceptance`）默认只扫白名单 + L1；`check-consistency --all-docs` 才扫全库（迁移 / 对账用）。`check-doc-refs` 仍按目录排除（archive / experiment / decisions / reviews / templates 不扫）。
- **net-negative:** 新增一个活文档，必须合并 / 替换 / 归档一个；否则不许加。
- 行数是**项目自定的软预算**：工具不内置默认值，要查就显式传 `--max-lines N`；超了只警告、不阻断。
- **历史内容只增不改，存在按寿命裁剪**：仍约束 → 升格进当下后退役；有证据地不再约束 → 退役（移出工作区，git 保留）；答不出 → 退役候选，交作者。`docs/archive/`、`docs/decisions/`、`docs/reviews/`、`docs/experiment/` 都不是日常入口；**归档不是永久层，退役不是删除**。

### 跨层工件 + novelty 分档

- **术语表** `docs/glossary.md`:跨模块领域词的唯一定义处(受控词汇);**单模块机制词归该模块的术语小节**,被第二个模块当作规则 / 判据使用才提升。**术语先定义再使用**,文档别处只引用不重述。
- **决策记录** `docs/decisions/`:ADR,记"为什么"和被拒方案。**是决策工作台,不是档案库**。
- **对账记录** `docs/reviews/`:teach-back 与**全量文档对账**的发现留档(E-5 产出);按对账周期**整批退役**,`.last-review` 是游标,不是历史。
- **时间轴模型 / 复核约定**:`docs-templates/temporal-model.md` / `docs-templates/review-panel.md`(就地读件;L1 的活文档索引里列出)。
- **项目特有的跨层工件族**:在 L1 用**目录 + 落点规则**声明一次(例:"实验脚手架一律住 `docs/experiment/`"——与游戏 / 产品开发入口分开),**不逐文件枚举**——新增文件不需要改 L1。
- **novelty 分档:** N0 通用模式 / N1 项目特有 / **N2 AI 未见**。N2 必须给"步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收 + 失败语义"。
  - **N2 写在哪(路由):** 属**模块内**逻辑 → 该模块 L3 的 N2 栏（若该模块还没有模块文档，先照模板补一份）；属**跨模块 / 架构骨架 / 高扇入**（判据：**被 ≥2 个模块的工作场景当前置读**——只被本模块需要就留 L3，第二个模块也要读它才上 L2）→ 五件套（含 `**验收**` 与失败语义）记到 **L2 `docs/architecture.md` 的「N2 单元规格」节，一个单元一节**。模块文档的 `novelty=` 照**模块概念**填：五件套上移之后那里仍是 `N2`，档位不因摆放位置降级。
    - **别把"加载表里有几行提到它"当判据**:L2 / L3 在加载表里各被提到多次,按行数算连 L3 也"≥2",判据就废了。要数的是**读者的模块数**:哪些模块的活在开工前必须先读这份规格。
    - **为什么是 L2 而不是 L4**:判据是加载——这些模块本来就读 L2,规格住在那里才读得到;L4 不在任何场景的前置读集合里。L4（`docs/core-analysis.md`）是可选的阅读视图,只做跨层再叙述,不给验收、不被引用。
    - **跨模块逻辑只许一处成文:** 五件套（含验收与失败语义）记在 L2（模块内 N2 记 L3），该模块 L3 **不复述；要指就用稳定代号**；正文只写在**承载它的那份**里——模块文档保留 `novelty` 档位标记，但不再重复五件套。**不要两处各写一份**（必然漂移）。L2 因此会变长：按「一个单元一节」读，不要从头顶顺读。
  - **信号 · 该不该开一份 L3:** 某模块的细节一直往 L2 / 别的大文档里堆、而不是堆进它自己的 L3 → 这是"该给它开一份 L3"的信号(**不限于"新建模块",存量模块同样适用**)。
  - **分档只回答"有没有先验",不回答"先验对不对"——判 N0 要两条同时成立:** ① 训练见过 / 能检索到;② 存在**明显唯一**的公认写法。**看着眼熟、但存在多个语义相近实现**的领域——金额与舍入、时区与 DST、权限边界、ID 生成、重试与幂等、字符编码、并发读写——**一律不许判 N0**:按 N1 起评,核心单元按 N2。此最危险的一档,因为它的先验不是"没有",而是"有很多个,随机挑一个,并且一样自信"。**这份名单(「易错领域名单」)是示例、不是封闭集合**——判据是"存在多个语义相近实现";任何满足该判据的领域都算(例如排版 / 渲染的确定性、加密参数选择、字符归一化)。**它怎么往里加条目:** 三类触发——① 调研发现新领域;② 真实事故 / 踩坑;③ 复核发现了名单之外的错法——**追加一行 + 来源**;在 E-5 对账时顺手做;名单长到影响加载时,外置成单独清单,此处只留示例 + 指向它的索引(判据是体量与副本数,不是行数)。

### 分层加载(AI 协作时按需读取)

| 场景 | 加载哪几层 |
|---|---|
| 平时对话 / 选方向 | 项目 L1(自动加载);方法论按需 |
| 遇到不认识的领域名词 | + `docs/glossary.md` |
| 做某模块工作 | + `docs/architecture.md` + 该模块 L3 |
| 改核心单元 / 新领域逻辑(N2) | **模块内**的 + 该模块 L3；**跨模块 / 骨架 / 高扇入**的 + `docs/architecture.md` 的对应 `N2: <单元>` 节 |
| 写非功能需求 / 审美要求 | + `docs-templates/verifying-nonfunctional.md`(确定性 / 性能 / 美观 / 合规怎么造验收) |
| 讨论架构变更 | + L2 的"为什么"和"不变量"段 |
| 讨论性能 / 质量 | + 各层"不变量"段 |
| 排查 bug | L2 主流程叙述 + 相关 L3 + 该 bug 所在单元的规格（L2 的 `N2: <单元>` 节 / 模块 L3）；想看核心怎么串起来再看 L4（可选） |
| 文档演进 / 对账 / 大改动前 | + `docs-templates/evolution-rules.md`(E-1–E-7) |
| 写文档 / 改代码前 | + `docs-templates/temporal-model.md` + `docs-templates/review-panel.md`(当下 DoD / 多镜复核) |

### 日常入口(立项之后怎么用)

- **建新模块**:从 `docs-templates/module-doc.md` 生成 `docs/modules/<name>.md`,先填三段式(标 novelty 档),再写代码 `[脚本可查]`
- **改代码前(主战场)**:载入相关 L2/L3;按 `docs-templates/temporal-model.md` 的当下 DoD 自检;命中信号时跑 `docs-templates/review-panel.md` 的多镜复核(攒批:若已拷入 `scripts/`,先跑 `scripts/review-backlog` 取 delta;未拷则人工列 delta 并标「未接入 / 未复跑」,复核完把起点写进 `docs/reviews/.last-review`)。**不需要每次改动都跑;推荐在对应实现之前完成** `[只能靠自觉]`。commit 时只跑轻量对账。
- **改代码前 / commit(工具)**:若已拷入 `scripts/`(整目录拷贝,含共享模块 `_doc_common.py`):改代码前跑 `scripts/check-code-refs.py`(契约级变更加 `check-consistency.py`,N2 变更加 `run-n2-acceptance.py`);commit 轻量跑 `check-docs-sync` + `check-code-refs.py`;`lint-doc-structure.py` 只作警告。未拷则跳过并标「未接入 / 未复跑」。
- **做决策**:按 E-4 判要不要记 ADR;要记就当场写 `[需独立复核]`
- **收尾(可选)**:若已把 `scripts/` 拷进项目,跑 `scripts/check-docs-sync`(代码动过但文档没动)与 `scripts/check-doc-refs`(死链 / 占位符 / N2 家缺 `**验收**` / N2 家缺危险实现清单 / 模块缺失败语义 / 危险实现清单行未填 / 现状文档引记录（`docs/` 现状文档里出现具体 ADR 条目、记录目录、`> 出处：` 行；L1 活文档索引里的目录级记录引用除外）)（均 `.sh` / `.ps1`）,可再接 pre-commit / CI `[脚本可查]`(Windows:先确保 `.sh` 为 LF——`*.sh text eol=lf`);未接入则跳过——**但文档里"已验证 / 全绿"这类声称要标"未接入 / 未复跑":声称不是证据**

### 铁律

> 每条末尾的标签 = **这条靠什么生效**:`[脚本可查]` 检查器能判定 · `[需独立复核]` 要一个独立 agent 判断 · `[只能靠自觉]` 无法强制。
>
> **别与"验证方式"混:** 不变量还有一套"怎么验它"的标注——**强制 / 约定**（其中"约定"=只写在文档里、没有自动检查）；两套轴含义不同，不要互推。

1. **先文档,再代码**——大改动前先更新对应层文档,改代码前按需跑复核 / panel;文档是设计的契约 `[脚本可查]`
2. **决策当场记**——事后补,90% 的理由会丢;记什么、记成什么载体、留多久,归演进规则 `[需独立复核]`
3. **被拒方案要记"为什么不"**——拒绝的方案要记下原因,一年后 AI 提同样方案时,这是唯一能挡住它的记录 `[只能靠自觉]`
4. **写决策需要的信息,不写实现需要的信息**——细节让 AI 现场读代码 `[只能靠自觉]`
5. **不变量优先级最高**——三段里"不变量"最不能省,它是 AI 改代码时必须遵守的约束。**先写危险实现清单**(3 种最可能被写出来的"看起来对"的错法)——**互为遮挡:每条不变量至少挡掉一种,每项至少被一条不变量或验收挡住**;清单空 = 不变量还没想清。**人指定的接口 / 数据结构 / 失败码 / 命名标 `[已定]`**,等同不变量——AI 不得"顺手优化" `[需独立复核]`
6. **共享内存失真比没有内存更危险**——文档与代码不同真时,先修文档再谈改动 `[需独立复核]`
7. **术语是分类信号,不是闸门信号**:新词所在的**最小逻辑单元**按 N1 起评、核心单元按 N2(若该词描述的正是领域特有的新行为,直接按 N2——登记时评估,细则见 `docs/glossary.md` 的维护规则)。**只有该词还没有可判定的定义**(词条空白 / 有 ≥2 种互相竞争的含义 / 含义刚被修改)**才值得做复核**——"新增了一个已定义清楚的词"不算信号,否则冷启动时每个单元都触发,复核立刻退化成仪式 `[需独立复核]`
8. **N2 逻辑必须写到可实现**——AI 未见的领域 / 创新核心,必须给"步骤级说明 + 危险实现清单 + 精确例子 + 可跑验收 + 失败语义"(怎么造验收见 `docs-templates/verifying-n2.md`),否则 AI 只能猜 `[需独立复核]`
9. **teach-back 是按需工具,不是必经关卡**——命中 **N2 / 不变量 / 术语歧义 / 跨层大改** 时**值得**做,由你主动发起(派发靠自觉);默认**攒批**做——**若已拷入 `scripts/`**,先跑 `scripts/review-backlog`;未拷则人工列 delta——只把 delta 喂给独立 agent——**推荐在对应实现前完成**。逐次跑太贵。结论记 `docs/reviews/`;另:**它判的是"文档写没写清",不是"断言为真"**——事实类断言靠外部核实(试跑 / 来源):能试跑先试跑,不能则写出来源或谁拍的板(细则见 `docs-templates/verifying-n2.md`)。**跳过要留痕:** 计划过复核又跳过 → 在任务笔记 / ADR 落一行「未复核(日期 / 原因)」——省略不应是无痕的 `[只能靠自觉]`
10. **任务笔记不是事实源**——本次调研 / 试错 / 草稿写进任务笔记(如 `task_plan.md`);一旦确认要长期保留,就登记进 `docs/` 对应文件并从任务笔记里删掉。
    **任务笔记的生命周期:** 它只放工作状态 / 过程 / 交接,**不是事实源**;引用提交 SHA 时,笔记提交必须晚于被引用提交,且**按阶段批量同步**(每轮同步会被后续提交反复打脸);阶段收尾写清"可玩 / 可用清单 · 待作者 · 下一步候选 · 提交链 · 验证结果";体量过大或阶段结束时压成收尾摘要,过程历史交给 git `[只能靠自觉]`
11. **压缩时保护关键上下文**——压缩 / 清理上下文时务必保留:术语表路径、当前不变量、验收命令、未决问题(open questions) `[只能靠自觉]`

### 文档完成判据(什么时候停)
