# Core Analysis — L4 核心分析(可选)

> **使用方式:** 当你要"把搭在核心上的业务代码剥掉、只看核心怎么跑"时才建本层。它只由 L1 的活文档索引列一行。

---

## 什么该进本层(先看这条)

> **判据是"想不想看懂",不是"重不重要"。**

- 收**单元之间怎么协作**:主流程、状态怎么流转、谁在什么时候调谁。
- 收**"为什么这么切"**:骨架选择的理由、被拒方案。
- 不收**单个单元的规格**:步骤级说明、验收、失败语义、`novelty=N2` 标记。
- 不收**实现细节**:函数签名、字段表、行号。

**条目数:** 核心单元应**明显少于**模块内的普通函数;若条目数 **≈ 模块数**,说明你把模块拆成了卡片。

## 与其他层的关系

> 目录由 L1 的活文档索引负责,方向是上指下;本层没有下层,不列文档。

- **本层不是任何内容的家**:N2 规格在 L2 / L3,主流程在 L2,模块机制在 L3。这里只做跨层的再叙述。
- **没有入度**:没人引用本层,所以本层可以随时删掉或退役(git 保留),不影响任何实现或验收。
- **不建本层不会缺任何规格**:缺的只是"一次读完的视角"。若你发现不建就看不懂核心,那说明该补的是 L2 的主流程与 N2 节,而不是这里。
