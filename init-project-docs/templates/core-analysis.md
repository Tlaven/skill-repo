# Core Analysis — L4 核心分析(可选)

> **使用方式:** 当你要"把搭在核心上的业务代码剥掉、只看核心怎么跑"时才建本层。它是**阅读视图**,不是契约——**没有别的文档引用它,也没有任何工作场景被要求前置读它**;它只由 L1 的活文档索引列一行。
> **本层不承载 N2 规格。** 跨模块 / 骨架 / 高扇入的 N2 五件套住 L2(`docs/architecture.md` 的对应单元节),模块内 N2 住模块 L3。本层不给验收、不挂 `novelty=N2`、不写危险实现清单——那些是契约,契约住在别人会读到的地方。
> 三段式:[是什么] / [为什么] / [不变量]
>
> **层按抽象度切,不按加载图 / 索引切:** 高层指方向,低层做具体;读低层默认已读上层。本层只记录核心运行逻辑,不承担给高层当依据的职责。

---

## 什么该进本层(先看这条)

> **判据是"想不想看懂",不是"重不重要"。** 重要的东西已经作为契约写在 L2 / L3 了;本层存在的理由只有一个:把散在多层的核心逻辑拼成一幅可以一次读完的图。

- 收**单元之间怎么协作**:主流程、状态怎么流转、谁在什么时候调谁。
- 收**"为什么这么切"**:骨架选择的理由、被拒方案。
- 不收**单个单元的规格**:步骤级说明、验收、失败语义——这些在 L2 / L3 的 N2 节,重抄就是第二处出处。
- 不收**实现细节**:函数签名、字段表、行号。实现以代码为准。

**条目数(定性,不设数字):** 核心单元应**明显少于**模块内的普通函数;若条目数 **≈ 模块数**,说明你把模块拆成了卡片——那是标准放松的信号。

## 与其他层的关系

> 本节是**归属规则**,不是文档目录(目录由 L1 的活文档索引负责,方向是上指下;本层没有下层,不列文档)。

- **本层不是任何内容的家**:N2 规格在 L2 / L3,主流程在 L2,模块机制在 L3。这里只做跨层的再叙述。
- **没有入度**:没人引用本层,所以本层可以随时删掉或退役(git 保留),不影响任何实现或验收。这也是它"可选"的实际含义。
- **不建本层不会缺任何规格**:缺的只是"一次读完的视角"。若你发现不建就看不懂核心,那说明该补的是 L2 的主流程与 N2 节,而不是这里。
