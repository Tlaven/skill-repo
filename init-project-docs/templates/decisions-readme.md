# Architecture Decision Records (ADR)

本目录记录项目所有重要架构决策。每条 ADR 一个文件,按编号递增。

> **规则正文归属:** ADR 的**触发粒度与推翻时的联动义务**是跨领域规则,唯一正文归属是 `docs-templates/evolution-rules.md`(随项目落地;L1 记忆文件里只留一行指针)——**何时记见 E4,推翻决策的联动义务见 E3**。本文件只讲 ADR 自身(为什么记 / 读取顺序 / 格式 / 命名 / 索引 / 归档),不重述那些规则。

## 为什么记 ADR

- **决策的"为什么"比"是什么"更重要**——代码能读出做了什么,读不出为什么
- **被拒方案要记"为什么不"**——记下"考虑过 X 但拒绝了，因为 Y"，防止后续重复踩坑
- **AI 协作的约束记录**——AI 不知道历史，会反复提出已否决的方案；ADR 是唯一能挡住它的记录

**但记录会被当成指令。** Agent 读到一段记录,不会自动知道它是哪一年的、还有没有效;它会照着做。所以每条记录必须**单独看也自带状态**,被取代的记录必须离开现役名单。

## 给 Agent 的读取顺序

1. **先读本文件的索引**——只有现役与在议;索引里没有的决策不在生效范围。
2. **需要理由 / 被拒方案时**再打开对应记录,打开后**先看 frontmatter 的 `status`**。
3. **`status` 不是 `accepted` / `accepted(修订)` → 不是约束**,只作历史参考。
4. 记录正文是**当时的陈述**（过去时）,不是现状;现状以代码与 `docs/` 下的现状文档为准。

**三个常见误读**（记录本身不会提醒你）:

| 误读 | 正确读法 |
|---|---|
| 把「考虑过的方案」里的被拒方案当成结论 | 结论只在 `## 选择`;被拒方案必须带着「被拒」读 |
| 把原文里的参数当现值 | 参数取**日期最新的「补充」**——原文 append-only,故意不改 |
| 把 `superseded` 的记录当约束 | 先看 `status`;被取代的记录只是历史 |

## ADR 格式

每条 ADR = **frontmatter + 五段**:

```markdown
---
status: accepted
date: 2026-10-24
# superseded_by: ADR-012        ← 被取代时才有
---

# ADR-XXX: [决策标题——祈使句]

## 背景          为什么需要这个决策?
## 考虑过的方案   列出所有方案(包括被拒绝的),被拒的写「拒绝理由」
## 选择          选了哪个?为什么(不是"它最好",而是"在我们的约束下最合适")
## 后果          正面 / 负面后果;需要跟进的
```

- **状态取值:** `proposed` / `accepted` / `accepted(修订)` / `deprecated` / `rejected` / `superseded`。`superseded` 必须带 `superseded_by: ADR-XXX`;非标准写法（如 `approved`）由检查器报错。
- **关系字段**（只在**旧记录**上声明一次）:`superseded_by` / `partially_superseded_by` / `revised_by` / `extended_by`;正向为 `supersedes` / `revises` / `extends`。索引由脚本推导,不重复声明。
- **句式:** 写「当时决定用 X（约束：…）」,不写「本项目使用 X」。记录会被单独引用,语法上就不能像一条现行规则。
- **可选第六段「修订 / 补充」(append-only):** 同一决策内的修正用带日期的补充追加在文末,不改原文、不新建 ADR;换掉被选方案本身 → 新 ADR（`superseded`）。
- **长度:** 超过 800 词会被警告——通常是两条决策,或一份实现日记（日记归 PR）。

模板见 `docs-templates/adr-template.md`;填好的完整示例见 `docs-templates/adr-example.md`。

## 命名规则

```
adr-XXX-[短描述].md
```

- `XXX` 是零填充的递增编号(001, 002, ...);编号不复用,删掉的也不回收。
- 短描述用英文 kebab-case(例:`adr-003-use-event-sourcing`)。
- 文件名编号必须与标题里的 ID 一致（`adr-003-*.md` ↔ `# ADR-003:`）,检查器会对账。

## ADR 索引

（暂无现役记录）
<!-- adr-index:end -->

- **索引由脚本生成,不要手写**——手写的索引在第一个忙周就会漂。
  维护:`python scripts/adr-index.py --root . --write`;对账:`--strict`（CI / pre-commit）。
- **只列现役（`accepted` / `accepted(修订)`）与在议（`proposed`）**。
  被取代 / 弃用 / 被拒的记录不进索引——**读文件的人也会读到留在文件里的东西**,列在末尾等于没删。

## 归档

被取代的记录**移进 `archive/`**,不留在本目录:

```
docs/decisions/
├── .ignore            # 让 archive/ 退出 rg 的默认检索面
├── README.md          # 索引（生成）
├── adr-001-...md      # 现役 / 在议
└── archive/
    └── adr-000-...md  # superseded / deprecated / rejected
```

归档是**移动,不是删除**:历史只增不改,`superseded_by` 仍要能解析到目标（脚本会同时查本目录与 `archive/`）。归档目录不进索引。

**但 `archive/` 挡不住关键词搜索。** Agent 不读索引,它 `rg 关键词`;目录位置对内容搜索没有任何意义,移进 `archive/` 的文件照样命中。必须再配一层:

`docs/decisions/.ignore`,内容一行:

```
archive/
```

- **必须放在 `docs/decisions/` 里**——放仓库根写 `docs/decisions/archive/`,在"从根目录搜 `docs`"时会漏(ripgrep 不读搜索根之外的祖先目录里的 `.ignore`)。
- `.ignore` 不受版本控制,`archive/` 照常提交;考古用 `rg --no-ignore 关键词`。
- **已知的洞:** `git grep` 不认 `.ignore`,也没有排除开关;IDE 全局搜索要各自配 `search.exclude`。
- 若 `docs/reviews/` 也是过程记录,同样处理(在 `docs/` 放 `.ignore` 写 `reviews/`)——这是"默认看不见过程记录",由项目拍板。

> 消不掉的残留:现役 ADR 提到已退役的术语,搜那个词仍会命中一堆现役记录。那是现役记录的正确内容,只能靠记录自带状态 + L1 的解读规则兜。
