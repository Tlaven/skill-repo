# Architecture Decision Records (ADR)

本目录记录项目所有重要架构决策。每条 ADR 一个文件,按编号递增。

> **规则正文归属:** ADR 的**触发粒度与推翻时的联动义务**是跨领域规则,唯一正文归属是 `docs-templates/evolution-rules.md`(随项目落地;L1 的「活文档索引」里列一行)——**何时记见 E4,推翻决策的联动义务见 E3**。本文件只讲 ADR 自身(为什么记 / 读取顺序 / 格式 / 命名 / 归档),不重述那些规则。

## 为什么记 ADR

- **决策的"为什么"比"是什么"更重要**——代码能读出做了什么,读不出为什么
- **被拒方案要记"为什么不"**——记下"考虑过 X 但拒绝了，因为 Y"，防止后续重复踩坑
- **AI 协作的约束记录**——只能用于**追溯过去轨迹**（"当时为什么这么定"）；不得用来主张"现在必须 / 不能这么做"

**但记录会被当成指令。** Agent 读到一段记录,不会自动知道它是哪一年的、还有没有效;它会照着做。所以每条记录必须**单独看也自带状态**,被取代的记录必须离开现役目录——**主目录就是现役名单,不要另写索引**。

## 给 Agent 的读取顺序

1. **先 `ls` 本目录**——主目录里的文件就是现役与在议;`archive/` 里的是历史。本文件只讲读法,不列清单——目录本身就是名单。
2. **需要理由 / 被拒方案时**再打开对应记录,打开后**先看 frontmatter 的 `status`**。
3. **`status` 不是 `accepted` / `accepted(修订)` → 不是约束**,只作历史参考。
4. 记录正文是**当时的陈述**（过去时）,不是现状;现状以代码与 `docs/` 下的现状文档为准。

**三个常见误读**（记录本身不会提醒你）:

| 误读 | 正确读法 |
|---|---|
| 把「考虑过的方案」里的被拒方案当成结论 | 结论只在 `## 选择`;被拒方案必须带着「被拒」读 |
| 把原文里的参数当现值 | 参数取**日期最新的「补充」**——原文 append-only,故意不改 |
| 把 `superseded` 的记录当约束 | 先看 `status`;被取代的记录只是历史 |

## ADR 格式

每条 ADR = **frontmatter + 五段**:

```markdown
---
status: accepted
date: 2026-10-24
# superseded_by: ADR-012        ← 被取代时才有
---

# ADR-XXX: [决策标题——祈使句]

## 背景          为什么需要这个决策?
## 考虑过的方案   列出所有方案(包括被拒绝的),被拒的写「拒绝理由」
## 选择          选了哪个?为什么(不是"它最好",而是"在我们的约束下最合适")
## 后果          正面 / 负面后果;需要跟进的
```

- **状态取值:** `proposed` / `accepted` / `accepted(修订)` / `deprecated` / `rejected` / `superseded`。`superseded` 必须带 `superseded_by: ADR-XXX`;不在这个集合里的写法（如 `approved`）等于没写状态,读者会按未知处理。
- **关系字段**（只在**旧记录**上声明一次）:`superseded_by` / `partially_superseded_by` / `revised_by` / `extended_by`;正向为 `supersedes` / `revises` / `extends`。别处不复述关系。
- **句式:** 写「当时决定用 X（约束：…）」,不写「本项目使用 X」。记录会被单独引用,语法上就不能像一条现行规则。
- **可选第六段「修订 / 补充」(append-only):** 同一决策内的修正用带日期的补充追加在文末,不改原文、不新建 ADR;换掉被选方案本身 → 新 ADR（`superseded`）。
- **长度:** 超过 800 词会被警告——通常是两条决策,或一份实现日记（日记归 PR）。

模板见 `docs-templates/adr-template.md`;填好的完整示例见 `docs-templates/adr-example.md`。

## 命名规则

```
adr-XXX-[短描述].md
```

- `XXX` 是零填充的递增编号(001, 002, ...);编号不复用,删掉的也不回收。
- 短描述用英文 kebab-case(例:`adr-003-use-event-sourcing`)。
- 文件名编号必须与标题里的 ID 一致（`adr-003-*.md` ↔ `# ADR-003:`）——目录里靠文件名找,名字对不上就找不到。

## 不做索引

**主目录即名单**:`ls` 就是现役与在议的清单,`archive/` 就是历史。不维护 README 里的清单块,也不手写索引——同一份信息存两处,只有一处会漂(手写的在第一个忙周就漂;生成的多一个要同步的脚本)。

- 要"有哪些决策":`ls docs/decisions/`。
- 要某条是否现行:打开它,看 `status`。
- 要理由 / 被拒方案:打开对应文件,不靠清单跳转。

## 归档

被取代的记录**移进 `archive/`**,不留在本目录:

```
docs/decisions/
├── .ignore            # 让 archive/ 退出 rg 的默认检索面
├── README.md          # 读法(本文件)
├── adr-001-...md      # 现役 / 在议
└── archive/
    └── adr-000-...md  # superseded / deprecated / rejected
```

归档是**移动,不是删除**:历史只增不改,`superseded_by` 仍要能解析到目标（目标在本目录或 `archive/` 里都算）。

**整个 `docs/decisions/` 默认退出关键词检索面。** 理由是记录的性质:ADR 是日志——连现役记录也只是「当时的陈述」,关键词命中的它**不是现行规则**。所以在 `docs/.ignore` 排掉整目录:

```
decisions/
reviews/
```

- **入口不在搜索,在目录**:问"有哪些决策"就 `ls` 本目录——这条路不受 `.ignore` 影响。历史本来就不该靠 grep 撞见,也不该靠正文里的指针才找得到;L1 的「活文档索引」有一行说明这个目录管什么,够了。
- 考古:`rg --no-ignore 关键词`,或直接 `rg 关键词 docs/decisions`(指定目录时父级 `.ignore` 不生效,这是有意的)。
- **已知的洞:** `git grep` 不认 `.ignore`,也没有排除开关;IDE 全局搜索要各自配 `search.exclude`。
- **最小方案**(项目坚持现役 ADR 可搜):只排 `archive/`——在 `docs/decisions/.ignore` 写一行 `archive/`(必须放这个目录里,放仓库根会漏)。此时现役 ADR 提到退役术语仍会被搜到,只能靠记录自带状态兜。
