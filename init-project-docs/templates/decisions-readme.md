# Architecture Decision Records (ADR)

本目录是**决策工作台**,不是档案库:只放**在议 / 仍在执行链上 / 理由尚未升格**的记录。决策稳定后,把仍成立的理由写进对应的现状文档,本文件退役(移出工作区,git 保留)。

每条 ADR 一个文件,按编号递增。

> **规则正文归属:** ADR 的**触发粒度、记录寿命与推翻时的联动义务**是跨领域规则,唯一正文归属是 `docs-templates/evolution-rules.md`(随项目落地;L1 的「活文档索引」里列一行)——**何时记见 E4,寿命见 E4「记录寿命」,推翻决策的联动义务见 E3**。本文件只讲 ADR 自身(为什么记 / 读取顺序 / 格式 / 命名 / 退役),不重述那些规则。

## 为什么记 ADR

- **决策的"为什么"比"是什么"更重要**——代码能读出做了什么,读不出为什么
- **被拒方案要记"为什么不"**——记下"考虑过 X 但拒绝了，因为 Y"，防止后续重复踩坑
- **AI 协作的约束记录**——只能用于**追溯过去轨迹**（"当时为什么这么定"）；不得用来主张"现在必须 / 不能这么做"
- **记录有寿命**——ADR 是决策过程的载体,不是长期档案:稳定后升格或退役(见 E4「记录寿命」)

**但记录会被当成指令。** Agent 读到一段记录,不会自动知道它是哪一年的、还有没有效;它会照着做。所以每条记录必须**单独看也自带状态**,被取代 / 前提消失的记录必须**离开工作区**——主目录就是在议与在途,退役记录在 git 里。

## 给 Agent 的读取顺序

1. **先 `ls` 本目录**——主目录里的文件就是在议与在途;退役记录不在工作区,用 `git log -- docs/decisions/` / `git show <sha>:docs/decisions/<file>` 找回。本文件只讲读法,不列清单——目录本身就是名单。
2. **需要理由 / 被拒方案时**再打开对应记录,打开后**先看 frontmatter 的 `status`**。
3. **`status` 不是 `accepted` / `accepted(修订)` → 不是约束**,只作历史参考。
4. 记录正文是**当时的陈述**（过去时）,不是现状;现状以代码与 `docs/` 下的现状文档为准。

**三个常见误读**（记录本身不会提醒你）:

| 误读 | 正确读法 |
|---|---|
| 把「考虑过的方案」里的被拒方案当成结论 | 结论只在 `## 选择`;被拒方案必须带着「被拒」读 |
| 把原文里的参数当现值 | 参数取**日期最新的「补充」**——原文 append-only,故意不改 |
| 把 `superseded` / `expired` 的记录当约束 | 先看 `status`;两类都只是历史,且都已退役 |

## ADR 格式

每条 ADR = **frontmatter + 五段**:

```markdown
---
status: accepted
date: 2026-10-24
# superseded_by: ADR-012        ← 被取代时才有
---

# ADR-XXX: [决策标题——祈使句]

## 背景          为什么需要这个决策?把前提写成可判定条件
## 考虑过的方案   列出所有方案(包括被拒绝的),被拒的写「拒绝理由」
## 选择          选了哪个?为什么(不是"它最好",而是"在我们的约束下最合适")
## 后果          正面 / 负面后果;需要跟进的
```

- **状态取值:** `proposed` / `accepted` / `accepted(修订)` / `deprecated` / `rejected` / `superseded` / `expired`。`superseded` 必须带 `superseded_by: ADR-XXX`;`expired` = 前提消失、没有继任决定。**两者都退役**;不在这个集合里的写法（如 `approved`）等于没写状态,读者会按未知处理。
- **关系字段:** 继任记录声明**正向链接** `supersedes` / `revises` / `extends`;现役记录之间仍只声明一次。退役记录不再要求可解析的反向链接——正向链是唯一保留下来的关系。
- **句式:** 写「当时决定用 X（约束：…）」,不写「本项目使用 X」。记录会被单独引用,语法上就不能像一条现行规则。
- **可选第六段「修订 / 补充」(append-only):** 同一决策内的修正用带日期的补充追加在文末,不改原文、不新建 ADR;换掉被选方案本身 → 新 ADR（`superseded`）。
- **长度:** 超过 800 词会被警告——通常是两条决策,或一份实现日记（日记归 PR）。

模板见 `docs-templates/adr-template.md`;填好的完整示例见 `docs-templates/adr-example.md`。

## 命名规则

```
adr-XXX-[短描述].md
```

- `XXX` 是零填充的递增编号(001, 002, ...);编号不复用,删掉的也不回收。
- 短描述用英文 kebab-case(例:`adr-003-use-event-sourcing`)。
- 文件名编号必须与标题里的 ID 一致（`adr-003-*.md` ↔ `# ADR-003:`）——目录里靠文件名找,名字对不上就找不到。

## 不做索引

**主目录即名单**:`ls` 就是工作台的清单;退役记录在 git 里,用 `git log -- docs/decisions/` 看。不维护 README 里的清单块,也不手写索引——同一份信息存两处,只有一处会漂(手写的在第一个忙周就漂;生成的多一个要同步的脚本)。

- 要"有哪些决策":`ls docs/decisions/`。
- 要某条是否现行:打开它,看 `status`。
- 要理由 / 被拒方案:打开对应文件,不靠清单跳转。

## 退役

记录不再约束当下时**移出工作区**,不是移进另一个目录:

```
docs/decisions/
├── .ignore            # 让本目录退出 rg 的默认检索面
├── README.md          # 读法(本文件)
└── adr-001-...md      # 在议 / 在途
```

- **为什么不是 `archive/`**:归档只换路径,`rg` / `git grep` 照样命中(实测见 skill 侧 `search-surface.md`)。退役 = 让字节离开工作区,这是唯一能改变"搜到什么"的做法。
- **git 保留**:`git log -- docs/decisions/` 看名单,`git show <sha>:docs/decisions/<file>` 取回。退役不是删除。
- **退役前**:按 E4 三问——仍约束且现状读不出 → 先把理由升格进 `[为什么]` / 不变量;再移走文件。继任记录写 `supersedes: ADR-XXX`。
- **`superseded` vs `expired`**:被新决定替代 → `superseded`;前提消失、没有继任决定 → `expired`。两者都退役。
- **非 git 项目不退役**:标 `expired` 留在原处(读的时候按 `status` 跳过),靠 `docs/.ignore` 退出检索面;没有恢复手段。
- **不做摘要 / 索引**:不要写 SUMMARY 文件或历史清单——第二处出处必然漂。

**整个 `docs/decisions/` 默认退出关键词检索面。** 理由是记录的性质:ADR 是日志——连现役记录也只是「当时的陈述」,关键词命中的它**不是现行规则**。所以在 `docs/.ignore` 排掉整目录:

```
decisions/
reviews/
```

- **入口不在搜索,在目录**:问"有哪些决策"就 `ls` 本目录——这条路不受 `.ignore` 影响。历史本来就不该靠 grep 撞见,也不该靠正文里的指针才找得到;L1 的「活文档索引」有一行说明这个目录管什么,够了。
- 考古:`rg --no-ignore 关键词`,或直接 `rg 关键词 docs/decisions`(指定目录时父级 `.ignore` 不生效,这是有意的)。
- **已知的洞:** `git grep` 不认 `.ignore`,也没有排除开关;IDE 全局搜索要各自配 `search.exclude`。**退役(移出工作区)是唯一能挡住 `git grep` 的做法。**
- **最小方案(项目坚持现役 ADR 可搜):** 不排本目录,只靠记录自带 `status` 与 L1 解读;退役记录已不在工作区,不构成残留。
