# AIGC降重经验记录

## 概述

中文论文AIGC检测降重。核心思路：**AIGC检测器看的是深层统计特征（句长方差、段落模板、句式多样性），不是表层词汇。** 浅层同义词替换无效，必须动句子骨架。

---

## 工具链

### thesis-docx CLI（核心工具）

```bash
# 读取文档结构（获取段落索引）
python cli.py read-structure "论文.docx"

# 读取统计
python cli.py read-stats "论文.docx"

# 按章节读内容
python cli.py read-section --title "章节名" "论文.docx"

# 搜索关键词
python cli.py search --query "关键词" "论文.docx"

# 替换整段
python cli.py replace-text --paragraph N --text "新内容" "论文.docx"

# 批量替换（高效，推荐）
python cli.py replace-batch-by-index --pairs-file pairs.json "论文.docx"
# pairs.json 格式: {"43": "新文本", "49": "新文本"}

# AI风格检测
python cli.py check-style "论文.docx"

# 段落长度检查
python cli.py check-paragraphs --threshold 200 "论文.docx"

# 备份
python cli.py replace-batch-by-index --pairs-file pairs.json --backup "论文.docx"
```

### 辅助脚本

| 脚本 | 用途 |
|------|------|
| `detect_colors.py` | 检测docx中红/黄色标记文本（颜色值可配置） |
| `roundtrip.py` | CN→DE→CN / CN→EN→CN 往返翻译（含截断检测） |
| `clear_colors.py` | 清除docx中红/黄色文字标记为黑色 |
| `check_length_diff.py` | 比较改写前后段落字数偏差（超±5%报警） |

## AIGC检测器识别的特征

| 特征 | AI文本表现 | 真人文本表现 |
|------|-----------|------------|
| **句长方差** | 每句25-45字，非常均匀 | 长短悬殊（3-5字短句和60+字长句混用） |
| **段落骨架** | "主题句→展开→总结"三段式 | 结构多变：结论前置、设问开头、数据垫后 |
| **段落开头** | 教科书中立定义句 | 设问、数据、背景铺垫、直接给结论 |
| **段落结尾** | 每段必有总结句 | 有时戛然而止，有时自然引出下段 |
| **连接词** | "首先其次最后""一方面另一方面" | 自然过渡，甚至不用连接词 |
| **主观色彩** | 零，纯客观陈述 | "值得注意""不难看出""有趣的是" |
| **列举模式** | "第一第二第三""其一其二其三" | 直接用内容自身组织 |
| **套路开头** | "近年来""随着""本文研究了" | 直接切入具体内容 |

## 降重策略（按效果排序）

### 策略1：德文往返翻译 CN→DE→CN ⭐⭐⭐⭐⭐

**原理**：中文SVO（主谓宾）→ 德语V2/SOV（动词第二位/从句尾动词）→ 强制中文重新组织句子。

**效果**：句子骨架被彻底重构，语序反转。

**副作用**：技术术语可能跑偏，需要手动修正。

### 策略2：英文往返翻译 CN→EN→CN ⭐⭐⭐

**原理**：中英翻译模型训练数据量大，变化不如德文路线强，但对技术术语友好。

**适用**：技术性强的段落（公式、参数、方法描述）。

### 策略3：手动结构改写 ⭐⭐⭐⭐⭐

**原理**：针对段落骨架做手术，消除AI特征。

**具体做法**：
1. 删掉"近年来""随着"等套路开头
2. 把"首先其次第三"改为自然过渡
3. 长短句交替（短句3-10字，长句50-80字）
4. 每段结尾不一定总结
5. 开头可以设问、数据、直接结论
6. 注入"说白了""有意思的是""不难看出"等自然表达

**🚨 关键原则：段落长度不能缩！**
- 改写只改标记的句子/短语，**保持原段落长度和内容量不变**
- 不要整段重写缩短，否则论文字数会大幅缩水
- 每段改写前后字数偏差控制在 ±5% 以内

**示例对比：**

```
原文: "近年来，XX技术的迅速发展为YY领域开辟了新的途径。"
改写: "XX近几年发展很快，给YY领域带来了新思路。"

原文: "第一，大部分研究集中在A上...第二，B这块各家用各家的方法..."
改写: "大部分研究集中在A上。另外B各家用各家的方法。还有模型为了精度把网络搞太复杂。"
```

## 完整工作流

### 阶段1：分析

```bash
# 1. 查看文档结构
python cli.py read-structure "论文.docx"

# 2. 运行颜色检测脚本获取红/黄标记段落
python detect_colors.py "查重报告.docx" -o colors.json

# 3. 运行AI风格检测
python cli.py check-style "论文.docx"

# 4. 查看段落长度分布（AI文本段落长度过于均匀）
python cli.py check-paragraphs --threshold 150 "论文.docx"
```

**⚠️ 查重报告一旦处理完可能丢失，务必尽早跑 detect_colors.py 保存 colors.json**

### 阶段2：处理红色段落（强力改写）

```bash
# 1. 用德文往返翻译
python roundtrip.py colors.json -o pairs_de.json --route de --target red

# 2. 手动检查术语偏差（人名、专业术语）
# 常见问题：术语被翻译跑偏、人名罗马化、[数字]格式混乱

# 3. CLI批量写回
python cli.py replace-batch-by-index --pairs-file pairs_de.json --backup "论文.docx"
```

### 阶段3：处理黄色段落（轻量改写）

```bash
# 1. 英文路线翻译黄色段落
python roundtrip.py colors.json -o pairs_en.json --route en --target yellow

# 2. 批量写回
python cli.py replace-batch-by-index --pairs-file pairs_en.json "论文.docx"
```

### 阶段4：清颜色 + 复查

```bash
# 1. 清除文档中残留的红/橙色（方便肉眼核对是否全部改写）
# 将 F12828/F39800 颜色的文字设为黑色

# 2. 重新检测AI风格
python cli.py check-style "论文.docx"

# 3. 针对剩余问题逐段手工改写
python cli.py replace-text --paragraph N --text "新文本" "论文.docx"

# 4. 检查总字数，确保没有大幅缩水
python cli.py read-stats "论文.docx"

# 5. 循环直到颜色为0 + check-style 0新增
```

### 阶段5：AI生成内容段落改写

针对**新增的AI生成章节**（非抄袭，是AI撰写的原创内容）：

1. 查重系统不会标红（不是抄袭），但AIGC检测器会识别
2. 改写策略：句式重构 + 删除套路开头 + 注入自然表达，注意**保持段落长度**
3. 不要整段压缩，否则论文字数会明显减少

## 翻译API注意事项

### MyMemory API

- 免费版单日配额有限（约1000次请求）
- 每次请求限制500字符，长文本需分句分段
- 超限时返回HTTP 429
- **绕过配额限制**：每次请求用不同email参数 `de=userXXXX@temp.com`
- **429后可用之前跑过的翻译结果复用，不必干等**

### 各语言路线效果对比

| 中间语言 | 变化力度 | 术语保留 | 适用场景 |
|---------|---------|---------|---------|
| 德语(DE) | ⭐⭐⭐⭐⭐ | ⭐⭐ | 摘要、引言、非技术描述 |
| 韩语(KO) | ⭐⭐⭐⭐ | ⭐⭐⭐ | 一般段落 |
| 日语(JA) | ⭐⭐⭐ | ⭐⭐⭐⭐ | 与中文共享汉字，变化有限 |
| 英语(EN) | ⭐⭐ | ⭐⭐⭐⭐⭐ | 技术段落、公式描述 |

## 常见问题Fix清单

### 翻译后必查项

| 问题类型 | 表现 | Fix |
|---------|------|-----|
| 人名 | 被翻译或罗马化 | 还原为原文 |
| 专业术语 | 被直译（如"卷积"→"折叠"） | 改回正确术语 |
| 引用标记 | [数字] 格式混乱或丢失 | 恢复正确格式 |
| 重复词 | 翻译后出现同词重复 | 去重 |
| 截断 | MyMemory 500字符限制导致句子不完整 | 重新翻译或手动补齐 |
| 声明/法律文本 | 措辞被改变 | 必须恢复原文，不能翻译 |

### 模板句替换

| 原文模板 | 改写建议 |
|---------|---------|
| 近年来，...迅速发展 | XX在近几年发展很快... |
| 本研究的主要内容如下 | 核心工作集中在... |
| 第一/第二/第三 | 用"另外""还有""同时"替代，或重新组织 |
| 综上所述 | 直接给结论或省略 |
| 本文围绕...展开 | 直接说做了什么 |

## 关键教训

### 段落长度不可压缩

因整段重写时大幅压缩段落长度，导致论文字数明显缩水。

**正确做法**：改写只动被标记的句子/短语，不动段落骨架长度。每段改写前后字数偏差控制在 ±5%。

### 查重报告要提前保存

查重标红版文档在处理过程中可能会丢失，一旦拿到就要立即跑 `detect_colors.py` 保存结果。

### 声明等法律文本不能动

诚信声明、授权书等段落有固定法律措辞，不能用翻译改写，必须保持原文。

### WPS文档样式ID特殊

WPS创建的文档中，Heading 1 的 styleId 可能是数字 "2" 而非 "Heading1"，插入新段落时需要注意匹配文档自身的样式ID体系。
