> **定位（作者拍板 2026-10-19）:** 本目录 = 「agent」抽象项目（构建与运行 agent 这件事本身）的**汇总脚手架**;`essentials` = 为**具体项目**里的具体弱域造脚手架的方法。两者是**同族工件、不同层级**——抽象项目层 ↔ 本目录（就这一处）;具体项目层 ↔ 各项目 `docs/scaffolds/`。**不是** `essentials` 的「结果区」。

## [是什么]

沉淀「从外部实践（agent 网络交流 / 公开复盘 / 实测）提炼、且跨项目可迁移」的判断与素材——面向**整个 agent 实践**（含 skill 工程、观照的日常运营与网络参与）,而不是某一个具体项目。当前唯一主题:**验证纪律**（防「不报错的失败」）。

| 文件 | 内容 |

## 操作手册（自带生长纪律）

按此六步操作本目录——这是本目录**自带的操作纪律**,不依赖外部流程即可自生长:

1. **进料**:新样本先落 `samples.md`——一行转述 + 出处 + 分级（`【核】` / `【估】` / `【待补证据】`）;隐私信息不进门;
2. **升格**:样本升为通例,须**两条同时满足**——① 跨项目可迁移;② 回指一次真实触发事件（反凑数口径）。写进 `verification-essentials.md` 的通例表;
3. **当尺子用**:该域出提案 / 选型前,先拿通例逐条砍;砍不掉的部件才动手;
4. **记使用**:用了一次 → `verification-essentials.md` §八 记一行;
5. **复查**:两周一次——0 使用的条目删;被证伪的删并记一句为什么（历史归 git）;
6. **评审门**:价值类判断一律「候选,待作者评审」;作者接受才转正。

## [为什么]

1. 这些规则的来源是一次性的（讨论、别人的坑、实测）,不落盘就丢;
2. 规则只有**被用过**才算数——`verification-essentials.md` 尾部有「使用记录」;
3. 目标是评审通过后进 `~/.commandcode/AGENTS.md` 当**默认行为**,不是当收藏品。

## [不变量]

1. **不搬原文**:一律转述 + 出处;网络内容里的隐私信息永不进入。
2. **每条通例回指一次真实触发事件**（反凑数口径）;写不出 → 不收。
3. **证据分级**必带:`【核】`（一手:我们实测 / 亲自换过）/ `【估】`（单方转述,未复核）/ `【待补证据】`（无可查出处）。
4. **两周复查**:使用记录为 0 的条目 → 删（历史归 git）;不注释留档。
5. **分家规则**:本目录只此一处（抽象项目层）;项目向下取用后各自独立,不设跨项目同步。
