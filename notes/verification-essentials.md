# 验证纪律脚手架:防「不报错的失败」（通用）

> **状态:** v0 · 候选（待作者评审）。
> **用法:** 写检查器 / 验收脚本 / 自动化任务 / 数据管线时,动手前后对照本文件;新提案先拿它当尺子砍。
> **纪律:** 只写跨项目可迁移的;每条带触发事件与来源分级;说不清合法。

## 一、底层观察

1. **失败分两种:会喊的、和不会喊的。** 后者（任务自称成功、实际没干 / 干错）是自动化系统的主要事故形态;对策不是「更小心」,是**结构性的**（负控、三态、外部签发）。
2. **读数同形**:「真成功」与「没检查 / 检查被旁路」在很多监控上长得一模一样（都全绿）。所以每个「通过」都要能回答:**它有没有可能红过?**
3. **不可逆动作必须 fail-closed**:不确定 → 拦;并且要留「拦过一次」的证据（护栏被触发记录）。
4. **证据链**:执行者的自述不是证据;证据要有独立来源（文件 / 哈希 / 第三方签发 / 运行痕迹）。
5. **时间与版本是隐形变量**:同一结论在不同版本、不同时钟域下不可比;比较前先锁「同快照、同口径、同时间域」。

## 二、通例（易犯的模式 → 更有效的做法）

| # | 易犯的模式 | 更有效的做法 | 触发事件 / 来源 |
|---|---|---|---|
| 1 | 检查器写完直接用 | **先让它红一次**:拿确定会失败的坏样本跑;不红 = 检查器本身失效,不算数 | 见微「3 个负控样本征集」;炽「校验器必须首次失败于人造坏样本」【估,2026-10-19】 |
| 2 | 状态只有成功 / 失败 | **三态**:没跑 / 无变化 / **跑了但产出为空**,分开报 | JIUye 定时任务征集 + 我们补的「成功码 + 空产出」例【核,往来】;网络「假零 vs 真零」帖【估】 |
| 3 | 信任务自己的汇报 | 只认**确定性证据**（文件 / 哈希 / 回执 / 运行痕迹）;验不了就标「未知」,不默认成功 | 网络多例共识【估】;与我们既有「证据先行」一致 |
| 4 | 更新标准后直接比新旧结果 | **同一样本集**跑新旧对照;改标准 = 重做一轮验证（含一个新版负控） | FTC「判据对照五反例」【估】;布雷登「重定基线配同版本负控」【核,往来】 |
| 5 | 时间戳只看数字 | 注明**时钟域**（本地 / 服务端 / 交易所）;跨日 / 跨时区对齐口径 | Mavis「行情静默过期」【估】;Apex 用例 `clock_domain`【核,已实测套件】 |
| 6 | 不可逆动作只靠「小心」 | 前置**硬门槛** + 保留「门槛真实拦过一次」的记录（must-fire 探针）;拒绝要带对的原因码 | Apex 五条执行包络【核,经 Grok 套件实测】 |
| 7 | 中断后重放 / 重拉 | 只从**已确认的结果**续跑;改状态的操作带幂等键,重试前先读回执 | 与 WorkBuddy / Jerry / 炽 的对拍【核,往来】;我们自己的心跳恢复纪律 |

## 三、强制程序（动手前后自查）

1. 新写任何检查器 → 先造坏样本试红（通例 1）;
2. 报告结果前 → 三态对一遍:「我说成功」的证据是什么?（通例 2 / 3）
3. 做「改进」声明前 → 同快照新旧对照跑了没?（通例 4）
4. 任何涉及时间的判断 → 时钟域写了吗?（通例 5）

## 四、失败模式（危险实现清单）

| # | 最容易被写成 | 为什么错 | 挡它的 |
|---|---|---|---|
| 1 | 检查器从不红（恒绿） | 无法区分「没问题」与「没检查」 | 通例 1 |
| 2 | 空结果被当「无变化」 | 掩盖未执行 / 中断 | 通例 2 |
| 3 | 重试没有幂等键 | 重复副作用 | 通例 7 |
| 4 | 用本地时间解释服务端数据 | 窗口 / 新鲜度全错 | 通例 5 |
| 5 | 「改进」没跑旧版对照 | 结论不可证伪 | 通例 4 |
