# 版式库与信息密度脚手架:一页一个结论,原型轮换

> **状态:** v0 · 候选(待作者评审)。
> **用法:** 设计 / 审查信息型 deck 的**版面结构**时先加载:定页型、排页序、加装饰之前,逐条对证本文件(判别"丰富"与"堆砌")。
> **纪律:** 只写跨项目可迁移的;每条带来源分级(`【核】` / `【估】` / `【待补证据】`);"说不清"合法。

## 一、底层事实 / 观察

1. **版式是思考工具,不是模板**:先写出一页要读者得出的**结论句**(action title),再选能证明它的版式;顺序反了就会"对着空白页排 3 小时"(StrategyU 作者自述)【估】。
2. **读者是扫描的**:标题链 + 图形先于正文;只看标题应能复述全篇论点(Deckary:MBB 实践)【估】。
3. **原型是有限的**:咨询业约 90% 的页可归入 ~14 种原型——大数字 / 柱图 / 图+解读 / 双栏对比 / 三支柱 / 流程 / 瀑布 / 漏斗 / 2×2 / 记分卡 / 引用+证据 / 时间线 / 仪表盘 / 执行摘要(StrategyU)【估】。选原型解决的是信息结构,不是装饰。
4. **两种失败对称**:一页一个 bullet = 提纲不是页;12 步流程图 = "装成 slide 的文档"(StrategyU process-flow 条目)【估】。原型自带容量上限。
5. **"丰富"的构成 = 单页组件密度 × 信息具体度**(作者语境,2026-10-19 二次指正):一页同时在场 3+ 个模块(数据 / 图例 / 标签 / 注释 / 注脚 / 小部件),呈现"信息图 / 咨询 exhibit"感;**"一页一信息"约束的是信息主线,不是模块数量**。原型轮换解决的是全篇节奏,但每页只有一型 = 稀疏页,不算丰富。【核:作者反馈】
6. **图表默认柱状**:面积 / 角度难比较(McKinsey 弃用饼图的转述)【估】;环形 / 仪表只在传达"占比感 / 状态"时用,读数值仍用柱。
7. **数据页必须有 so-what**:图 + 解读框(指向具体数据点),否则"同图不同结论"(StrategyU #3)【估】。
8. **引用页 = quote + evidence**:单引用是轶事,单数据是抽象;配对才成立(StrategyU #11)【估】。
9. **装饰不得承载信息**:氛围层只用几何 / 纹理,不写低对比文字;信息文字只用角色色(本项目 typography + 目检收敛经验)【核:2026-10-19 收敛轮】。
10. **页序有节奏**:封面 → 执行摘要 → 论证页群 → 收尾;论证页群内同型不连排;过渡页(分隔)一 deck 0–2 个,多了是碎【估】。

## 二、通例(易犯的模式 → 更有效的做法)

| # | 易犯的模式 | 更有效的做法 | 触发事件 |
|---|---|---|---|
| 1 | 先排版再想结论 | 先写一行**结论句标题**(完整句、带判断);写不出 = 内容没想清 | Deckary action-title;StrategyU 自述慢页 |
| 2 | 一页多个论点 | 一页一信息;第二论点另起页 | Deckary "one message per slide" |
| 3 | 12 步流程图 / 满页文字 | 步骤 ≤5;超出就分阶段或进附录 | StrategyU process-flow |
| 4 | 单值埋在 14 个数字里 | **大数字页**只放大那一个值 + 一行语境,其余进下一页 | StrategyU #1 |
| 5 | 只放图不解读 | **图 + 解读框**,指向具体数据点;解读必须是句结论 | StrategyU #3 |
| 6 | 饼图 / 面积图做比较 | 比较用柱;环只传达占比 / 状态 | StrategyU #2(转述 McKinsey) |
| 7 | 全篇同一种卡片网格 | **原型轮换**(连续 ≥3 页不同型)+ 尺度对比;bento 式尺寸差表达优先级 | 本项目触发:11 页卡片阵列仍被作者判"不够丰富"【核 2026-10-19】 |
| 8 | 装饰文字 / 低对比水印当氛围 | 氛围层只用几何与纹理;**任何可见文字都按信息层配色** | 本项目 C5 会拦低对比文字【核:tests/】 |
| 9 | 引用无据 / 数字无源 | quote+evidence 配对;数字带来源行(本技能字号下限 10pt,来源行用 10–12pt) | StrategyU #11;Deckary source rule |
| 10 | 收尾只写"谢谢" | 收尾给**行动项 / 清单指针**(下一步做什么) | 本项目 acceptance-checklist 惯例【核】 |
| 11 | 全页元素同权重 | 每页**一个视觉焦点**(大数字 / 图 / 标题),其余降级为注脚或次级色 | StrategyU #1 / #3;Deckary bold-bullet |
| 12 | "丰富" = 元素多 | 丰富 = 单页组件密度 × 信息具体度;元素多是结果不是目标 | 作者两轮反馈"要看起来有很多东西组成 → 不够丰富"【核 2026-10-19】 |
| 13 | 每页只有一种模块(大留白极简) | **每页 ≥3 个模块同时在场**(结论 + 证据模块 + 元信息:来源 / 页码 / 标签),并给具体数字与出处 | 作者二次指正:"不懂这个语境里'丰富'的含义"——v0.1 据此修订【核】 |

## 三、强制程序(动手前后自查)

1. **一句话标题**:每页写结论句标题;写不出 → 回到内容,不排版。
2. **选原型**:对照 14 型清单选一型;一页不混两型;同型不连排。
3. **容量检查**:流程 ≤5 步;KPI ≤6 块;表格 ≤8 行(记分卡类可到 9–10);超限 → 拆页 / 附录。
4. **三层检查**:信息层 / 图解层 / 氛围层是否分离;氛围层有无文字。
5. **数据 / 引用页**:so-what 有没有;来源行有没有。
6. **出图后**:先跑 `qa_check --strict`,再按 [visual-quality-ledger.md](visual-quality-ledger.md) 的视图目检(焦点 / 对齐 / 留白节奏;旧文已冻结)。

| # | 最容易被写成 | 为什么错 | 挡它的 |
|---|---|---|---|
| 1 | 全篇一种网格 | 单调,读者失去方位感 | 通例 7 |
| 2 | 12 步流程图 | 文档冒充 slide | 通例 3 |
| 3 | 低对比装饰文字 | 被 C5 拦;且抢注意力 | 通例 8 |
| 4 | 大数字页塞满佐证 | 焦点稀释 | 通例 4 / 11 |
| 5 | 图无解读 | 各人自取结论 | 通例 5 |
| 6 | 引用页只有金句 | 轶事当证据 | 通例 9 |
| 7 | 每页多结论 | 记忆负担 | 通例 2 |
| 8 | 堆小卡片当"丰富" | 噪声;层次消失 | 通例 12 |
