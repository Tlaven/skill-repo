# 《AI 生成 PPTX 的交付验收》— 8 页页面规划

**设计前提(先说明假设)**

- 受众:内部工程团队(生成器 / 模板 / 流水线维护者),30 分钟评审。
- 决策目标:批准把 C1–C9 接入生成流水线,并把"交付前必跑"写进交付定义;这不是"分享一套检查清单"。
- 阈值一律标注为**建议默认值,须用干净基线校准**;全书不引用任何未经实测的统计数字,需要"证据"的地方用 7 个负控样本的离散事实(7/7、0)说话。
- 这份 deck 本身必须通过它自己倡导的断言,因此在全局刻度里锁死字号下限与色板总数。

**全局视觉系统(页面表中,间距、层级、强调色、收口四类的简写都指此表)**

- 画布 16:9(13.333×7.5in),版心边距 0.75in,安全区 0.5in;12 列栅格,列间距 24。
- 间距刻度:只用 8 的倍数 —— 8、16、24、40、64;禁止 12、20、36 等刻度外的值。
- 字阶:H0 64(只用于数字)/ H1 40 / H2 28 / 正文 20 / 表格 16 / 注 14。**14pt 为全 deck 硬性下限**(自证 C3)。
- 色板 6 色:墨 `#1A1A1A`、深灰 `#4D4D4D`、浅灰 `#9A9A9A`、底灰 `#F2F2F2`、纸白 `#FFFFFF`、朱红 `#C0392B`(自证 C4:色板总数 ≤ 6)。
- 红色只有两个语义:**阻断**、**失败回流**;每页红色出现不超过 1 处,且不用于装饰性下划线以外的填充。
- 收口统一:每页右下角一行 14pt 深灰"所以呢"句,单行、不超过 28 字。

## 2. 三个最容易做错的视觉 / 版式判断

**① 九类断言按 3×3 矩阵平铺,还是按列分三层?**
选择按列分三层(文件层 / 视觉层 / 产出层)。平铺会让 C1–C9 读成九个并列项,丢掉"分层执行"的语义,而后面的清单页正是按层实施;分层也解释了为什么 C3 字号和 C9 可编辑性必须分开处理。

**② 把 9 行阈值表塞进一页,还是拆页?**
选择一页 9 行、但砍到 4 列并把字号锁在 16pt。为了塞下而降到 12pt 以下,等于这份讲"字号下限"的 deck 当众违反自己的 C3;宁可删列(判定方式并入判定量),也不删字号。

**③ 负控结果做成仪表盘/百分比,还是二进制记分板?**
选择 7 格二进制记分板 + "误报 0"。7 个样本支撑不了比率叙事,仪表盘会暗示统计置信度;而且"7/7 全中 + 0 误报"本身是离散事实,越朴素越可信。

## 3. 交付前我会跑的 3 个检查(断言式,跑在这份 deck 自身上)

**检查 1 — 字号下限(C3 自检)**
断言:`∀ text run r:sz(r) ≥ 1400`(14pt),且 `∀ 正文文本框 b:min sz(b) ≥ 1800`(18pt)。
判定:违规 run 数 = 0 才通过;仅 `ftr-` 前缀的页脚/来源框豁免至 14pt。
执行:解包 `slide*.xml`,取所有 `a:rPr/@sz` 与 `a:defRPr/@sz` 的最小值,期望 ≥ 1400。

**检查 2 — 安全区与越界(C7 自检)**
断言:`∀ shape s:x ≥ 0.5in ∧ y ≥ 0.5in ∧ x + w ≤ W − 0.5in ∧ y + h ≤ H − 0.5in`,且 `∀ s1, s2 ∉ bg-:area(bbox(s1) ∩ bbox(s2)) = 0`。
判定:越界元素 = 0 **且**非法重叠对 = 0 才通过(允许重叠仅限 `bg-` 前缀背景层)。

**检查 3 — 色板与对比度(C4 + C5 自检)**
断言:`|{填充色 RGB} ∪ {文字色 RGB}| ≤ 6`;且 `∀ text run:contrast(fg, 底层填充) ≥ 4.5`,大字(≥ 24pt 或 ≥ 18.66pt 加粗)≥ 3.0(WCAG 相对亮度公式)。
判定:超出色板 = 0 **且**对比度不达标 run = 0 才通过。
只有三条全过,才允许导出 PDF 并签字交付;任意一条失败即退回修改,不进入"目检"环节。

**说明与取舍**:页 4 的阈值全部是建议默认值、须由干净基线校准;页 2 / 页 5 刻意回避了任何未经实测的统计数字。
