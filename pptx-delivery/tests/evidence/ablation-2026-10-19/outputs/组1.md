## 结论

8 页按「问题 → 体系 → 自证 → 落地 → 收口」五段推进,主线是一条**闸门**(每页只回答一件事:哪条不过就停)。版式不连排同型:双栏 → 九宫格 → 大数字 → 矩阵 → 四格 → 清单 → 流程。全篇只有 1 个语义色,正向结论一律不上绿。

**前提假设:** 场景定为「阅读型交付 + 现场只翻标题链」的内部工程评审(会后传阅),因此正文 16pt 而非放映型 18–24pt;若改现场放映,只把正文提到 20pt、注脚提到 12pt,其余刻度不动。

**全篇统一基线(下面表格的“视觉处理要点”列的取值都取自此)**

- **间距刻度:** 只用 8 / 16 / 24 / 40 / 64。组内 8–16、组间 24–40、页边距 左右 64 / 上下 40。
- **文本层级(浅底 4 级):** L1 标题 24/700 `#111` · L2 正文 16/400 `#333` · L3 次级 11/400 `#555` · L4 注脚 10/400 `#777`。**不出现第五种灰**。大数字 72 算“尺度焦点”,不计入层级。
- **强调色:** 深红 `#B42318`,语义只等于「不过/停/闸门」,每页 ≤1 处、全 deck ≤6 处;**不使用绿色**(正向结论靠尺寸与并置,不靠颜色)。
- **收口:** 内容页底部锚线统一 `y = 页高 − 40`,左起 64,10pt `#777`,格式「C#｜来源｜P.x」;末页不留“谢谢”,留一句下一步。
- **注意:** C3 的 10pt 是机器闸门的下限,不是设计目标;本 deck 设计目标为正 文 16pt / 注脚 10pt。

## 二、三个最容易做错的视觉 / 版式判断

1. **C1–C9 排成一行 9 个编号 chip(节奏好看)还是 3×3 + 三组组头。选 3×3。** 9 个 chip 单行必然把字号压到 8–9pt,这一页自己就先违反它要讲的 C3;分组把记忆单元从 9 个降到 3 个,编号仍可逐项查。
2. **负控页用红/绿双向标(抓到=绿、误报=红)。选只留一个“停”色,正向结论靠 72pt 与并置。** 红绿同框等于把验收页做成交通灯,而本 deck 第二节刚讲完颜色卫生与对比度——自己先违规,后面的断言就没有说服力。
3. **目检盲区页用 4 张真实翻车截图(“看起来有东西”)。选纯文字四格 + 动作行。** 截图会引入不可控的渲染差异,还可能自带低对比文字被自家 C5 拦;这页的价值是让人知道“去看什么”,不是展示车祸现场。

## 三、交付前我会跑的 3 个检查(可判定断言)

1. **文本层(C1 / C3 / C5,脚本可判):** `len(titles) == 8` 且每条标题为含判断词的完整句(不含“概述 / 背景 / 总结 / 谢谢”);`∀ 文本块 font_size ∈ {10,11,12,14,16,18,24,40,48,72} 且正文 ≥10pt`;`∀ 文本块 对比度 ≥4.5:1(≥18pt 或 ≥14pt 粗体 ≥3:1)`。任一为假 → 该页不过。
2. **几何与节奏(C7 + 收口):** `∀ 元素 bbox ⊆ 画布 −(左右 64 / 上下 40)`;`∀ 内容页 footer 基线 y 相同(±1pt)且左缘 64(±0.5pt)`;`∀ 页 focus_count == 1`;`∄ 连续 3 页 prototype 相同`。任一为假 → 不放行。
3. **交付语义(清单级,终局闸门):** 末页不含“谢谢”且行动项 ≥3、每条以动词开头;P7 三条命令在 CI 里 `exit code == 0`;负控 `caught == 7/7` 且 `clean_baseline_findings == 0`。**这条不过,前两条的“通过”不算数。**
