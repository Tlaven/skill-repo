# Essentials — 弱领域的外部脚手架

## 定位

产物是一份 **essentials 文档**(居所:`docs/scaffolds/<domain>-essentials.md`;模板见 `templates/essentials-doc.md`)。按实践,它的主力形态是**强制程序 + 本地标定**,不是知识汇编。

- **主路径:复盘蒸馏。** 每次实战之后,把"哪里会错、什么数值得住"沉淀成规则——这是常态,也是它真正产出的地方。
- **低频事件:前瞻审查。** 决策前读**决策卡**,逐条砍提案;指不回任何一条的部件,删或改(术语出现不算证据)。
- **价值位:一致性 / 交接。** 让作者与 agent、本会话与下个会话在同一套判断上工作——不是"单次会话的质量升级器"。判它用:重复解释次数、跨会话回归数、冷启动质量、使用记录里的被引用数。

**只收三类**:① **反先验事实**(资料推翻直觉);② **本地标定**(本项目实测 / 拍板,别处没有);③ **强制程序**(不做会出事的动作)。凭先验写得出的、搜一下就有的通用知识——不收,最多进「来源」指针。

**边界**:不写代码、不替作者拍板(价值类一律「候选,待否决」)、不产调研报告。

## 何时用 / 不用

**触发(任一):** 作者质疑可靠性("你可靠吗 / 这是你擅长的领域吗");作者点名;你要在先验可疑的领域给推荐(多个语义相近实现,或没有先验,且错了会静默扩散)。

**分诊三问(完整版需全过):**

| 问 | 答 | 处置 |
|---|---|---|
| ① 有唯一公认写法吗? | 有 | 直接做,不造 |
| ② 会重复出现吗? | 只此一次 | 轻量版:当场核证(带来源)+ 记入任务笔记 |
| ③ 赌注大吗? | 小 | 轻量版 |
| —— | ①没有 + ②重复 + ③大 | 完整版 |

**不该用:** 已有完善脚手架的领域(直接用,只做生长);纯执行任务;已被否决的方法(走 ADR / 否决记录)。
**强制动作:** 弱领域给推荐前,先给**可靠度声明**——①唯一公认写法 ②多个语义相近实现 ③没有先验;②③ 进分诊。

## 怎么写(五条)

1. **每条回指一次真实触发事件**(踩的坑 / 调研发现 / 事故);写不出 → 不收。
2. **标层**:`[通用]` 跨项目成立;`[本地]` 本项目实测 / 拍板。层决定这条能不能带走(见「生命周期」的复用)。
3. **执行化**:每条尽量落成 ① 可跑检查 ② 交付物里的必答项 ③ 强制步骤(留产物);落不成的标「观察项」(全文 ≤5 条)。
4. **搜集找"哪里会错"**,不是"该做什么":反例、冲突、代价、失败复盘;先例优先,挖透细节;来源标 `【核】/【估】/【待补证据】`,查不到出处的进「开放问题」,不写成事实。
5. **作者裁决与被拒方案**记在文档里(不设"作者经验"空槽);否决理由进 ADR。

## 文档生命周期

- **状态字段**:`活跃 / 冻结(域暂停,保留)/ 归档`。冻结不删;域复活先复核过时性。
- **决策卡**:红线清单 + 最近被引用最多的 ≤5 条(无引用时取前 5 条);决策时只读它。
- **到期删除**:两周或 N 次使用 0 触发 → 删条目(git 留史)。
- **转正**:有据可查的"因它改变"≥1 次;声称"产出更好"须做同任务对照(`references/ablation.md`)。
- **复用(可选)**:复制 `[通用]` 层 + 重审;`[本地]` 留在原项目;不设跨项目单源。

## 记录(两条线,都走引用,不手填)

- **生长**:版本表一行 = 触发事件 + 变更;提交信息写 `doc vX(Tn)`。
- **使用**:某决策因某条而改变时,在决策 / 任务笔记写 `<domain>#T<n>`;使用记录由这些引用汇总(grep)。
- 变更史归 git / ADR,不写进正文。

## 入口

- 居所唯一:`docs/scaffolds/<domain>-essentials.md`;**第一份落盘才建目录**(不预建空壳);从模板复制,填完删注释。
- 项目 L1 写一行"脚手架 → `docs/scaffolds/`",并在加载表加一行"进弱领域 → + `docs/scaffolds/`(相关的)"——只写不读等于没搭;具体登记习惯随项目。
- 正例:`references/sample.md`(标注了 `[通用] / [本地] / 观察项` 三种写法)。

## 红线(决策前扫一眼)

- ❌ 无来源条目 / 来源不标强度
- ❌ 收通用知识(凭先验写得出)
- ❌ 把 `[本地]` 条目复制到别的项目
- ❌ 决策时读长文而不是决策卡
- ❌ 「候选」当结论
- ❌ 没有引用记录就宣布有效

## 验收（teach-back）

- **档位:** teach-back（无确定性产物；验收 = 独立复核 + 可查引用）
- **流程:** 对一份新产出（或修订）的 essentials 文档，派一个**看不到本会话**的独立 agent，只给该文档 + 目标项目 L1 + 本 skill 的「怎么写」「红线」两节；产出：逐条对照五条写法与红线的缺口清单 + 判定（通过 / 不通过 / 需人拍板）。
- **可查证据:** ① 每条规则能回指真实触发事件；② 至少 1 条 `<domain>#T<n>` 引用（因它改变过决策），否则只能标「未转正」；③ 声称「产出更好」须按 `references/ablation.md` 做同任务对照。
- **留档:** 复核结论写目标项目 `docs/reviews/YYYY-MM-DD-<域>-essentials.md`。

## 演化

本 skill 按 `seeding-skills` 的纪律生长;复盘回改信号:分诊被跳过、文档 0 引用、示例被绕过、本地条目混进通用层、重复规则回流。
