# Essentials — 弱领域的外部脚手架

## 定位

给 agent 的**先验不可靠的领域**造一副外部脚手架。产物是一份 **essentials 文档**(居所:正在开发项目的 `docs/scaffolds/`;结构见 `templates/essentials-doc.md`)。三个用途,**缺一不算完成**:

1. **审查**(主用途):该域出提案 / 选型 / 推荐**之前**,先拿决策卡砍自己的提案;
2. **一致性 / 交接**:作者与 agent、本会话与下个会话、这个 agent 与下一个 agent,在同一套判断上工作——**这是它真正的价值位**;
3. **生长**:从实操摩擦中修订,随项目演化;同一领域在别的项目再次出现时,整份复制过去复用(可选)。

**别用错指标:** 它不是"单次会话的质量升级器"。作者全程在环时,边际差别可能不可见;判它用——重复解释次数、跨会话回归数、冷启动质量(新会话不给提示能不能做对)、使用记录里的"被引用决策数"。

**只收不可检索、且跨项目可迁移的判断。** 可凭先验写出、或搜一下就能得到的通用最佳实践,**不收**(零增量,只制造"词汇层合规")。收的只有三类:① **反先验事实**(资料推翻直觉);② **本地标定**(实测才有、别处没有);③ **强制程序**(不做会出事的动作)。文档开头是**决策卡**——决策时只读它;正文给复盘与生长看。

**不做什么:**

- 不替作者做**价值判断**(好不好玩 / 好不好看 / 手感 / 方向)——价值类一律标「候选,待否决」,作者是评审 oracle;
- 不做工程实现(本 skill 的产物是判断文档,不是代码方案);
- 不对「有唯一公认写法」的领域启动——直接做,造架子是浪费;
- 不产一次性调研报告,也不产"通用最佳实践合集"(后者只是检索结果摘抄);
- 不承诺"用了就更好"——没有"因它而改变"的记录时,如实说不知道。

## 何时用 / 不该用

**该用(触发,任一即进分诊):**

- 作者质疑可靠性:"你可靠吗?" "这是你擅长的领域吗?" "你懂这个吗?" ——**最高优先**;
- 作者点名:"做个脚手架 / 要领 / essentials";
- 你要在**先验可疑**的领域给推荐:该域存在**多个语义相近实现**(金额舍入、时区、权限边界、ID 生成、重试幂等、字符编码、渲染确定性、游戏手感与物理参数……),或**没有先验**,且判断错了会静默扩散。

**分诊(三问;完整版需三问全过):**

| 问 | 答 | 处置 |
|---|---|---|
| ① 该域有唯一公认写法吗? | 有 | 直接做,不造 |
| ② 会重复出现吗? | 只此一次 | **轻量版**:当场核证(带来源)+ 记入任务笔记 |
| ③ 赌注大吗? | 小 | 轻量版 |
| —— | ①没有 + ②重复 + ③大 | **完整版**:造脚手架 |

**不该用:** 已有完善 essentials 的领域(直接用,只做生长);纯执行任务(无判断空间);已知无效的方法(走否决记录 / ADR,不建新文档)。

**强制动作(没有触发词也要做):** 弱领域给推荐前,先给**可靠度声明**——该域先验属哪层:①唯一公认写法 ②多个语义相近实现 ③没有先验。分层不依赖"自知弱点",只需如实报告;②③ 进分诊。

## Workflow

1. **分诊**(上表 + 可靠度声明)。

2. **定范围**:列出这份脚手架要支撑的**判断清单**(将来拿它审什么);补**隐含需求**——作者没说、但显然要满足的要求,逐条列出,请作者确认或标「待确认」。

3. **外部搜集——找"哪里会错",不是"该做什么"**:
   - **目标反转**:搜集反例、冲突、代价、失败复盘、本项目实测;通用最佳实践只进「来源」节当指针,**不进正文**;
   - **先例优先**:作者点名的参考物(某产品 / 某文章 / 某作品),先挖透它的细节,从细节里取答案;不要拿抽象选项菜单向作者提问;
   - 来源优先序:官方文档 / 标准 > 权威社区实践 > 同类作品前例 > 真实用户报告(issue / 论坛 / 复盘);每条**附链接**;
   - **来源分级**:`【核】`有来源 / `【估】`推断(自估打折看,注明) / `【待补证据】`弱来源;查不到出处的 → 进「开放问题」,不许写成事实;
   - 手段:`web_search` / `web_fetch`;中英双语各搜一轮。

4. **蒸馏与收录**——先过**准入三问**,再走证据定级与执行化:

   | 准入三问 | 答 | 处置 |
   |---|---|---|
   | 不查资料、凭先验写得出来吗? | 是 | **不收**(通用知识,零增量) |
   | 查一下就有吗? | 是 | 只进「来源」节当指针 |
   | 属于 反先验 / 本地标定 / 强制程序? | 是 | 收入正文 |

   收入后按**证据定级**处置:

   | 档 | 条件 | 去处 |
   |---|---|---|
   | 可复用指令 | 跨项目成立且有证据 | 「通例 / 判据」 |
   | 限定示例 | 只在特定条件成立 | 例子 + 写明条件 |
   | 剔除 | 无证据 / 只对单一场景成立 | 丢,或进「开放问题」 |

   **执行化**(收进来之后):每条通例尽量落成三种之一——① 可跑的检查(断言 / 脚本);② 交付物里必须出现的必答项;③ 强制步骤(留产物)。落不成的标「观察项」,全文 ≤5 条。
   **反凑数**:每条通例必须回指**一次真实触发事件**(踩的坑、调研发现、事故);写不出 → 不收。
   **作者评审门**:价值类判断一律「候选,待否决」;作者接受才转正,否决理由进 ADR(或项目等价物)。

5. **当尺子用**(最容易漏的一步):
   - 时机:该域出提案 / 选型 / 推荐**之前**;
   - 动作:提案的每个部件逐条对证——指不回任何一条判据的部件,删或改;
   - 证据判据:改进的证据 = **结构 / 行为变化**(新增选择 / 失败状态 / 技巧轴 / 系统交互,或工程上可复现的行为变化);**术语出现不算**;
   - 试跑优先:能跑 / 能试的先试(声称不是证据);不能试的写出来源或谁拍的板。

6. **生长与验证**:
   - 每用一次 → 在文档「使用记录」记一行(日期 / 条目 / 用在哪 / 改变了什么决策);
   - **到期删除**:两周或 N 次使用内 0 触发 → 删条目(git 留史);
   - **转正条件**:「候选」→「已验证」必须有据可查的"因它而改变"至少一次;若声称"让产出更好",须做**同任务对照**(流程见 `references/ablation.md`);
   - 修订触发 = 新摩擦 / 更强来源 / 判断被证伪;版本记录写在文档内;变更史归 git / ADR,**不写进正文**。作者经验由作者补,agent 只代记。

7. **复用(可选)**:同一领域在另一个项目再次出现 → 把整份文档**复制**到该项目的 `docs/scaffolds/`,并按目标项目的评审重走一遍;每份文档归它的项目,不设跨项目单源(没出现第二次就什么都不做)。

## 入口

- **居所(唯一)**:正在开发的项目里 `docs/scaffolds/<domain>-essentials.md`。**第一份脚手架落盘时才创建该文件夹**(不预建空壳);从 `templates/essentials-doc.md` 复制后填写,填完删引导注释。
- **加载顺序**:决策时只读文档开头的**决策卡**(5–10 行);正文是给复盘与生长看的,别在决策现场翻长文。
- **登记两行**(习惯随项目,不重造):① L1「本项目特殊工件」写一行"脚手架 → `docs/scaffolds/`"(别逐文件列举);② L1 加载表写一行"进弱领域 → + `docs/scaffolds/`(相关的)"——只写不读的文件夹等于没搭。
- **复用(可选)**:同域在别的项目出现 → 复制整份过去 + 重审;文档始终随项目,不设跨项目单源。
- **正例**:`references/sample.md`(一份真实脚手架——学它的格式,别抄它的内容;该样例是 v0 格式)。
- **验证工具**:`references/ablation.md`(同任务三组对照——判"有没有用、哪种形态有用")。

## 示例

**正例 · 一条合格的通例**(摘自 `references/sample.md`):

> 易犯:手感不对就调数字 → 更有效:先分诊(结构 / 参照 / 参数);三层修法完全不同,结构错时调参数 = 打地鼠。

合格点:来自真实摩擦;抽象到跨项目;给出可执行动作。

**反例 1 · 词汇层合规**:通篇引用"张力""可输性""决策深度",但没有新增任何失败状态或选择结构。→ 术语出现、结构照旧:**不算改进,不算收录**。

**反例 2 · 无来源条目**:「玩家会喜欢 X」——无出处、无试跑、无标记。→ 这是编造;正确写法:标「候选,待否决」并附依据,或登记进「开放问题」。

**反例 3 · 通用知识凑数**:「一页一个结论」「间距要一致」——不查资料也写得出来。→ 零增量;**不收进正文**,最多当来源指针。

## 边界 · 反模式

- ❌ 无来源条目 / 来源不标强度(`【核】/【估】/【待补证据】`必须带)
- ❌ 收录可凭先验写出的通用知识(零增量,只增词汇)
- ❌ 为一次性小问题造完整脚手架(仪式化 → 文档通胀)
- ❌ 跳过「当尺子用」(退化为调研存档)
- ❌ 决策时加载长文而不是决策卡
- ❌ 术语合规冒充改进(词汇层)
- ❌ 没有一条"因它改变"的记录就宣布转正 / 有效
- ❌ 用"文档写了 / 引用了"冒充"行为变了"
- ❌ 「候选」当结论引用;跳过作者评审
- ❌ 把脚手架搬离项目,或给同一份文档维护两个源(复用 = 复制 + 重审,不搞同步)
- ❌ 通例凑数(写不出真实触发事件的条目 → 不收)

## 演化

本 skill 自身按 `seeding-skills` 的纪律生长(从小开始 / 基于观察 / 变更史归 git);本文件只管脚手架**文档**的造、用、长。复盘回改信号:分诊被跳过、架子造了不用、示例被绕过、反例又在现场发生、使用记录长期为空、通用条目混进正文。
