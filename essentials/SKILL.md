# Essentials — 上下文的自我调试

> **主型:元型**(决定验收:交接复现);**副型:判断型**(正文是判定规则)。类型定义见 `seeding-skills` 的 `references/skill-types.md`。
> **状态:** v0.5(三工件,活跃)· **未转正**。v0.1–v0.2 走"文档工厂"定位,六轮评测无净增益(`tests/evidence/`);v0.3 把产物从文档改为账本;v0.4 增「上下文调试」入口;v0.5 加域要领 / 账本 / 视图三工件与引用回写,**交接复现尚未跑**。

## 定位

一句话:为当前任务调试**我自己的上下文**——缺什么、去哪取、取来的有没有用;有用的留下,没用的退掉。三层里只有它朝外取证:

- `init-project-docs` — 已知该记什么(供给 / 加载)。失败 = 忘掉、漂移。
- `seeding-skills` — skill 本身怎么长。失败 = 僵化、膨胀。
- **essentials** — 我该怎么补:从哪取得、凭什么算数、何时留下 / 退掉。失败 = 错误经验被固化、复用。

**边界:** 不写代码、不产**没有决策绑定**的调研报告(产物是候选条目,不是报告;交付物仍由原任务流程做)、**不替用户拍板**(价值与边界只记录用户的裁决,不代拟结论)、不做没有证伪条件的累积。已有可靠脚手架直接用;已否决方案走 ADR。

**外部对照:** 同类系统在解同一半问题,单品清单与差异见 `references/landscape.md`;它只作候选来源,不作证据。

**为什么不判流程型:** 四步环路有入口 / 产物 / 闸,形态像流程,但失败不是"漏步 / 乱序",而是"判断被写错并固化";账本行是宿主任务的副产物,不构成独立产物链。按第 1 问取元型,环路只作准入闸。【实测:v0.1–v0.2 按"文档工厂"流程化用,六轮评测无净增益;交接复现里带材料的 B / C 组低于基线,C 组照抄素材规则(J3 失分),见 `tests/evidence/handoff-2026-10-20/SCORE.md`】

## 环路(四步,不能省)

两个入口,一个账本:① **收尾**(摩擦先行)② **上下文调试**(任务入口或用户点单,见下节)。

- ① **摩擦** → 收可观测的失败信号,记进"事件"列。
- ② **候选** → 一句话断言 + **证伪条件**(什么现象会推翻它);不写证伪条件不入账。
- ③ **检验** → 按「判据来源」取证,留下证据指针。
- ④ **晋升 / 退役** → 生效或退役,证据一行,视图重誊。

**挂点:收尾。** 每次收尾过一遍——本次有没有被否决 / 返工的判断?有 → 一行候选;没有 → 不写;顺手跑账本的引用 grep 更新排序。【依据:四份样例 0 条引用记录——但 0 也可能是没记,不等于没使用】

## 触发(事件型,不许内省)

- 用户的否决 / 返工 / "这个我说过" / 同一决策被重复解释【实测:B 矩阵指出"只有写入、没有读取"】
- 检查器、QA、测试失败,且原因不是笔误
- 用户点名,或问"你可靠吗 / 这是你擅长的领域吗" → **只出可靠度声明**(声明本身不入账;由它引出的检验结果才入账)
- 用户只是描述"你不熟 / 这块你弱"→ **不触发**;要用户明确要求补 / 取 / 查,才进「上下文调试」。
- 用户要求"补一下这个领域 / 按流程带我过一遍" / 新项目开工 → 建域要领;不是所有域都建账本。

**可靠度声明**(一句话三档):① 只有一种公认写法 ② 多个语义相近实现 ③ 没有先验。②③ 才进环路。

## 上下文调试

任务入口先分诊:够用 / 换一版 / 要取 / 要写;两类可同时成立,拆成「补」(取证)与「写」(候选)分别走。只有「要取」走下面五步;「要写」直接落一条候选;不是摸清一个领域,也不做综述。

1. **声明** 先出一句三档(同上),可混合:task 级写主档,断言级逐条定;不等用户问。
2. **缺什么** 从任务里抽出会被依赖的判断,逐条标档;只对 ③ 取证。
3. **取证** 每条写"不成立时哪个决策要改";搜不到记「未知」,不编。
4. **落候选** 行同账本,判据写 `AI 自拟 / 检索`。
5. **交付** 一屏:≤5 条 + 去向,不写综述;来源只留指针。

**交付屏 ≠ 视图。** 交付屏是对话输出,不自动入账;要留下,AI 提议 1–3 条,用户点头后落账(带动作),再誊视图。

**点单 ≠ 确认。** 点单只授权取证,不授权晋升;交付时逐条复述判据,用户点头才记 `用户确认@日期` 并升生效,没点头留候选。

**闸:** ≤5 条(每条一行)、每条绑一个决策;绑不上的不入账。一屏 = ≤5 条,不含来源与解释。

## 账本(断言层的唯一真相)

- 居所:`docs/scaffolds/<domain>-ledger.md`;模板 `templates/ledger.md`;第一份落盘才建目录。
- 一行 = 事件 / 断言 / 层(`[通用]` `[本地]`) / 证伪条件 / **证伪动作** / 判据+取证 / 状态 / 载体。断言前写 `[约定]` 的走用户裁决,其余按事实类取证。
- **证伪动作是执行方式,四选一**:`复跑:<命令>` / `对照:A vs B` / `盲评:<prompt>` / `人看:<一句话问题>`。**没有动作不入账**——只留在会话,不写行。
- **视图 = 账本「二」**(从「一」誊写);要另存副本用 `<domain>-view.md`。`*-essentials.md` 是**域要领**(教学/干预层),不是视图;事实断言冲突以账本为准。
- **冷启动例外**:账本全是候选时,视图只誊**有证伪动作**的候选并标「候选」;无动作的不进视图;出现生效条目后,候选退出视图(视图只装生效条目)。
- 加载:项目 L1 一行"脚手架 → `docs/scaffolds/`" + 加载表"进弱领域 → + 相关视图"(加载表写法按 `init-project-docs` 的 L1 模板)。**只写不读等于没搭。**
- 自检:`scripts/check-ledger.ps1 -Path <账本>`——列完整性、证伪动作四选一、判据来源、视图 ≤5;红是裁决输入,不自动改状态。

## 三种工件(域要领 / 账本 / 视图)

| 工件 | 文件 | 作用 | 真相范围 |
|---|---|---|---|
| 域要领 | `*-essentials.md` / `<domain>-guide.md` | 教学 / 干预 / 综合 | 综合层;不要求逐条证伪 |
| 账本 | `<domain>-ledger.md` | 事件 / 断言 / 证据 | 断言层唯一真相 |
| 视图 | 账本「二」 | 运行时加载 | 缓存;≤5 条 |

- 不是每个域都要三件:可只有域要领(已有长文),也可只有账本(纯事件域)。
- 域要领可以是"记录和尝试",不承诺完整;不套账本的 90 天退役。
- 域要领是 pull:用户点单 / 项目开工 / 进新域才建;不因 agent 自诊自动生成。
- **引用**:域要领条目给稳定 ID `<域>#C/R/P/F<n>`,账本行 `<域>#L<n>`;ADR / 契约 / 提交只写 ID。
- **回写**:被引用的条目一改,同一次提交改域要领,或加 `[YYYY-MM-DD 修正:…]`;退役保留 ID,标 `退役@日期`。
- 细则见 `references/artifacts.md`。

## 检验源与晋升

**强度取决于判据来源,不取决于谁跑。** AI 可自跑复跑 / 对照 / 盲评;但必须 提案者 ≠ 判定者 ≠ 执行者(至少换会话),判据**开跑前**预注册留档,盲评隐组别。

| 判据来源 | 取证方式 | 能晋升什么 |
|---|---|---|
| **用户编码**(判据落成测试 / 检查器,可回指用户的引入记录) | 复跑、回归 | 事实:数值、配比、流程项(**满强度**) |
| **用户确认过的判据**(用户听过并认可一句可判的话) | 复跑、A/B 对照、盲评 | 事实 + "更好"类声称 |
| **AI 自拟的判据** | 同上 | **只到候选**,用户确认判据后升 |
| **用户裁决**(含可观察边界的取舍句) | 复述确认一次,记 `用户裁决@日期` | 约定:红线、取舍、边界;事实类只能记「观察级」(仅作线索) |

- **AI 可以自己跑检验**:起草证伪条件、搭夹具、复跑、派盲评——这是默认动作,不是例外。
- AI 自建的检查器**不算用户编码**——除非有用户的引入记录(提交 / ADR);否则按"AI 自拟判据"处理。
- **用户的感觉**(未复述确认)不计证据,只记一条摩擦事件;同一感觉重复一致后再请确认。
- **否决也分级**:用户 / 用户编码的证据可判退役,AI 自拟判据的否决只降回候选。事实类不得拿用户裁决当满强度证据,只能记「观察级」——仅作线索,不进视图,不得当作别的断言的证据;约定类不得用复跑晋升。
- **不可自测是一等公民**:视觉观感、审美、体感没有可跑的判据,`人看` 就是合法终态,不是欠债——但必须写**看它的时机**(哪个里程碑)。代理指标(如抽色 / 量间距)可以记,不得用它晋升审美断言。

**晋升三条件(全中):** ① 能回指一次真实事件;② 写清推翻它的现象;③ 判据来源与断言类型匹配。
**退役(分层):** 0 引用不判生死。事实类——自生效日满 90 天 0 引用【假设待测】→ 回候选(**降级日重起算**);再满 90 天仍 0 → 退出视图,保留账本。候选——自入账/降级日满 90 天 0 引用且无用户裁决 → 退出视图,不退役。约定类不因 0 引用退出。**只有被证伪或用户否决才退役**(约定类由用户复评退役);被证伪者按「否决也分级」处置。**候选可删行、编号不复用;生效过的退役行留在账本**,「退役记录」写替代 ID 或「无替代」——引用可能已在仓外(提交信息 / ADR),删了无法重链。

## 载体分诊(三类不落一处)

- 反先验事实 → 贴着它约束的代码 / ADR(读代码时才会用上)。
- 本地标定 → 账本 → 视图(需要跨会话加载)。
- **教学 / 判断 → 域要领**;**可执行动作 → 检查器 / hook / 提交前清单**(散文拦不住动作)。【实测:盲评里带 skill 组把"标准"当材料,反成负担】

于是:账本留断言全量;域要领留教学与程序;视图只装"能跨会话加载"的那一类:强制程序只留编号 + 检查器指针,正文不进文档。视图 = 红线 + ≤5 条,生成规则见 `templates/ledger.md` 的「二、视图」。【实测:四份样例 0 条引用记录;0 可能是没记,不等于没使用】

## 红线

- ❌ 条目无证伪条件或证伪动作 / 候选当结论
- ❌ 把"点单"当"确认"(未逐条确认判据就升生效)
- ❌ 强制程序写成散文
- ❌ 被引用的条目改了不回写
- ❌ 引用用"维度 1 / 通例 15"这类会漂的序号(应用稳定 ID)
- ❌ `[本地]` 条目复制到别的项目
- ❌ AI 自拟的 `[通用]` 条目跨项目直接加载(须先在本项目复跑一次)
- ❌ "用了 N 次没出事"当证据
- ❌ 内省式理由("我觉得这领域弱")当触发

## 验收(teach-back)

- **档位:** teach-back;口径为**交接复现**,不再用"方案质量"。
- **流程:** 开跑前预注册(本域最该被砍的 3 条判断 + 通过线)→ 派独立 agent,只给 视图 + 项目 L1 + 一个弱领域任务(域要领不进 B 组;它测的是视图,不是教程)→ 比对它砍掉 / 改掉的提案;协议见 `references/handoff-replication.md`。
- **指标:** 复现率 / 重复解释次数 / 误引率(把方法当材料的次数);**未跑即标「未转正」**;留档 `docs/reviews/YYYY-MM-DD-<域>-essentials.md`。
- **上下文调试另算:** 双轨——**引用**(自报 grep)只用于视图排序;**用户裁决**(采纳/否决)才算存活依据。3 次真实任务里 ≥1 条被用户采纳或否决才继续;全无信号 → 退出视图、保留账本【假设待测】。细则 `references/context-debug.md`。
- **演化信号(任一):** 账本长期 0 行 / 候选积压未晋升 / 晋升缺证据 / 视图被绕过 / 强制程序又写回文档;版本归 git,负结果在 `tests/evidence/`。
