# B 矩阵预注册 GOLD(输出产生前写死)

> 任务:维护 hoverster 的脚手架系统(材料见 `MATERIALS.md`)。
> 三组:无 skill / v0.1 / v0.2;同一材料、同一任务提示,唯一变量是 skill 文本。
> 命中标准:方案里实质点到该问题(措辞不限,语义等价即算)。

## 五个已知问题(来自 hoverster 实践)

| # | 问题 | 判据(命中标准) |
|---|---|---|
| P1 | **主路径写反**:文档主要靠"作者反馈→修复→事后蒸馏"生长,前瞻审查只有 1 次 | 方案指出"生长是常态、审查低频"或据此调整文档形态 / 优先级 |
| P2 | **通用层与本地标定混在一起**:文档头写"只写跨项目通用",但 feel 通例 17–23 全是本项目实测数值;整份复制会污染别的项目 | 方案提出分层 / 标签 / 复制时剥离本地内容 任一 |
| P3 | **使用记录缺调用点**:四份 0 条使用记录;决策不引用条目;提交只引用"生长出处" | 方案提出调用点约定(如决策写 `#T<n>`)或用提交 / 引用自动汇总 任一 |
| P4 | **"作者经验"是死槽**:feels 空占位、game-design/dev 无此段、collab 只有 1 条 | 方案建议删除 / 改造该段 |
| P5 | **生命周期与决策卡缺失**:四份均无状态字段与卡片;feel 67 行 23 条,决策时读不完 | 方案提出文档状态(活跃/冻结/归档)与决策卡生成规则 任一 |

## 回归清单(方案的"不许")

- 不许删掉 feel 的本地标定条目(通例 14 / 17–23 的实测内容);
- 不许把 23 条通例压成 <10 条(丢信息);
- 不许新增空章节(如"作者经验"换个名字又留空);
- 不许把文档改成流水账 / 无结构的清单;
- 不许照搬外部项目的具体数值。

## 评分

- **命中**:五问逐条;满分 5;
- **回归**:上述任一项越界 = 1 次回归,记录;
- **作者盲评**:愿不愿意直接合并(三档:合并 / 改后合并 / 不合并);
- **基线判读**:若无 skill 组命中 ≥4/5 → 脚手架文档的增量只剩"格式",v0.2 的定位应据此收敛。
