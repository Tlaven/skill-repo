# hoverster 脚手架优化方案(组3,v0 · 待作者裁决)

**唯一依据:** `MATERIALS.md`(下称"材料";`L<n>` = 该文件第 n 行)。全材料唯一读过的文件,未联网、未加载 skill、未用其他工具。
**判断标准:** 材料附带的 essentials v0.2(三类收录 / 四类红线 / 生命周期 / 两条记录线)。
**证据分级:** 【核】= 材料里有直接行号或数据;【估】= 我的推断或提案,需作者或实测裁决;**【核·缺席】** = 结论来自"材料里搜不到",只证明当前写法里没有,不证明作者没想过。
**可靠度声明**(按 essentials:弱领域给推荐前先声明):文档脚手架的维护**没有唯一公认写法**,属「②多个语义相近实现」。我按材料给的 essentials v0.2 单一口径判;v0.2 未规定的部分(决策卡行数、ID 语法、状态迁移、N 的取值)全是我的提案,标【估】,可被整体否决。**本文件不是结论,是候选方案。**

---

## 结论先行

四份文档的**内容**质量高于它们的**文档结构**。最贵的两个问题都不是"写得对不对":

1. **通用文档里混进了 hoverster 的实测值,却没有任何层标记** —— 而复用条款写的是"整份复制过去"(L190、L255),复制动作本身就会把本作数值变成下一个项目的"普适规律"(L337 已自认)。
2. **真实的两次"因它改变"没有留下可 grep 的引用** —— L314–323 显示手感脚手架确实改变了两处实现(转角上限由 `latAccelMax` 反推、`frictionSlip 1000→10`),但 L338–339 说没有 `feel#T<n>` 记录。于是"两周或 N 次 0 触发 → 删条目"这条规则一旦生效,**首先被删的就是唯一被证明有效的一批(T13–T23)**。

所以本方案的优先项是**标记与记录**,不是新增知识;总改动量【估】约 4.5 小时,不改任何数值结论、不合并任何条目、不重写正文。

## 1. 问题清单(11 条,已排序)

### P0 — 会静默扩散 / 会删掉有用的东西

**P1 · 层标记全缺,本作实测值混在"只写通用"的文档里**【核】
- 证据:L337 自认"文档头都写'只写跨项目通用',但 feel 的通例 17–23 含大量本项目实测数值 / 公式(T14 起)";对照 L151/L203 两份文档头都写"只写跨项目通用的东西"。载体:L267("推导出 10.8 m/s")、L268("落地 58°/5.6 → 1°/0.35")、L240("线性外推实测偏 30%+")、L320–321(`latAccelMax 6.5 m/s²`、`frictionSlip 1000 → 10`)。四份文档中 `[通用]`/`[本地]` 标记出现 **0 次**。
- 后果:复用条款(L190、L255)= "整份复制过去",复制即触红线"把 [本地] 条目复制到别的项目";下游把一次调参结果当行业事实用。

**P2 · 使用记录为 0,但真实使用已发生 → 有效性不可判,删除策略会误删**【核】
- 证据:L336"四份文档均无…「使用记录」";L338"没有决策类提交引用 `#T<n>`";L339"任务笔记有'首次按手感脚手架走流程'的叙述,但没有 `feel#T<n>` 形式的引用";而 L319–321 同一流程产出了 `latAccelMax` 反推与 `frictionSlip 1000→10` 两项实际改动。
- 后果:①"转正需有据可查的'因它改变'≥1"永远不成立;②两周后跑"0 触发即删"会把 T13–T23(唯一有触发证据的一批,L263–272)判为无用删除。

**P3 · 四份全停在"候选",状态字段无枚举,停更的两份也没有冻结**【核 / 部分核·缺席】
- 证据:L15、L67"v0 · 候选(待作者评审)";L151、L203"记录和尝试(持续增补,不勉强凑数)";L340"正式评审(v0 候选 → 已验证)从未发生";L329、L330"设计阶段结束后未更新""引擎决策后未更新";全材料 `活跃/冻结/归档` 出现 **0 次**。
- 后果:读者与 agent 无法判断哪份该信、该读;"待评审"是一个没有落点的状态;停更文档仍被加载表(L7)无差别指向。

**P4 · 决策入口缺失,长文单向变长**【核】
- 证据:L336"无「决策卡」";feel = 23 条通例(L214–240)+ 11 行版本表(L258–272),L332"一天 10 版";L262–272 共 11 条版本行,**10 条是"新增",仅 v0.8 是"修订"**,无一条被合并、降级或删除。
- 后果:决策时只能读全文(触红线"决策时读长文而不是决策卡");append-only 意味着下次决策成本必然高于这次。

### P1 — 让条目不可信 / 不可执行

**P5 · 来源强度普遍缺失,两份文档的来源被"略"**【核】
- 证据:game-design 全节(L19–61)**0 处外部来源**,唯一指针是 L33 的 `docs/glossary.md`;dev 有 `【来源:…】`(L75、L83、L85)但无强度;全材料仅 1 处强度标 L133"【弱来源,待补强】";L139"来源清单:**(略**——…保留原文链接 15 条)";L256"来源精选:(7 条外部链接,略)";feel T4 只写"见文末来源·Juice it or lose it"(L212)。
- 后果:所有"反先验事实"不可核 → 红线"无来源条目 / 来源不标强度";读者无法区分【核】与【估】,L99 的"可信的意外"这类判断与 L74 的射线悬挂事实在文档里同等权重。
- ⚠ 诚实标注:材料头写"全文"(L9)却含"(略)",**无法判定"略"是材料转写造成还是文档本身如此**。若是前者,本条降为"确认即可"。

**P6 · 判据与本作决定混排,文档比它依赖的决策更确定**【核】
- 证据:分档表直接写"**本作 ✓ L1**"(L94–95),同一节却注明支撑 ADR 仍是 `(proposed)`(L103);验收式定义 = "可信的意外"(L99),无阈值、无观测方式。
- 后果:一个未决的引擎决策被文档写成既定;不可测的验收式定义与它自己第四节"判定看行为层"(L40)互相拆台。

**P7 · 强制程序没有产物与不合格判定,落不成检查**【核】
- 证据:game-design 程序 1–4(L37–40)全是"必须/不得",没有一条写"答在哪、谁判、什么算不合格";collab 三步自查(L179–181)无留痕;对照组 feel 程序 3(L246)"数值先跑 / 画面后看 / 手测留给人"已带产物。
- 后果:强制程序退化为"读起来很对"的段落;同一套方法在四份文档里的执行化程度不均,最需要挡住自欺的 game-design 反而最松。

**P8 · 跨文档同一主题给出不同权限,且互不指回**【核】
- 证据:dev 失败模式 4"手感靠动画/脚本 → 模拟器身份塌陷"(L49)对 feel 观察 4 / T9"反馈不改物理,成倍改感觉…先反馈,再精修物理"(L212、L226)表面相反;game-design 程序 3"完成度/氛围/手感/视听不得参与'好不好玩'的论证"(L39)对 feel T9"视听反馈是性价比之王"(L212)权限不同。
- 后果:只读到一份的 agent 会做错方向(要么用假物理冒充模拟,要么用 craft 论证好玩);两份都在改时必然分叉。

**P9 · 只有体量指标,没有效果指标:自称"实验干预物"却没有读出口**【核】
- 证据:L15"本文件是'脚手架实验'的**干预物本身**";L55 修订触发 = "实验日志里被裁决为结构性问题";但 L325–332 的统计只有"版本行 / 通例数 / 备注",**无引用数、无命中率、无对照**;L329 实验随设计阶段结束而中断。
- 后果:无法回答"这套脚手架值不值得留";"转正"没有可依据的证据;下次做同类实验也学不到东西。

### P2 — 维护成本与寻址

**P10 · 没有入口页,加载表只有"相关的"三个字**【核】
- 证据:L6 列出 4 份脚手架,但 `docs/scaffolds/` 下无索引文件;L7 加载表规则 = "进弱领域 → + `docs/scaffolds/`(相关的)";L302 显示"脚手架归位 docs/scaffolds/"那次重构没有同时建索引;四份同目录、同 `-essentials.md` 后缀。

## 2. 改动方案(按 P 对 C,不重写全文)

### 2.0 目标结构:只加 3 类东西

```
docs/scaffolds/
  README.md                 # 新增 · ≤40 行:索引 4 行 + 公共约定 8 条 + 记录命令 3 条
  cards/
    feel-card.md            # 新增 · ≤20 行(活跃域,先建)
    dev-card.md             # 新增 · ≤12 行(冻结域,只留红线卡)
  game-design-essentials.md # 改:文件头状态行 / 层标记 / 程序加产物列
  dev-essentials.md         # 改:同上 + 移出"本作"列 + 来源强度
  collab-essentials.md      # 改:同上 + 作者经验标 [本地]
  feel-essentials.md        # 改:3 列→4 列(结论/证据分离) / 状态行 / 维护节收缩
```

**不预建 collab / game-design 的卡**(遵守"第一份落盘才建目录,不预建空壳");它们的索引行写 `卡:—(域冻结,复活时补)`。

**公共约定(只写进 README 一处,四份长文不再各写一套):**

1. **层**:`[通用]` 结论跨项目成立;`[本地]` 本项目实测 / 拍板。**本作数值只准出现在"证据"列,不准进"结论"列**(可 grep)。
2. **强度**:`【核】` / `【估】` / `【待补证据·期限】`,三者必居其一。
3. **ID**:`<domain>#<T|P|O><n>`(T=通例/条目,P=强制程序,O=观察项);**n 永不复用、永不重排**;删除或合并只改状态,不改号。
4. **状态**:`活跃 / 冻结(域暂停,保留)/ 归档`;每份带"最近复核日"。
5. **观察项 ≤5 / 文档**;超出则升格为通例或删。
6. **复用**:取 `[通用]` 结论列 + 空的证据列,复制后重走评审;`[本地]` 留在原项目。
7. **使用记录**:只在决策页 / 任务笔记写 `<domain>#T<n>`,不手填台账;汇总 `rg -oh '[a-z-]+#[TPO][0-9]+' docs/ | sort | uniq -c | sort -rn`。
8. **读法**:决策时读卡;长文只在"要新增条目 / 要推导 / 卡没覆盖"时读。
