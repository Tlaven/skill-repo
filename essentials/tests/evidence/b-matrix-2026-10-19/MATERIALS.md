### 1)docs/scaffolds/game-design-essentials.md

# 创作要领:搞怪载具模拟器(v0 · 实验干预物)

> **状态:** v0 · 候选(待作者评审)。本文件是"脚手架实验"的**干预物本身**;每轮实验后按 `docs/experiment-log.md` 的结论修订,版本记录见文末。
> **用法:** 设计工作先满足本文件;评审用第三节的**强制程序**执行。本作的任何具体决定写进 `docs/design-contract.md`,**不进本文件**(本文件只收跨作品可迁移的规律)。
> **范围声明:** 本文件提炼自会话讨论与公开资料的初步综合,尚未经过独立复核——**v0 的每一节都可能在评审中被否决或改写**。

## 一、成败标准(这类游戏为什么好玩)

1. **笑话必须可玩**——荒唐长在机制里,不在标题里。检验:拿掉标题与全部文案,还笑不笑?
2. **失败即内容**——翻车必须好看、值得主动追求、可分享;惩罚性的失败会把玩家教育成保守玩家,喜剧内容随之死亡。
3. **死板真实 × 荒唐**——世界、UI、流程越严肃可信,载具越荒唐好笑;**世界自己不玩梗**(梗在事件里,不在文案里)。
4. **技巧轴 + 可分享时刻**——需要一条"难但不冤"的操控 / 判断技巧轴,和一类"玩家会主动截图发出去"的瞬间。

## 二、评估维度(设计前必答;设计后逐条对证)

1. **决策深度**:玩家每 30 秒在决定什么?把决策空间写出来——若最优解一眼可算,那就是没有决策(配额,不是选择)。
2. **张力与可输性**:能不能输?输掉什么?失败的代价是什么(喜剧性的代价也算)?**无法输的游戏张力为零。**
3. **策略空间**:系统之间有没有交互 / 排斥 / 取舍?各自独立的数字直线不构成策略。
4. **掌握曲线**:执行 / 知识 / 规划三轴上,5 分钟的玩家与 60 分钟的玩家差在哪?**差距只在数字上 = 平曲线**。
5. **主题-机制一致性**:主题自己会写明它该有的机制(打捞 → 推运气;飞行车 → 失控物理 / 风 / 电)。没接住主题暗示的机制,是"设计力缺失"最干净的证据。
6. **玩具测试**(定义见 `docs/glossary.md`):去掉一切任务与目标后,还剩什么?模拟器体裁的合法性在这里。

## 三、强制程序(防"词汇层合规")

1. **先立标准再设计**:设计文档第一节必须是"成败标准 / 维度怎么满足";不许先出方案再补标准。
2. **逐条对证**:每个设计部件必须指回它满足的标准 / 维度;指不回的部件——删或改。
3. **禁止 craft 替代**:完成度 / 氛围 / 手感 / 视听包装不得参与"好不好玩"的论证;它们只回答"做得好不好"。两套轴分开评分、分开取证。
4. **判定看行为层**:改进的证据是**结构变化**(新增可输性 / 选择 / 技巧轴 / 系统交互),不是术语出现。反例:通篇引用"张力"却没有任何失败状态——算词汇层,不算改进。

## 四、常见失败模式(设计级"危险实现清单")

| # | 最容易被写成 | 为什么错 | 挡它的维度 / 程序 |
|---|---|---|---|
| 1 | 任务 = 进度条 | 可目算,无决策 | 维度 1(目算压力测试) |
| 2 | 无输性(资源单调、失败无代价) | 张力为零 | 维度 2 |
| 3 | 系统彼此独立(升级 = 数字直线) | 无策略 | 维度 3 |
| 4 | 手感靠动画 / 脚本,不是模拟 | 模拟器身份塌陷 | 维度 5 |
| 5 | 把惩罚当张力(读秒 / 抹进度) | 玩家变保守,喜剧内容死 | 标准 2 |
| 6 | 世界也玩梗(文案里自我调侃) | 反差消失,笑点变平 | 标准 3 |

### 2)docs/scaffolds/dev-essentials.md

# 开发要领:物理载具玩具(工程脚手架 v0)

> **状态:** v0 · 候选(待作者评审)。与 `docs/scaffolds/game-design-essentials.md`(创作要领)同一手法、换到**工程侧**:从外部资料提炼"做这类游戏"的可迁移事实、判据、程序与失败模式——用来**审查技术判断**(尤其是 AI 的自产直觉),并指导技术决策。
> **用法:** 技术决策先对证本文件;本作的具体决定(选哪个引擎等)写进决策页 / 任务笔记,**不进本文件**(本文件只收跨作品可迁移的规律)。
> **纪律:** 每条尽量带来源;弱来源标 `【待补证据】`;"说不清"合法。
> **范围:** 本 v0 由两轮桌面搜集提炼(2026-10-18);后续轮次补强。

## 一、底层事实(外部来源)

1. **车辆物理的主流实现 = 射线悬挂(Raycast Vehicle)。** 每个轮子打一条射线,用交点计算悬挂压缩量 → 给车身上施加悬挂力;轮胎摩擦用各向异性摩擦模型。这是 Bullet 物理系的官方术语,也是 Web 侧(PlayCanvas)与主流引擎的默认同族做法。
   【来源:UPBGE/Bullet 文档、PlayCanvas 官方教程】
   - 推论:车"好不好开"集中在三处——**悬挂参数、轮胎摩擦模型、质心位置**。这是调参的战场,不是"引擎送不送"的问题。
2. **没有免费的"好开":所有主流引擎自带的车辆组件,都有成堆的已知坑。**
   - Unity WheelCollider:抖动 / 不稳定、高速挫顿、爬坡打滑、异常倾斜……官方论坛与问答站上大量帖。
   - Godot VehicleBody3D:贴地弹跳、轮子下陷、配置玄学("就是不动")。
   - three.js + Rapier:固定步长与帧率不同步会抖动;WASM 内存管理要多写代码;**移动端浏览器上物理表现有"明显变差"的报告**,存在专门的移动性能工程要求。
   - **推论:选引擎不是选"哪个不翻车",是选"翻车后有没有资料、有没有前例、能不能自己修"。**
3. **喷射器的实现 = 刚体上按喷口位置 / 方向施加力 / 力矩。** 标准刚体动力学,任何引擎都能做;实现成本低,成本在调参与调试可视化。
   【参照:BeamNG 官方文档对 thrusters 的定义即"节点对之间的施力"】
4. **软体 / 形变级(L3)是专门团队的多年自研成果。** BeamNG 2011 年由两名程序员 + 两名美术起步(Rigs of Rods 后继),自研软体物理引擎走到今天。
   【来源:BeamNG 官方论坛历史帖、官方技术文档】
   - 推论:个人 / 小团队不做 L3;需要形变就做视觉假货。

## 二、拟真度分档(判据;本作落位 = L1)

> 框架:拟真度不是"越高越好"的滑杆,是"买什么、不买什么"的清单——**买因果(质量 / 重心 / 施力点 / 接触 / 碰撞),不买包装(外观 / 特效 / 细节)**。

| 档 | 做法 | 适用 | 本作 |
|---|---|---|---|
| L0 | 脚本演出(动画冒充物理) | 演出型产品 | ✗(杀"失控"笑点) |
| **L1** | **刚体 + 射线悬挂车 + 点施力** | 街机 / 半拟真驾驶,绝大多数游戏 | **✓** |
| L2 | 部件级(铰接、轮胎滑移、轻形变) | 想更"有戏"时逐步加 | 以后可选 |
| L3 | 软体 / 组件级(BeamNG 式) | 有专门物理团队 | ✗ |

- **"够"的验收式定义:** 能稳定产生"**可信的意外**"(玩家学得会,但每次惊一点),不是"像不像真车"。

## 三、技术栈判据(以本作为准的检查清单)

对候选(Unity / Godot 4 / three.js+Rapier / UE5)逐条查证打分,证据要带来源;【本作已产出:`docs/decisions/adr-001-engine-and-platform.md`(proposed)】:

1. **现成车辆方案的可用性**(有没有"射线悬挂车"起步物可改,而不是"有没有组件");
2. **迭代与调试速度**(改动 → 看到结果的最短路径);
3. **AI 协作友好度**(代码即全部 vs 编辑器工作流;能不能自动跑 / 截图 / 测试);
4. **分享与分发**(给朋友测试、发片段的成本);
5. **物理可控性与可修性**(能不能自己接管悬挂与施力;出错后的资料量);
6. **长期风险**(许可 / 生态 / 性能上限)。

- 已知证据(部分):three.js 官方含 Rapier 集成文档与示例;已有用 three.js + Rapier3D 发布的小游戏(如 "Tubing",Yandex Games);Rapier API 精简、学习曲线尚可。**移动端要专门处理**(性能与碰撞可靠性)。

## 四、强制程序(工程版,防自欺)

1. **核心原型先于一切**:车 + 喷气 + 能飞;不通过,不写任何场景 / 内容 / 美术。
2. **数值全部热调 + 可视化**:调参必须实时可见;没有仪表就等于盲调。
3. **每步一个"能不能玩"的判定**:作者亲手玩;通过才进下一步。
4. **不引入无法验证的环节**:尽量让 agent 能跑、能截图、能自动测试。
5. **范围纪律**:先"一个场景",多场景要"挣来"。

## 五、失败模式(工程级危险实现清单)

| # | 最容易被写成 | 为什么错 | 挡它的 |
|---|---|---|---|
| 1 | 自研物理 / 自研车辆物理 | 重造轮子,个人级不可行 | 事实 1 / 4 |
| 2 | 追求 L3 拟真起步(软体、形变) | 成本灾难;笑点不需要 | 分档表 |
| 3 | 先做场景 / 内容 / 美术,后验核心 | 核心不成立时全部白做 | 强制程序 1 |
| 4 | 盲调参数(无仪表、不可热调) | 调参地狱,收敛不了 | 强制程序 2 |
| 5 | 范围膨胀(第一版做城市 / 任务系统) | 第一作最大通病 | 强制程序 5 |
| 6 | 押注"引擎自带 = 好开" | 所有引擎都有坑 | 事实 2 |

- 外部佐证:独立游戏失败常见于**范围(过大)与商业**,而非技术;存在大量"第一作太大"的复盘。【弱来源,待补强】

# 协作脚手架:AI 与用户在编程项目中的交流(通用)

> **状态:** 记录和尝试(持续增补,不勉强凑数)。与 `game-design-essentials`(创作)、`dev-essentials`(工程)同族,换到**协作 / 交流**域。
> **用法:** 任何编程项目的 Agent;**尤其**"方向 / 定位"类讨论——最容易低效的对话类型。
> **纪律:** 只写跨项目通用的东西;不写具体项目内部的事。

## 一、底层观察(实践中反复出现)

1. 工作都有阶段(方向 → 方案 → 实现 → 迭代);沟通最大的失分来自**阶段错位**——用户认定的"当前阶段"是主时钟。
2. 最大的隐性成本是**重复纠正**:同一个坑被纠第二次,意味着沟通方式没有落地。
3. **方向讨论**与**执行工作**遵循不同规则:前者要发散、明说候选;后者要收敛、给结果。

## 二、通例(易犯的模式 → 更有效的做法)

| # | 易犯的模式 | 更有效的做法 |
|---|---|---|
| 1 | **越过阶段**:越过用户认定的当前阶段,提前铺下游 | 提出任何事之前先对阶段;当前没过,不展开后续 |
| 2 | **层级错位**:用户用简单语言谈方向,却升级成自造框架 | 顺着用户的抽象层级;结构按需引入 |
| 3 | **常规选项**:把"谁都会给的第一个答案"当推荐 | 先自查;是 → 只当背景,继续找更贴合的 |
| 4 | **概念替代细节**:用户点了具体参考,却谈抽象概念 | 参考物优先:先挖透那个参考,拿细节说话 |
| 5 | **问重复问题**:问已被回答、或能自己查的问题 | 先穷尽(对话 / 文档 / 外部资料);带候选答案;一次一个;问意图不问实现 |
| 6 | **过度自信**:说得顺,但超出自己可靠范围 | 先外部核证再说出口,并标注可靠度 |
| 7 | **催收敛**:在探索期催决定、施压 | 方向未定时一切皆候选;等用户示意 |
| 8 | **未确认就开做**:理解没把握却直接执行 | 复述检查点:先复述 → 确认 → 再执行 |
| 9 | **报告腔**:形式化、长清单、含糊 | 短、直接、先结论;说不清就说不清;错了就认、马上修 |
| 10 | **结论散落**:下个会话接不上 | 结论落进项目文档 / 笔记;改动播报 |
| 11 | **先例不复用**:已有被认可的格式 / 做法,却另起一套 | 遇先例先沿用;确有理由才另起,并说明 |

## 三、强制程序(回复前自查)

1. 用户已经给过答案吗?(翻对话 / 翻材料)

3. 我准备的推荐,是不是"常规选项"?(是 → 只当背景)

### 4)docs/scaffolds/feel-essentials.md

# 手感脚手架:操作 / 相机 / 反馈(通用)

> **状态:** 记录和尝试(持续增补,不勉强凑数)。与 `dev-essentials`(工程)、`game-design-essentials`(创作)、`collab-essentials`(协作)同族,换到**手感 / 操控 / 反馈**域。
> **用法:** 做"直接操控一个物理主体"的游戏(载具 / 飞行 / 动作):**键位、相机、反馈**类改动,先对证本文件。
> **纪律:** 只写跨项目通用的东西;不写具体项目内部的事。本 v0 由一个项目的实操改进记录抽象提炼(2026-10-18);外部来源见文末。

## 一、底层观察(实操中反复验证)

1. **手感 = 输入 → 物理 → 反馈 的闭环。** 玩家只感知两端:按了什么、看到 / 听到什么;中间是物理。改手感优先动两端,物理只动"因果"与"作用点"。
2. **"感觉不对"分三层,先分诊再动手:** ① 结构(键位图 / 相机逻辑 / 施力方式)② 参照(该像谁而没像谁)③ 参数(力度 / 速度 / 灵敏度)。三层修法完全不同——结构错时调参数 = 打地鼠。
3. **人是常量:** 反应约 0.2s、决策 0.3–0.5s——一个"整圈动作"(翻滚 / 大位移)以 1.5–2s 留出反应窗口;**每只手 5 根手指**,按住类的键同时最多 2–3 个、不跨两排;左右手与鼠标键都要用上。
4. **反馈不改物理,成倍改"感觉"。** 同一套物理,加一档视听反馈(音效 / 形变 / 粒子 / 轻震)观感翻倍——性价比之王(见文末来源·Juice it or lose it)。先反馈,再精修物理。

## 二、通例(易犯的模式 → 更有效的做法)

| # | 易犯的模式 | 更有效的做法 |
|---|---|---|
| 1 | 把行为做成"模式开关"(按 X 才进入飞行 / 瞄准) | **输入 = 行为本体**:按下的键就是力本身,状态由物理涌现,不设"模式" |
| 2 | 键位靠直觉拍(按左 → 左边发力) | **按物理推**:要往哪去,哪一侧施力(向左滚 = 右侧喷);推一次,全场一致 |
| 3 | 一个键兼职两种语义;空中存在无效输入 | 兼职只在**物理上有理由**时允许(空中轮子本就无效 → 转向键变姿控);把死输入回收成新动作,零成本多一维 |
| 4 | 力的作用点随手放 | **力矩 = 作用点相对质心**;要"纯"的方向(只前推、不抬头),施力点过质心;副作用要么推导得出,要么消除 |
| 5 | 手感不对就调数字 | 先分诊(结构 / 参照 / 参数)——见底层观察 2 |
| 6 | 凭直觉定基准(相机高度、灵敏度、速度区间) | 先套**同类行业基准**(竞速 / 飞行 / 动作各有成熟参数区间),再谈差异化 |
| 7 | 相机只平滑一个点(眼点动、注视点钉死) | **眼点与注视点都平滑**;垂直比水平更软;自适应参数自身再低通一层;高 / 快时改构图(拉远、抬高俯角、注视点下移) |
| 8 | 默认加震动 / 强跟转(以为"更爽") | 震动是**事件**(碰撞 / 落地),不是常态;常态镜头要稳、慢、可预测 |
| 9 | 只有物理在动,没有声音 / 形变 / 粒子 | **反馈先行**:落地、碰撞、动作起止先给一档视听反馈,再谈物理精修 |
| 10 | 手感改动没有回归手段 | **双测**:数值断言(headless)+ 可复现画面钩子;"声称"不是证据 |
| 11 | 失败态是死局(翻车只能重置) | 失败要**可恢复**(自动摆正 / 一键复位);失误是内容,不是惩罚 |
| 12 | 物理量与游戏性系数混写 | 分开标注:物理量(可推导 / 有来源)vs 游戏调参(说得出为什么);全部热调,手测后回写 |
| 13 | 用"砍输入"兜底物理问题(限转角 / 限速度 / 限响应) | 先改"**条件**"(抓地 / 下压力 / 支撑几何)——把"能干什么"还给人,把"会不会翻"交给条件;砍输入是最后手段 |
| 14 | 把参数当独立旋钮(单个调) | 先找它的**配比对**(改 A 必须复扫 B):成对敏感的参数(抓地 × 下压力、质量 × 弹簧、射程 × 精度)单独动会失衡;扫参脚本定位,定值后固化断言 |
| 15 | 起跳 / 落地姿态翻车 → 加稳定辅助(阻尼器 / 自动摆正) | 先查**几何与角动量**:台口角 / 曲率 / 重心 / 落地角——几何是免费的,辅助会吃掉玩家的操作权(操作权本身就是玩法) |
| 16 | 玩家说"太难操作" → 先加辅助 / 先降难度 | 先盘点**玩家缺哪个动词**(转向 / 垂直 / 姿态):缺动词 = 模型缺项,按同类游戏的惯例把它放回主轴;辅助默认开、但**必须可关**(选择权留给玩家) |
| 17 | 依取向的力(下压力 / 吸地 / 磁吸)写在世界坐标系 | 定义在**机体坐标系**(车底朝向):直立时等价世界下压,倒挂 / 贴壁 / 隧道顶时自动成立——一个方向选择就换来整类特技,零特判 |
| 18 | 贴面板(吸地 / 磁轨 / 粘墙)的速度限制靠"感觉"定 | 曲面贴面行驶有硬上限 **v ≤ √((g + F贴/m)·R)**:超出即撞进坡面。先按**目标进坡速度**定半径(或反过来引导玩家减速),把它写成注释 / 断言,别拍脑袋 |
| 19 | 自动姿态 / 位姿控制用固定增益(PD)逼近,落地前的"临门一脚"总差口气 | 状态里带上**残余速度**,按**时间最优**解:双积分器 bang-bang,目标 mod 2π 时对"多转一圈"求最短时间 |
| 20 | 用"自动保持一个姿态 / 状态"去解决难操作 | 常驻设定值控制器 = **看不见的持续推力** + 和玩家故意摆的姿态打架。先盘点缺的**动词**并把它直通给玩家;自动只保留有理由的场景,且分档:不急时宽容差 + 低出力(省资源)、急时满权限(落地);"慢 = 省"要成立,耗气必须 ∝ 推力 |
| 21 | 姿态规划里直接用"轴+角"或 atan2 角 | 表示在 180°/±π 处会翻向或跳变 → 控制器目标瞬间反向 → 车被抖着打滚。**逐帧展开(unwrap)**或换连续表示;bang-bang 的死区角速度要大于 A·dt 的极限环幅值 |
| 22 | 自动层为了归位急着刹停玩家正在做的动作(翻转 / 甩尾 / 特技) | 有像样动量时**顺着动作走完**(目标取旋转方向的下一个等价姿态),刹车用"刚好在动作末尾停下"的柔和值(**只刹、绝不加速**);小动量才快速归位;真正紧急(落地)才允许满权限打断 |
| 23 | 自动层的触发时机靠"预测时间",却用当前位置/速度线性外推 | 预测要按**真实运动学**(自由落体含加速度:`t=(v+√(v²+2gy))/g`);线性外推会系统性乐观(实测偏 30%+)。另:分配器在低基准(未按升力)时的"差动"对半砍——用满侧补足差动 |

## 三、强制程序(动手前后自查)

1. **分诊**:这次"不对"是结构 / 参照 / 参数哪一层?说不清 → 先复现现象,再归层。
2. **参照物**:我引用的参照是什么——名字 + 来源?没有 → 先去找,别用直觉。
3. **验收**:改完怎么测?数值先跑(headless / 断言),画面后看(可复现截图);手测留给人。
