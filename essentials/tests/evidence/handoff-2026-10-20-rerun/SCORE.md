# 交接复现 · T1 判分（2026-10-20）

> 三组各一独立会话，同一提示词；B 只给视图（不含 V8），C 给账本全文（含 V8，阳性对照）。
> 判分：agent 初评，待用户确认。0 / 0.5 / 1 三档。

## 一、逐条

| 判定 | A 基线 | B 视图 | C 账本 |
|---|---|---|---|
| J1 定位在图形设计层 | 0.5（主判"主张缺位"，但提了"非模板化图形语言"） | 1（"构图与视觉语言"，点名等分栅格 / 锚点） | 1（"图形设计层：构图语言、图形系统、色彩层次"，引 V8） |

## 二、按预注册规则判读

- **C 命中 → 阳性对照成立**：任务可解，材料没坏。
- **B 命中 → 视图没有丢这条判断**：3 行视图足以让下一个会话走到图形设计层。
- **A 2.5，仅差 0.5（1 项）** → **不能声称有 lift**。n=1、单项、同一模型家族，差异在噪声内。

## 三、但这一轮有个设计缺陷（重要）

任务提示里写了"**密度已被用户认可**"——这句话把陷阱拆了：三组都不必判断"该不该加密度"，J3 变成白送。

真实历史里，陷阱是存在的：v0.1 稀疏 → 用户说"不够丰富" → 加模块 → 用户说"很普通"。**去掉这句提示**，"加模块"才会成为基线组的自然错误；那时视图若仍能把它挡住，才是 lift 的证据。

→ 本轮结论只到"视图不丢信息"，不构成"视图改变行为"。

## 四、附带的观察

- B 组引用了 V3/V4/V5 编号 → 引用机制可用（视图里的编号被自然使用）。
- A 组与 C 组的差异集中在"问题归哪层"这一句；动作层面已趋同——**再往下测只能拉开归因，不容易拉开方案**。
- C 组主动写了"（vq#V8，待用户确认）"——候选状态被正确读出，没有当结论用。

## 五、下一步

去掉"密度已被认可"，改成只在结尾给用户原话（"还行吧，很普通"），预注册 gold 仍是 V8，但把 **"是否提出加模块 / 加密度"** 列为独立指标（J4，反向）。

- A 提加模块、B 不提 → 视图挡住了已知陷阱 → 可转正候选；
- A、B 都提 → 视图无效；
- 都不提 → 该任务仍无区分度，换任务。
