# 交接复现:验收 essentials 的唯一口径

> 为什么不用"方案质量":六轮评测测的都是单次产出,方向一致地无净增益(`tests/evidence/`)。这个 skill 的声明价值是**交接**——判断能不能被下一个会话接住。所以只能测交接。
> **前提:** 没有 ≥5 条生效条目的真实账本,不要跑——用样例数据跑等于演戏。

## 一、它能证明 / 不能证明什么

- **能:** 视图(红线 + ≤5 条)能否让下一个会话在正确的点上砍提案 / 改方案;视图丢了哪些必要信息。
- **不能:** 产出质量更好。那是 `ablation.md` 的问题,不是这个协议的问题。

## 二、预注册(开跑前写死,跑完不许改)

写进 `tests/evidence/handoff-<日期>/PREREG.md`:

1. **3 条判定**:本域最该被砍或被改的 3 个判断。**必须有一部分不在视图里**——否则测的是"抄写视图",不是"迁移判断"。
2. **通过线**:≥2/3 命中,且 **0 次误引**(把方法当材料、编造条目号)。
3. **判分者**:用户;判分前不看组别,不看会话记录。

## 三、三组条件(各自全新会话,同模型 / 同 effort / 同工具)

| 组 | 加载什么 |
|---|---|
| A 基线 | 项目本身 + 任务,无视图、无账本 |
| B 视图 | 项目 + 视图(红线 + ≤5 条) |
| C 账本 | 项目 + 视图 + 账本(可选;回答"视图够不够") |

## 四、任务提示词(三组逐字一致)

只写"做什么 + 交付什么",**不写哪里不好**。必须是一个真实的弱领域决策(有取舍),不是纯执行。

示例形态:"按现有约束评审这个改动方案,给出你会砍掉 / 改掉的点与理由;交付一份评审意见。"

## 五、判分表

| 项 | 取法 |
|---|---|
| 命中 | 3 条预注册判定逐条勾:砍对 / 改对 |
| 误引 | 引用不存在的条目号 / 把视图规则当项目材料 |
| 复述 | 需要用户补充解释的次数 |
| 代价 | 步数、token(可选) |

## 六、判定

- **B ≈ A** → 视图没有传递判断 → 重写视图或归档结论;
- **B > A 且 C ≈ B** → 视图够用,可转正;
- **C > B** → 视图丢了必要信息 → 加条目或**拆域**(不压缩,见 SKILL.md「载体分诊」);
- **A > B** → 视图在误导,立刻查条目来源。

## 七、夹具要求

- 真实项目 + 一份 ≥5 条生效条目的账本 + 从账本「二」抽出的视图;
- B 组只给账本「二」(或其副本),不给「一」「三」「四」;抽取 = 复制「二」到 `fixture/view.md`,保证 B ≠ C;
- gold 独立于视图(有 held-out 条目);
- 初始文件快照一致,三组都不得使用用户的最新反馈。

## 八、留档

- 输出与判分写 `tests/evidence/handoff-<日期>/`(PREREG / outputs / SCORE);
- 结论一行进账本「四、引用」,并据此决定状态:转正 / 回候选 / 归档。
