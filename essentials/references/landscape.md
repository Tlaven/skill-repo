# 同类系统对照:谁在解同一半问题

> **用途:** 回答“我们这条判断有没有别人做过、做到哪、值得抄哪一段”。是候选来源,不是证据。
> **读法:** 外部同类**只能生成候选**——判据一律记 `AI 自拟 / 检索`,流行度、星数、官方背书都不是晋升理由。晋升仍看 `SKILL.md` 的「检验源与晋升」。
> **检索:** 2026-10-22。**深度分级:** 【读全】= `SKILL.md` 与全部/相关 reference 逐字读完;【读机制】= `SKILL.md` 全文 + 关键 reference,机制清楚但未逐字读完;【摘要】= 只读 README / 文档页,**不得作为候选依据**。
> **局限:** 未逐个实跑;效果证据只有两家自建(Hebb 厂商数字、codex 合成 eval),均无第三方复现。

## 一、先分层,别拿全家桶当同类

- **全家桶**(几十个 skill 打包):`EveryInc/compound-engineering`(36 skills)、`alirezarezvani/claude-skills`、`borghei/Claude-Skills`。星数是仓库级,分到单 skill 上等于零——必须进内部找那个单品。
- **单品**(一个 skill 解一件事):最可比,见第二节。
- **研究线**:Reflexion(2023)、ExpeL(AAAI 2024)、Generative Agents 的 reflection、AutoSkill(ECNU)。共同点:经验池 + 归纳 insight,**都没有准入校验**——这是学术线留出的空位,也是我们主张的位置。

## 三、复读后修正(2026-10-22 第二轮)

第一轮只读摘要,以下四条判断被推翻或收窄,保留原判断以便对照:

| # | 第一轮说法 | 复读后 | 性质 |
|---|---|---|---|
| R1 | “ce 只做 schema 审计,没有机械闸;E3 可以抄它” | **反了。** `validate-doc-claims.py` 逐断言查路径/SHA/链接/草稿残留,语义 grounding 要引源码行;`assembly` 和 `per-action-flows` 都有。是**我们该抄它** | 硬错 |
| R2 | “codex 效果证据为零” | 它有 `skill-evals`:19 case + rubric + runs + baseline,是唯一按**输出质量**评测的。仍属作者自建、无第三方复现 | 硬错 |
| R3 | “没有人做判据来源分级,这是我们独有” | 收窄为:**没有人按“谁拍的板”分级**。ce 按单条断言标来源、codex 按证据强度、memory-skill 按遗忘后果、recap 按行为计数 | 收窄 |
| R4 | “ce 删除会断引用,我们保 ID 更优” | 它 Delete/Consolidate/Replace 都带引用清理(含 catalog 行、中途发现实质引用即重分类、可选 `supersedes`)。**改链 vs 保号是取舍,不是它漏了** | 收窄 |

另有两处新增认识:

- **E1 的支撑从一家变两家**:ce 的消失反事实 + memory-skill 的 Q1“忘了会不会出 bug”问的是同一件事。行业收敛,但仍非证据。
- **“写原则还是写规则”有第三个答案**:Warp 说写原则;memory-skill 强制 ALWAYS/NEVER/MUST;codex 给硬词软化表(只在真全局且持久时用)+ 范围条件。**第三种与我们的分层同构**:准入硬、教学软,且给了可判据——“`always/never/must` 有没有配范围”。

## 四、机制对照

| 机制 | 他们怎么做 | 我们 | 判定 |
|---|---|---|---|
| 准入:值不值得留 | 消失反事实(ce)+ 三问闸(memory-skill) | 绑决策 + 证伪条件 | **互补**:我们问“真不真”,没问“没了会不会重犯” |
| 准入:谁说了算 | 四根不同的轴(R3) | 判据来源四级 | **独有**:按决策权归属分级 |
| 断言校验 | ce:路径/SHA/链接/草稿 + 语义 grounding,红是**裁决输入** | 只有证伪动作,没有检查器 | **我们缺执行面;且要学“红≠错”** |
| 载体 | 8 结局判定(codex)/ 按后果分层(memory-skill) | 三类载体散文 | **他们更像判定表** |
| 计数卫生 | `last-swept` + 只扫上次之后(recap) | 无 | **我们缺** |
| 观测点 | 用户改稿差异 ≥2 次(draft-learn) | 只覆盖用户开口 | **我们漏了“默默改”** |
| 退出 | 不设归档 + 改链(ce);14/30 天自动归档(Hermes);`-`/`+` 阈值(recap) | 0 引用降级、90 天、保 ID | Hermes 的年龄制与我们直接冲突;ce 是取舍 |
| 反仪式 | no churn(ce);不新增主分类除非 eval(codex) | 反仪式、不为填表写 | 收敛 |

## 六、两处要用户裁决(约定类,AI 不代拟)

1. **退役形态**:改链(ce,零 ID 维护、删除即净)vs 保号(我们,引用出仓库也稳)。两者都已证成可行,选的是成本结构。
2. **准入的第二条腿**:是否引入消失反事实(E1)。先看对照结果,别先改正文。

## 七、不借的

- **频率制准入**(≥2–3 次即晋升:alirezarezvani、kumaran-is、recap)。重复只证明“发生过”,不证明“对”。
- **无条件自动写入**(pskoett 每日 cron、recap 的“应用修复不需确认”)。捕获要零摩擦,落账要有闸。
- **`+` 即 proven**(recap)。被赞是引用,不是验证;这正是我们“引用只排序”的理由。
