# 手感脚手架:操作 / 相机 / 反馈(通用)

> **状态:** 记录和尝试(持续增补,不勉强凑数)。与 `dev-essentials`(工程)、`game-design-essentials`(创作)、`collab-essentials`(协作)同族,换到**手感 / 操控 / 反馈**域。
> **用法:** 做"直接操控一个物理主体"的游戏(载具 / 飞行 / 动作):**键位、相机、反馈**类改动,先对证本文件。
> **纪律:** 只写跨项目通用的东西;不写具体项目内部的事。本 v0 由一个项目的实操改进记录抽象提炼(2026-10-18);外部来源见文末。

## 一、底层观察(实操中反复验证)

1. **手感 = 输入 → 物理 → 反馈 的闭环。** 玩家只感知两端:按了什么、看到 / 听到什么;中间是物理。改手感优先动两端,物理只动"因果"与"作用点"。
2. **"感觉不对"分三层,先分诊再动手:** ① 结构(键位图 / 相机逻辑 / 施力方式)② 参照(该像谁而没像谁)③ 参数(力度 / 速度 / 灵敏度)。三层修法完全不同——结构错时调参数 = 打地鼠。
3. **人是常量:** 反应约 0.2s、决策 0.3–0.5s——一个"整圈动作"(翻滚 / 大位移)以 1.5–2s 留出反应窗口;**每只手 5 根手指**,按住类的键同时最多 2–3 个、不跨两排;左右手与鼠标键都要用上。
4. **反馈不改物理,成倍改"感觉"。** 同一套物理,加一档视听反馈(音效 / 形变 / 粒子 / 轻震)观感翻倍——性价比之王(见文末来源·Juice it or lose it)。先反馈,再精修物理。

## 二、通例(易犯的模式 → 更有效的做法)

| # | 易犯的模式 | 更有效的做法 |
|---|---|---|
| 1 | 把行为做成"模式开关"(按 X 才进入飞行 / 瞄准) | **输入 = 行为本体**:按下的键就是力本身,状态由物理涌现,不设"模式" |
| 2 | 键位靠直觉拍(按左 → 左边发力) | **按物理推**:要往哪去,哪一侧施力(向左滚 = 右侧喷);推一次,全场一致 |
| 3 | 一个键兼职两种语义;空中存在无效输入 | 兼职只在**物理上有理由**时允许(空中轮子本就无效 → 转向键变姿控);把死输入回收成新动作,零成本多一维 |
| 4 | 力的作用点随手放 | **力矩 = 作用点相对质心**;要"纯"的方向(只前推、不抬头),施力点过质心;副作用要么推导得出,要么消除 |
| 5 | 手感不对就调数字 | 先分诊(结构 / 参照 / 参数)——见底层观察 2 |
| 6 | 凭直觉定基准(相机高度、灵敏度、速度区间) | 先套**同类行业基准**(竞速 / 飞行 / 动作各有成熟参数区间),再谈差异化 |
| 7 | 相机只平滑一个点(眼点动、注视点钉死) | **眼点与注视点都平滑**;垂直比水平更软;自适应参数自身再低通一层;高 / 快时改构图(拉远、抬高俯角、注视点下移) |
| 8 | 默认加震动 / 强跟转(以为"更爽") | 震动是**事件**(碰撞 / 落地),不是常态;常态镜头要稳、慢、可预测 |
| 9 | 只有物理在动,没有声音 / 形变 / 粒子 | **反馈先行**:落地、碰撞、动作起止先给一档视听反馈,再谈物理精修 |
| 10 | 手感改动没有回归手段 | **双测**:数值断言(headless)+ 可复现画面钩子;"声称"不是证据 |
| 11 | 失败态是死局(翻车只能重置) | 失败要**可恢复**(自动摆正 / 一键复位);失误是内容,不是惩罚 |
| 12 | 物理量与游戏性系数混写 | 分开标注:物理量(可推导 / 有来源)vs 游戏调参(说得出为什么);全部热调,手测后回写 |

## 三、强制程序(动手前后自查)

1. **分诊**:这次"不对"是结构 / 参照 / 参数哪一层?说不清 → 先复现现象,再归层。
2. **参照物**:我引用的参照是什么——名字 + 来源?没有 → 先去找,别用直觉。
3. **验收**:改完怎么测?数值先跑(headless / 断言),画面后看(可复现截图);手测留给人。
