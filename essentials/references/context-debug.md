# 上下文调试:为当前任务找合适的上下文

> **何时用:** 任务落进"没有先验",或用户明确说"这个领域补一下 / 按流程带我过一遍"。
> **何时不用:** 现有上下文够用;已有成熟脚手架;纯执行任务。
> **它不是:** 领域综述、调研报告、知识库搬运。

## 〇、先分诊(四选一)

| 判断 | 动作 |
|---|---|
| 现有上下文够用 | 不动,不写账 |
| 有一版但不对 | 改一版:局部 patch,不重写全文 |
| 缺的是事实 / 规范 | 取证(下面五步) |
| 缺的是程序 | 直接写一条候选(步骤 / 检查 / 禁忌);仍须写证伪动作,写不出 → 不落账 |

**边界先行:** 用户要的是交付物本身 → 照常交付(效力=候选,不因做了就生效);交付物本身不入账,只把其中会被复用的判断落候选。

只有「要取」走下面五步;「要写」直接落一条候选,再回账本。两者可同时成立:拆成「补」(取证)与「写」(候选)两个动作,分别走。

## 一、五步

1. **声明**——先给一句三档,不等用户问;task 级可写混合,断言级逐条定档:
   - ① 只有一种公认写法:不取证,直接做;
   - ② 多个语义相近实现:取一次证(挑一个并说明理由);
   - ③ 没有先验:逐条取证,是本流程的主体。
   - ②/③ 必须能举出一个具体候选实现或未知点;举不出即 ①。
2. **断言清单**——从任务里抽出"会被依赖"的判断,逐条标档:

   | 断言 | 档 | 依据(缺省写"无") | 不成立时哪个决策要改 |
   |---|---|---|---|
   | … | ③ | — | … |

   抽不出"会改变哪个决策"的断言,直接删,不列。
3. **取证**——只对 ③,一次一条;优先官方规范 / 源码 / 可复跑的实验;搜不到记「未知」,不补全、不推断。
4. **落候选**——行格式同账本,判据写 `AI 自拟 / 检索`;状态 `候选`;**不写"生效"**。
5. **交付**——一屏:≤5 条,每条一行;不写综述;每条带首次使用场景;来源进账本「五、来源」,不进正文。

## 二、交付长什么样(示例,数字为占位)

```
任务: <一句话> · 声明: ③(或 task ②+③:骨架 ② / 红线 ③)
候选(3):
1. <断言> — 依据 <来源> — 首次用在 <哪个决策> — 不成立则 <改什么>
2. …
3. …
未知: <搜不到的点,1 条>
```

**交付屏 ≠ 视图:** 它只是对话输出,不自动入账;要留下,AI 提议 1–3 条,用户点头后落账(带动作),再誊视图。
**未知占多数时:** 未知 ≥ 候选数 → 只交未知清单,不硬凑;取证超时也先交未知,后补。

## 三、晋升:点单 ≠ 确认

- 点单只授权**取证**;晋升仍看判据来源,`AI 自拟` 只能到候选。
- 交付时**逐条复述判据**;用户点头 → 记 `用户确认@日期`,可升生效;没点头 → 留候选。
- 用户说"你去弄吧"之后走开 → 全部留候选,不替他点头。

## 四、反例(都是真实失败形态)

- **收集癖:** 10 条断言、5 页综述、0 条绑定决策——这是 v0.1 文档工厂,不是上下文调试。
- **搜到即成立:** 把一篇博客当规范,不标来源强度。
- **自封生效:** 用户点了单,就把 AI 检索的判断记成生效。
- **补全未知:** 搜不到就按"常识"写一条,还标了来源。

## 五、指标

- **存活(双轨):** 引用(自报 grep)只用于视图排序;用户裁决(采纳 / 否决)才算数。3 次真实任务里 ≥1 条被用户采纳或否决才继续;全无信号 → 退出视图、保留账本。
- **误引率**:引用不存在的条目号、把检索结果当项目事实——应为 0。
- 两项都只记事实,不记"感觉有用"。
