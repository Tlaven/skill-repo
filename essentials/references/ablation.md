# 消融:判断一份脚手架有没有改变行为

> 用途:`essentials` 的验证工具。回答两个问题:① 这份脚手架有没有让决策不同?② 哪种形态(全文 / 决策卡)有差别?
> 原则:同一任务、同一模型、同一 effort,只变"有没有脚手架";判分独立,作者盲评。**没有这一步,"有效"只是声称。**

## 一、准备

- **夹具**:一个真实、可复跑的任务 + 一份 **gold 集**。
- **gold 集**:事先写死"好"的判据,必须**独立于被验证的脚手架**(否则循环论证)。优先用:历史评审记录 / 客观检查指标 / 作者既有判断。
- **固定项**:模型、effort、任务提示词、可用工具、初始文件快照;三组都不得使用作者的最新反馈。

## 二、三组条件(各自一个全新会话)

| 组 | 加载什么 |
|---|---|
| A 基线 | 不给脚手架(只给项目本身与工具) |
| B 全文 | 完整 essentials 文档 |
| C 决策卡 | 只给文档开头的决策卡(5–10 行) |

> 至少跑 A/B 两组;加 C 只多一次运行,能回答"哪种形态有效"。

## 三、任务提示词(三组逐字一致)

只写"做什么 + 交付什么",**不写"哪里不好"**(否则等于泄漏答案)。

## 四、记分(跑完统一盲评,隐去组别)

| 指标 | 怎么取 |
|---|---|
| gold 命中 | 三组输出对照 gold 集逐项打勾 |
| 客观指标 | 如 `qa_check --strict` 的 errors / flags 数 |
| 作者盲评 | 按事先定好的 3–5 个维度打分(不告诉组别) |
| 副作用 | 新增回归 / 新增错误 / 超时 |

## 五、判定

- B ≈ A 且 C ≈ A → 该域**不适合**脚手架(或内容无效)→ 归档结论,不转正;
- C > B > A → 决策卡形态有效 → 优先瘦身文档;
- B > A 且 C ≈ B → 有 lift → 可转正,继续生长。

## 六、留档

- 输出与判分写到夹具项目的 `tests/evidence/ablation-<日期>/`;
- 结论一行进 essentials 文档的「使用记录」;项目有实验日志的,同步一行。

## 示例夹具(pptx-delivery,现成)

- 夹具:`pptx-delivery/examples/acceptance-sample/`(deck + 渲染 + QA);
- gold:`UPGRADE-REPORT.md §7` 的目检余项 + `qa_check --strict` 的 errors / flags;
- 任务示例:"改进这个 deck 的视觉质量,输出改后 deck 与改动说明;不要加内容。"
- 留档:`pptx-delivery/tests/evidence/ablation-<日期>/`。
