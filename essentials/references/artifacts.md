# 三种工件:域要领 / 账本 / 视图

> 为什么分开:长文要领是**教学 / 干预**层,账本是**断言 / 证据**层,视图是**加载**层。混用会导致过期判据、命名冲突和"唯一真相"过度声称。
> 一句话:**账本管"这条还成立吗",域要领管"这类事怎么做",视图管"这次加载什么"。**

## 一、分工

| 工件 | 文件 | 作用 | 真相范围 | 生命周期 |
|---|---|---|---|---|
| 域要领 | `*-essentials.md` / `<domain>-guide.md` | 教学、干预、综合 | 综合层;不要求逐条证伪 | 按真实摩擦版本化;可长期"记录和尝试" |
| 账本 | `<domain>-ledger.md` | 事件、断言、证据 | 断言层唯一真相 | 行级状态:候选 / 观察级 / 生效 / 退役 |
| 视图 | 账本「二」 | 运行时加载 | 缓存 | 随账本重誊;≤5 条 |

- 不是每个域都要三件:可只有域要领(已有长文),也可只有账本(纯事件域);视图只在需要跨会话加载时存在。
- 域要领可以是"记录和尝试",不承诺完整;不套账本的 90 天退役。
- 域要领是 pull:用户点单 / 项目开工 / 进新域才建;不因 agent 自诊自动生成。

## 二、稳定 ID

格式:

```text
<域>#C<n>  判据 / 断言(维度、标准)
<域>#R<n>  规则 / 通例
<域>#P<n>  强制程序
<域>#F<n>  失败模式
<域>#L<n>  账本行
```

规则:

- **只给会被引用的条目**;懒分配,不追求全量编号。
- **不重编号**:已有"通例 15"直接映射 `#R15`;新条目取该类型的下一个空号;删除 / 退役的号不复用。
- ID 是**项目内稳定**,不是跨项目全局;复制 `[通用]` 条目到别的项目时,新项目重新给本地 ID,并写来源(旧 `<项目>/<域>#R15`)。
- 表格加 `ID` 列;散文条目在标题或句首加 `[R15]`。
- 类型变了(规则变程序):保留旧 ID 并标退役,新类型用新 ID。

## 三、回写

- **触发**:被引用条目发生变更 / 退役。不是"定期 review"。
- **同一次提交**改域要领,或在原文旁加 `[YYYY-MM-DD 修正:…]`;旧句保留,不静默删。
- **退役**:保留 ID,标 `退役@日期`,指向替代条目;引用方无需改号。
- **回写率**应为 100%;账本「四、引用」的 `#C/R/P/F` 计数只用于回写检查,不参与视图排序。
- 反例:hoverster 的 `10.8 m/s` 已在 `task_plan` / `glossary` 修正,`feel` 与 ADR-002 仍留旧值——这就是 stale authority。

## 四、优先级

- **事实断言冲突** → 账本(断言层唯一真相)。
- **教学取舍 / 程序冲突** → 域要领;但域要领不得把取舍写成事实。
- **视图与账本冲突** → 账本。
- 域要领里的旧事实被账本推翻 → 改域要领或加日期注记,不能两边都留。

## 五、何时建哪种

| 信号 | 建什么 |
|---|---|
| 新域 / 弱领域 / 用户点单"补一下" | 域要领 |
| 出现可证伪断言、用户裁决、需要状态跟踪 | 账本 |
| 需要跨会话加载 3–5 条判断 | 视图 |
| 只是"记录和尝试",没有可证伪断言 | 域要领;不强行建账本 |

## 六、反例

- **长文当视图**:把 `*-essentials.md` 当账本副本 → 命名冲突,改视图时误改教程。
- **账本自称覆盖教学**:对所有知识都说"唯一真相" → 过度声称,长文被降级成 legacy。
- **序号会漂**:引用"维度 1 / 通例 15" → 插入一条后引用失效。
- **改了不回写**:ADR 引用了判据,源文档保留旧值 → 过期判据被继续引用。
- **把点头当事实**:用户确认的是**判据**,不是事实;事实仍要复跑 / 检索;用户裁决只升约定。

## 七、迁移

- 不批量迁移长文;只在条目**第一次被引用**时补 ID。
- 已有长文加一行边界:"这是域要领,不是账本视图;新事件进 `<domain>-ledger.md`。"
- 账本只收真实事件;文献结论先留在域要领,绑定事件后再入账。
