# Macro Market Radar — 全球宏观市场雷达

## 定位

给用户一个**自上而下的全球市场环境快照**:不分析个股,而是回答"现在全球市场处于什么状态、哪里强哪里弱、今天为什么涨跌、有什么值得注意的信号"。

**一键触发**: 用户只需说一句短指令 ("今天市场怎么样" / "大盘怎么样" / "全球市场" 等, 见下方触发词), agent 就应**自动跑完全流程** —— 数据快照 → 按覆盖清单收集各市场收盘与关键新闻 → 交叉验证 → 融合解读 → 直接输出"环境 + 值得关注的新闻", **不需要用户追问第二句**。

**架构原则: 数据源为辅, 搜索为主。**
免费行情接口 (akshare/东财) 在本机实测**不稳定** (请求一多会封 IP, 封禁期间所有接口失败)。因此本 skill 不依赖脚本拉全所有数据, 而是:
1. 脚本**尽力拉取**一次快照 (能拉多少是多少, 失败自动标记)
2. agent 看数据健康度标记, 对**缺失/过时**的部分用 **web_search 实时补充**
3. **按覆盖清单收集每日固定信息** (隔夜美股/A股/港股收盘 + 关键新闻)
4. 融合成解读

## 何时使用

适合用户问:
- "今天全球/大盘怎么样?"
- "宏观环境如何? 现在风险偏好是高是低?"
- "港股/美股/A股最近强弱如何? 钱在往哪流?"
- "今天市场为什么涨/跌? 有什么关键消息?"
- "现在适合加仓/减仓/防守吗?"(提供环境判断, 不做个股推荐)

不适合:
- 问具体某只股票/某个板块深度 → 转个股/行业分析
- 需要分钟级盯盘/精确点位 → 本 skill 是宏观视角, 数据有延迟

## 数据模块与可靠性 (摘要)

- 脚本的 **6 类数据模块** (+ 美股板块/当日新闻无脚本源, 靠搜索) 的**接口、字段、口径与全部已知坑** → `references/data-guide.md` (需要核对数据口径/换源时读)
- 核心原则: 东财系接口会被限流封禁 (封禁期间**所有**东财接口一起失败); 乐咕宽度源独立稳定; A股指数历史有**双源冗余 (东财→新浪)** + **本地缓存 (一天一拉, 有盘中值副作用)** + 失败冷却
- **failed 的模块一律不硬拉, 改用 web_search 补** (升级路径见 `references/coverage-checklist.md` §B)

## 工作流 (一键触发时全自动跑完)

### Step 0: 定市场时点 (先做)

用当前北京时间判断各市场是**盘中/已收盘**。规则见 `references/coverage-checklist.md` §0。铁律: 回答"今天哪个板块最强"必须用收盘/复盘源, 不能用盘中快讯 (实测盘中与收盘可能完全相反)。

### Step 1: 尽力拉取数据快照

**前台运行** (不用 `run_in_background` / 追加 `&`, 见下方反模式):

```bash
# Windows (PowerShell 前台直接看 stdout; 长耗时 >120s 需设 timeout)
uv run --with akshare --with pandas python scripts/fetch_macro_data.py --format md
```

- `--format md` 输出可读 Markdown; `--format json` 输出结构化数据
- `--output FILE` 可指定输出文件 (后台跑完再读文件)
- 首次运行自动解析 akshare 依赖 (uv 临时环境), 无需全局安装
- 输出开头有**数据健康度摘要** (如 `全球指数快照=failed | 核心指数历史=2/6 ok`), 明确标出哪些需搜索补

**反模式 (Windows 实测踩坑)**: 用后台模式 (run_in_background) 跑本脚本拿 stdout, 可能拿到**空输出** (uv 冷启动 + 管道缓冲未落盘), 且会把脚本拖成**双跑** — 而连续跑会加重东财封禁。若误用了后台跑且 log 为空, **不要重跑**去确认, 直接按上一轮前台结果 + 健康度缺口走 Step 2, 缺的用 web_search 补。

### Step 2: 按覆盖清单收集 (核心, 一键触发时必做)

**先读 `references/coverage-checklist.md`, 逐项过清单 A (每日固定收集项):**

1. **A1 隔夜美股收盘**: 三大指数 + 领涨板块 + 催化 (收益率/美元/美联储/财报)
2. **A2 当日 A股收盘**: 指数 + 领涨/领跌板块 (必须收盘源) + 成交额/情绪
3. **A3 当日港股收盘**: 恒指/科指 + 南向资金 + 领涨题材
4. **A4 关键新闻**: 央行/中国政策/地缘大宗/龙头财报/宏观数据 — 挑真正影响市场的 2-4 条
5. **A5 特殊日历窗口**: 今天是不是非农日/FOMC 窗口/CPI 日/财报季? 是则重点核对

**然后看脚本 `data_health`, 凡 failed 的数据块按清单 B 补** (搜不到就如实说, 不编造)。

搜索严格按 `references/information-sourcing-guide.md` 的方法: 信息分级、交叉验证、区分盘中/收盘/复盘。

**按需读取 (触发时机, 避免漏读)**:
- 接口报错/被封禁/需要换源/怀疑字段与口径 → `references/data-guide.md`
- 搜索结果被污染、需要信源分级与验证方法 → `references/information-sourcing-guide.md`

**搜索被垃圾结果污染时**: 不反复重试同 query, 按清单 B 的升级路径 (加来源词 → 换措辞 → web_fetch 兜底页 → 如实说明)。

### Step 3: 融合解读 (核心)

把"脚本拉到的 + 覆盖清单搜到的"合并, 按 `references/interpretation-framework.md` 的框架讲出有用信息 (不要复述整张表):

1. **全球风险偏好总览**: 普涨还是普跌? 亚太/欧美/新兴谁强谁弱? (数上涨 vs 下跌指数, 别单看一个)
2. **跨市场强弱**: 结合 20/60 日 (脚本有则用, 无则搜索) 判断中期方向, 钱往哪流; 警惕"单日大涨但 60日仍弱 = 反弹非反转"。
3. **板块结构**: A股领涨/领跌板块 (脚本或搜索), 判断资金在 A股内部流向哪条产业线 (涨价周期/科技成长/防御)。
4. **市场宽度/赚钱效应**: 看涨跌家数、涨停/跌停比、活跃度 (乐咕), 判断普涨普跌还是结构性行情、情绪亢奋还是冰点。
5. **资金面**: 看南北向资金 (脚本或搜索), 判断外资/内资动向 (南向大买港股 = 内资南下; 北向流入 A股 = 外资做多)。
6. **消息面催化**: 用清单 A4 搜到的关键新闻解释"今天为什么涨跌", 挑真正影响市场的 2-4 条, 说清影响了什么资产/为什么。
7. **宏观印证**: PMI/GDP/CPI 等是印证还是背离市场? 数据弱+股市涨 = 预期驱动, 提示脆弱性 (注意数据时点: PMI 是上月、GDP 是上季)。
8. **风险/关注点**: 最值得盯的信号 (美元、BDI、超买超卖、政策时点、特殊日历窗口)。

### Step 4: 给出结论与判断 (硬性, 两段缺一不可)

**Part A — 状态结论 (描述层)**:

1. **一句话定调** (全球风险偏好状态) + 1-2 个最强信号
2. **各市场强弱** (美股/港股/A股/欧股, 每块 1-2 句, 标注是哪个时点的收盘)
3. **最值得关注的板块/方向** (今天钱在流向哪、离开哪)
4. **值得关注的新闻 2-4 条** (作为固定模块, 每条说清影响什么/为什么)

**Part B — 判断/预期 (决策层, 必给; **判断四要素** 的权威定义与模板见 `references/judgment-standard.md`)**:

1. **方向**: 明确表态 (偏多/偏空/震荡/分化 + 相对强弱排序), 不只列情景
2. **时间窗 + 概率**: 例 "未来 1-2 周偏空 (60%)、1-3 个月震荡筑底 (50%)"
3. **基准情景**: 多情景必须标主观概率并指明**基准情景**, 不允许并列罗列不表态
4. **证伪条件**: 什么数据/事件发生就说明判断错了 (可核对)

**免责声明的正确位置**: 在判断**之后**, 用于说明数据边界; **不得**用它替代判断 (免责 ≠ 不判断)。

**自检闸门 (输出前逐条核对, 任一不满足 = 本次输出不合格)**:
- 报告存在"判断/预期"段, 且判断要素齐全: 方向 / 时间窗+概率 / 证伪条件 (**多情景时**另需"基准情景")
- 用户追问"所以呢?"时能用一句话回答
- 关键数字标来源与时间; 观点注明是谁的看法; **新闻是固定模块, 不等用户追问**; 不推荐个股、不做买卖建议

**追问类问题同样适用**: 用户问"原因是什么 / 未来会怎样 / 某行业怎么看 / 会不会加息 / 该不该担心"时, Part B 为必答项 (Part A 可压缩)。

## 反模式 (出现即不合格, 输出前对照自检)

- ❌ **只描述、不给判断**: 读完了用户还得追问"所以呢?" —— 本 skill 最常见的失败模式
- ❌ **情景并列不表态**: 列了 A/B/C 却不给概率与基准情景
- ❌ **用免责声明替代结论**: 把"不构成投资建议"当成回避方向的挡箭牌
- ❌ **只给"关注点"不给"方向"**: "关注美元、关注油价"是待办清单, 不是判断
- ❌ **表格复述代替提炼**: 把快照整张念一遍, 没回答"什么在变化"
- ❌ **把判断写成事实**: 推断必须标注"判断/概率", 不能伪装成确定性陈述
- ❌ **数据缺失就不给结论**: 正确做法是标注缺口 + 降置信度, 仍要给出判断
- ❌ **用借口跳过判断** ("宏观视角 / 数据有缺口 / 用户没问方向 / 只要事实 / 下轮再说") —— 逐条对照 `references/judgment-standard.md` §7 的"借口 → 事实"表

## 边界与不变量

- **不推荐个股, 不做精确择时** —— 但不等于"不给判断": 必须给出判断要素 (方向 / 时间窗+概率 / 证伪条件, 多情景时含基准情景; 标准见 `references/judgment-standard.md`)。区别在于: 给"环境与方向的判断 (含条件)"; 不给"个股标的、精确点位、买卖指令"。
- **判断必须可证伪且明确标注为判断**: 严格区分 ①事实 (标来源与时间) ②他人观点 (标"是谁的看法") ③本 skill 的框架判断 (标概率与条件)。免责声明放在判断之后, **不能替代判断**。
- **数据有延迟与源误差**: 指数时间为各市场本地时间, 注意时区; 脚本数据与搜索数据冲突时, 以更新/更权威来源为准并说明。
- **免费接口不稳是常态**: 数据缺了就搜, 搜不到就明说, **绝不编数据**。
- **宏观数据更新频率低**: PMI/GDP 月/季度, 说明数据时点。
- **免责**: 仅供研究参考, 不构成投资建议。
